当前 Excel 中，汇总表抓取的是各组各年财报中的固定单元格，而不是经营表。

## 3. 数据流总览

当前 Excel 的主链路可以概括为：

```text
初始年财报
  -> 0年经营
  -> 0年财报
  -> 1年经营
  -> 1年财报
  -> ...
  -> 8年经营
  -> 8年财报
  -> 统计汇总
```

可以把它理解成 4 层：

1. `初始基线层`
   初始年财报给后续所有年度提供起始基数
2. `年度经营层`
   经营表记录某一年的经营动作、累计值和现金流
3. `年度财报层`
   财报表把经营结果转成损益表和资产负债表
4. `管理员汇总层`
   汇总表只读取财报结果，不直接读取经营过程数据

## 4. 各表角色定义

### 4.1 初始年财报

作用：

- 定义游戏起点
- 为 `0年经营` 提供上一年所得税、现金、资产、负债、权益等基数

当前可确认结论：

- 它不是普通年度结束后自动生成的财报，而是系统初始状态
- 在产品设计上更适合归为“管理员初始化数据”

### 4.2 N年经营表

作用：

- 承载某一年的经营录入
- 汇总年初、季度、年末的经营动作
- 自动计算现金流、费用汇总、贷款余额、折旧、衍生指标

它本质上是：

- 一张“经营过程表”
- 不是最终排名依据
- 但它是当年财报的直接数据来源

### 4.3 N年财报表

作用：

- 将经营表结果转成标准财务结果
- 输出当年 `收入 / 利润 / 权益 / 资产 / 负债 / 现金 / 应收`
- 为下一年经营表提供承接基数

它本质上是：

- 一张“年度结果确认表”
- 是汇总页的直接数据来源

### 4.4 汇总表

作用：

- 按组、按年汇总财报核心指标
- 供管理员观察结果和排名使用

当前可确认结论：

- 汇总页只关心财报结果，不关心经营过程
- 汇总页当前抓的是 `1年财报` 到 `8年财报`
- `0年财报` 没有进入当前汇总结构

## 5. 年际传递关系

下面以 `1年经营 / 1年财报` 为例说明。`2年` 到 `8年` 只是把“上一年 sheet 名”替换掉，结构不变。

### 5.1 上一年财报 -> 当年经营

`1年经营` 对 `0年财报` 的关键引用如下：

| 当年经营单元格 | 公式 | 业务含义 |
|---|---|---|
| `M1` | `='0年财报'!C21` | 读取上年所得税，作为年初缴税基数 |
| `P10` | `='0年财报'!K7+O12-O10` | 短期负债余额 = 上年短贷 + 本年新增短贷 - 本年到期还贷 |
| `P42` | `='0年财报'!K8+O44-O43` | 长期负债余额 = 上年长贷 + 本年新增长贷 - 本年到期还款 |
| `O49` | `='0年财报'!G7+O27-O23` | 生产线残值滚动 |
| `O50` | `='0年财报'!G8+O28` | 折旧前待折资产总值 |
| `C59` | `='0年财报'!$G$13+$F$59-$I$59` | 年末现金 = 上年现金 + 本年现金收入 - 本年现金支出 |

这组引用说明：

- 每年经营表不是独立的
- 它必须建立在上一年财报已经确定的前提下
- 一旦上一年财报变化，下一年经营基线就会变化

### 5.2 当年经营 -> 当年财报

`1年财报` 对 `1年经营` 的关键引用如下：

| 当年财报单元格 | 公式 | 业务含义 |
|---|---|---|
| `C4` | `='1年经营'!O38` | 销售收入 |
| `C5` | `='1年经营'!O39` | 直接成本 |
| `C10` | `='1年经营'!O2` | 综合费用 |
| `C11` | `='1年经营'!O51` | 折旧 |
| `C16` | `='1年经营'!C60` | 财务收入/支出 |
| `C17` | `='1年经营'!C61` | 额外收入/支出 |
| `G5` | `='1年经营'!O52` | 在建生产线 |
| `G13` | `='1年经营'!C59` | 现金 |
| `K7` | `='1年经营'!P10` | 短期负债 |
| `K8` | `='1年经营'!P42` | 长期负债 |

这组引用说明：

- 财报页不是独立核算页面
- 它是经营页结果的结构化映射和再计算
- 经营页提交完成后，财报页才有完整意义

### 5.3 当年财报 -> 下一年经营

`1年财报` 又会成为 `2年经营` 的输入来源。核心承接项包括：

- 所得税
- 现金
- 应收款
- 短期负债
- 长期负债
- 生产线残值
- 待折资产
- 股东资本
- 利润留存

这说明：

- 每年结束的财报不仅影响汇总
- 还决定下一年经营的起点

### 5.4 财报 -> 汇总

汇总表以 `第一组` 的 `第一年` 为例：

| 汇总表单元格 | 公式 | 来源含义 |
|---|---|---|
| `B3` | `=SUM('[1]1年财报'!$C$4)` | 收入 |
| `C3` | `=SUM('[1]1年财报'!$C$22)` | 利润 |
| `D3` | `=SUM('[1]1年财报'!$K$19)` | 权益 |

因此当前汇总页抓取的正式口径是：

- `收入 = 财报 C4`
- `利润 = 财报 C22`
- `权益 = 财报 K19`

## 6. 经营表内部计算规则

以下仍以 `1年经营` 为例。

### 6.1 费用总计

`O2 = P5+O21+O22+O29+O33+O34+O40+O45+O48+O53`

可解释为：

- 综合费用由市场投入、变更项目、生产线拆除、人力费用、研发投入、管理体系、管理人员费、生产线维护、生产厂房租金、市场培育等构成

### 6.2 订单总额

关键公式：

- `M5 = SUM(E5:L5)`
- `M6 = SUM(E6:L6)`
- `M7 = SUM(E7:L7)`
- `M8 = SUM(E8:L8)`
- `O5 = SUM(M5:N8)`

可解释为：

- 先按区域汇总项目金额
- 再汇总得到年度订单总额

### 6.3 贷款余额

关键公式：

- `O10 = SUM(G10:N10)`，累计到期还贷
- `O12 = SUM(G12:N12)`，累计新增短贷
- `P10 = 上年短期负债 + O12 - O10`
- `P42 = 上年长期负债 + O44 - O43`

可解释为：

- 经营页中短贷和长贷都采用“上一年余额 + 本年净增减”的模式

### 6.4 生产线与折旧

关键公式：

- `O49 = 上年生产线残值 + O27 - O23`
- `O50 = 上年待折资产 + O28`
- `O51 = FIXED(O50/3,0,TRUE)`

可解释为：

- `O27` 表示本年新增转固带来的残值增量
- `O23` 表示生产线出售导致的残值减少
- 折旧按待折资产的三分之一取整

### 6.5 现金流

关键公式：

- `F59 = O12 + O23 + O36 + O44 + O47 + O58`
- `I59 = M1 + P5 + O10 + O11 + O18 + O21 + O22 + O26 + O29 + O31 + O33 + O34 + O40 + O45 + O46 + O42 + O43 + O48 + O53 + O55 + O57`
- `C59 = 上年现金 + F59 - I59`

可以拆成：

现金收入项：

- 新增短期贷款
- 生产线出售收入
- 应收账款回收
- 新增长期贷款
- 生产厂房出售
- 额外收入及奖励

现金支出项：

- 上年所得税
- 市场投入
- 短贷还款和利息
- 材料费
- 生产线调整相关支出
- 人力资源费用
- 工人工资
- 研发投入
- 管理体系投入
- 管理人员费用
- 生产线维护费
- 生产厂房购买
- 长贷利息和到期还款
- 生产厂房租金
- 市场培育
- 折现费用
- 额外支出及罚款

补充说明（最终版模板）：

- 经营页主表在 `B41` 新增 `核对季末现金` 标签。
- `G41 / I41 / K41 / M41` 分别展示 `Q1 / Q2 / Q3 / Q4` 的季度现金核对值。
- `A59` 显示 `期末现金`，原 `B59 = 现金` 的标题布局已调整。
- 该行用于玩家线下核对，不构成系统提交闸门。

### 6.6 经营表衍生指标

经营页还计算了一些衍生指标：

| 单元格 | 公式 | 含义 |
|---|---|---|
| `K59` | `=O5/P5` | 市场回报比 |
| `M59` | `=O33/(O38+O58)` | 研发投入强度 |
| `O59` | 组合公式 | 劳动生产率 |
| `C60` | `=O11+O42+O55` | 财务收入/支出 |
| `E60` | `=O46-O47` | 厂房增减值 |
| `G60` | `=O38-O36` | 应收相关增减值 |
| `C61` | `=O58-O57` | 额外收入/支出 |
| `E61` | `=O27-O23` | 残值增减值 |
| `G61` | `=O28-O51` | 待折资产增减值 |

### 7.4 资产负债平衡关系

财报表中存在两个最终结果位：

- `G22 = 总资产`
- `K22 = 总负债和权益`

Excel 当前会各自计算，但没有发现“若二者不相等则自动阻止提交”的现成机制。

因此从规则底稿角度，可以明确得到：

- `总资产 = 总负债+权益` 是一条应被关注的核心平衡关系
- 但它在当前 Excel 中更像结果对照，不是显式提交闸门

### 7.5 总监得分原公式与系统确认调整

#### 7.5.1 原 Excel 公式链核验

已只读核验 `game doc/1组贵宾.xlsx` 与 `game doc/1组（服务）.xlsx` 的 `0年财报 ~ 2年财报`，两份工作簿的公式结构一致：

| 财报位置 | 原 Excel 公式口径 | 含义 |
|---|---|---|
| `H27`（`0年财报`） | `='0年经营'!O5` | 0年最佳销售总监得分等于0年订单总额 |
| `H27`（`1年财报`） | `='0年经营'!O5+'1年经营'!O5` | 累计0年至1年订单总额 |
| `H27`（`2年财报`） | `='0年经营'!O5+'1年经营'!O5+'2年经营'!O5` | 累计0年至2年订单总额 |
| `H29` | `=SUM(H24:K28)` | 最佳 CEO 得分为总监得分区最终值合计 |

因此，原工作簿的业务含义为：

```text
原最佳销售总监得分_y = O_0 + O_1 + ... + O_y
原最佳 CEO 得分_y = 五项总监最终得分合计
```

#### 7.5.2 用户确认后的系统公式

用户于 `2026-07-20` 确认调整为：

```text
新最佳销售总监得分_y = (O_0 + O_1 + ... + O_y) / 10
```

系统按上一年结果递推时，等价实现必须是：

```text
S_0 = O_0 / 10
S_y = S_(y-1) + O_y / 10    （y >= 1）
```

不得使用 `(S_(y-1) + O_y) / 10`，因为 `S_(y-1)` 已经是除以 `10` 后的结果，再次整体相除会重复缩小历史得分。

最佳 CEO 新公式为：

```text
新最佳 CEO 得分_y =
  最佳市场经营总监得分_y
  + 最佳科技创新总监得分_y
  + 最佳生产/服务人力总监得分_y
  + 新最佳销售总监得分_y
  + 最佳 CFO 得分_y
  + 当前年份所有者权益_y / 2
```

其中当前年份所有者权益固定取财报 `K19`（系统字段 `reportTotalEquity`），不是上一年权益、权益增量或总资产。若 `K19` 为负，权益项按负数扣减 CEO 得分；结果不额外取整，允许小数。

#### 7.5.3 差异与历史兼容说明

- 这是用户明确确认的系统公式调整，与原 Excel `H27 / H29` 公式存在有意差异，不得在后续公式审计中误判为实现错误。
- 不覆盖或改写原始 Excel 文件；本说明只记录系统规则与 Excel 原公式链的差异。
- 新规则同时适用于生产制造版和贵宾服务版，并从 `0年` 起对全部年份追溯生效。
- 最佳 CFO 当前已有权益增量相关得分；CEO 再增加当前所有者权益的一半是独立评分项，两者均保留，不做抵消。
- 历史页面查询按当前公式从 `0年` 递归重建总监得分；旧提交 JSON、旧快照与失效草稿不物理改写，回退重提后保存新公式结果。
- 前端财报预览直接复用后端已按新公式返回的最佳销售总监得分，不再执行第二次 `/ 10`；但必须根据实时预览的 `reportTotalEquity` 给 CEO 增加权益项，确保编辑态与提交态一致。

## 8. 手工输入边界

## 8.1 经营表

经营表中，玩家主要填写的是各阶段的经营动作数据，系统自动计算累计值和结果。

从当前模板看，经营表更接近：

- 当前阶段数据由玩家录入
- 汇总列、累计列、现金和指标列由公式计算

经营表中不建议按“单个公式单元格”定义手工输入边界，而更适合按业务阶段定义：

- 年初区
- Q1 区
- Q2 区
- Q3 区
- Q4 区
- 年末区
- 其他收支区

### 8.1.1 第 9 步订单数量留痕（系统确认扩展）

原始 `1组 最终版.xlsx` 的 `B35:P35` 仅为“下新供应链订单”的合并提醒行，没有季度输入格，也没有公式直接读取该行。用户于 `2026-07-17` 确认将该线下空桶动作升级为系统手工留痕：

- 生产制造版按基础产品、标准产品、精密产品、智能产品四类记录。
- 贵宾服务版按代办过检服务、两舱贵宾服务、商务贵宾服务、会员定制服务四类记录。
- 每类按第一至第四季度填写，单位为“个”；当前季度四项均必填，没有订单时显式填写 `0`。
- 只允许非负整数，不允许负数、小数或文本。
- 数据按小组、年份和季度独立保存，不从上一年带入下一年。
- 该记录不参与 Excel 现金、收入、成本、财报、汇总或排名公式，也不接入系统正式订单池、选单和交付链路。
- 管理员按现有阶段级回退机制退回到对应季度后，该季度及后续季度的记录可修改并重新提交；原提交、回退前安全快照和补提版本均保留。

差异说明：这是基于用户明确指令新增的系统记录字段，不静默改写原始 Excel 文件及其公式链。

### 8.2 财报表

财报表的手工输入边界更清晰。

基于当前模板样式和公式引用，可确认首版财报手工输入边界为：

- `G15`：在制品
- `G16`：成品
- `G17`：材料
- `C24`：所得税税率

补充说明：

- `C24:C26` 在模板样式上属于同一输入区域
- 但当前公式真正读取的是 `C24`
- 因此产品实现时，应把税率作为一个明确字段，而不是让用户在 `C24:C26` 范围任意输入

### 8.3 初始年财报

初始年财报虽然也包含手工值，但从业务角色上更适合定义为：

- 管理员初始化数据
- 不作为普通玩家年度财报提交流程的一部分

### 8.4 手工数字输入整数口径

用户已确认：系统中用户手工填写的数字均不允许小数。

适用范围包括：

- 玩家经营页手工数字输入
- 玩家财报页手工数字输入
- 玩家订单页市场投入
- 管理员初始基线
- 管理员订单数量控制台
- 管理员单市场投入上限
- 管理员通知奖惩金额

例外范围：

- 所得税税率下拉值，例如 `0.25`、`0.15`
- 系统计算结果，例如比例、收益率、公式推导值
- 系统生成订单单价，单价允许小数，但订单金额必须为整数
- 历史数据、导入数据或 Excel 公式结果展示

因此，系统实现时应在前端输入控件和后端提交接口同时校验手工数字为整数，不能只依赖页面输入框限制。

第 9 步订单数量留痕还需在通用整数规则上增加“不得小于 `0`”的专门约束。

## 9. 对系统设计有直接影响的稳定结论

### 9.1 页面可以贴 Excel，规则层不能只靠页面

原因：

- 页面结构确实适合高保真贴近 Excel
- 但真正的规则来自公式链和跨表传值
- 尤其是“上一年财报 -> 下一年经营”的承接，必须由系统状态控制

### 9.2 汇总页应以财报提交结果为正式口径

因为当前汇总页读取的是财报固定单元格：

- 收入：`C4`
- 利润：`C22`
- 权益：`K19`

因此产品上更适合定义为：

- 只有财报提交完成后，管理员汇总才更新该年正式值

### 9.3 跨年回退天然比年内回退重

因为：

- 当年财报会成为下一年经营基线
- 一旦允许在“下一年已开启后”改动上一年财报，系统就需要连锁重算后续年度

这不是页面问题，而是公式链决定的。

当前系统层已确认：

- 首版新增管理员端 `回退与修正`，但不改 Excel 公式链。
- `退回重提` 保留为轻量异常解锁，适合本年内小范围修正。
- `恢复快照` 只做单组、阶段级快照回退，可跨年恢复某组状态；目标节点之后的经营页和财报页结果失效但保留为草稿，玩家重新提交后再按既有公式链计算。
- 单组快照回退不重算市场龙头、不释放订单、不重排历史选单顺序、不重新生成已确认订单池。
- 若未来确实需要全局连锁恢复，应单独设计 `全局快照恢复` 或 `标段局部重开`，不能静默修改本规则底稿中的 Excel 链路。

### 9.4 0年是链路的一部分，但不在当前汇总口径中

当前 Excel 结构显示：

- `0年经营 / 0年财报` 是正式链路的一部分
- 但汇总表当前从 `1年财报` 开始抓取

因此后续需求要单独确认：

- `0年` 是不是练习年
- 或者只是链路中的过渡年
- 以及它是否需要出现在系统正式排名中

### 9.5 订单推算工作簿的控制台链路

订单推算工作簿 `道具-订单推算（服务企业）.xlsx` 是线上订单模块的规则来源之一，不是玩家经营表或财报表的一部分。

当前工作簿结构包括：

- `订单模型`
- `数量推算`
- `市场地位（横）`
- `市场预测`
- `1年本地` 到 `8年全球` 的年度市场订单生成表

当前可确认的 Excel 链路为：

```text
市场预测 sheet 中的多年订单数量控制台
  -> 各年度市场订单生成表
  -> 市场预测 sheet 的预测展示区
```

控制台区域：

- `市场预测!O14` 存放小组数量。
- 本地市场控制区约为 `K17:O24`。
- 区域市场控制区约为 `K27:O34`。
- 全国市场控制区约为 `K37:O44`。
- 全球市场控制区约为 `K47:O54`。
- `L` 列为代办过检数量控制。
- `M` 列为两舱贵宾数量控制。
- `N` 列为商务贵宾数量控制。
- `O` 列为会员定制数量控制。
- `P` 列为四类订单数量合计，例如 `P17 = SUM(L17:O17)`。

跨表引用示例：

| 来源单元格 | 目标单元格 | 业务含义 |
|---|---|---|
| `市场预测!L17` | `1年本地!D22` | 1年本地市场代办过检订单卡数量 |
| `市场预测!M17` | `1年本地!D45` | 1年本地市场两舱贵宾订单卡数量 |
| `市场预测!N17` | `1年本地!D68` | 1年本地市场商务贵宾订单卡数量 |
| `市场预测!O17` | `1年本地!D91` | 1年本地市场会员定制订单卡数量 |
| `1年本地!V23` | `市场预测!L4` | 1年本地市场代办过检预测展示金额 |
| `1年本地!V46` | `市场预测!M4` | 1年本地市场两舱贵宾预测展示金额 |
| `1年本地!V69` | `市场预测!N4` | 1年本地市场商务贵宾预测展示金额 |
| `1年本地!V92` | `市场预测!O4` | 1年本地市场会员定制预测展示金额 |

年度市场订单生成表示例：

- `1年本地!C4 = IF(D22>=1,RANDBETWEEN(D23,J23),0)`，表示当该类订单卡数量大于等于 `1` 时，按区间随机生成订单数量。
- `1年本地!V23` 汇总该产品生成出的订单金额，用于回写市场预测展示区。

由此得到的系统口径：

- 多年订单数量控制台是订单数量主来源，系统不应再在年度订单管理页维护另一套独立数量。
- 市场预测由多年订单数量控制台和订单生成公式链产生，是玩家端市场投入前的只读趋势展示。
- 系统展示市场预测时固定按 `1~3年 / 4~5年 / 6~8年` 三段组织，不受管理员配置的最终年份裁剪。
- 市场预测页中的图表形态为竖状柱状图；系统管理员端与玩家端展示都应贴近该 Excel 形态：每个阶段下按市场分图，年份为横轴，四类订单为柱状系列。
- 每年开始前只生成当年正式订单池，不赛前一次性生成全部年份订单池。
- 当年正式订单池只读取该年份、管理员手动开启市场对应的控制台数量。
- 市场是否开启不由控制台数量自动推断；即使某市场在控制台中有数量，只要管理员当年未手动开启，该市场仍不生成订单、不进入抢单。
- 系统生成订单时，订单金额口径确认为 `订单金额 = 数量 × 单价`；数量为整数，单价可以有小数，但相乘后的订单金额必须为整数。该口径由后端在生成预览订单池时自动校准有效单价完成，不新增管理员逐单调整金额或单价的操作。
- Excel 右侧市场说明文字更接近静态说明或主持人维护内容，不应被理解为由公式自动推导出的规则结果。

### 9.6 机场沙盘订单工作簿链路

机场订单工作簿 `机场沙盘订单.xlsx` 是新增 `AIRPORT_ORDER_TEMPLATE_V1` 的规则来源，不是对 `道具-订单推算（服务企业）.xlsx` 的覆盖。

当前工作簿结构包括：

- `市场预测`
- `1年国内窄体` 到 `8年国际宽体` 的年度市场订单生成表

当前可确认的 Excel 链路为：

```text
市场预测 sheet 中的多年订单数量控制台
  -> 各年度市场订单生成表
  -> 市场预测 sheet 的预测展示区
```

市场预测 sheet 结构：

- `L / N` 列展示国内市场窄体 / 宽体收入。
- `M / O` 列展示国内市场窄体 / 宽体订单数量。
- `P / R` 列展示国际市场窄体 / 宽体收入。
- `Q / S` 列展示国际市场窄体 / 宽体订单数量。
- 行 `4 ~ 11` 对应 `1年 ~ 8年`。

跨表引用示例：

| 来源 / 目标 | 业务含义 |
|---|---|
| `市场预测!M4` -> `1年国内窄体!C1` | 1年国内窄体订单卡数量 |
| `市场预测!O4` -> `1年国内宽体!C1` | 1年国内宽体订单卡数量 |
| `市场预测!Q4` -> `1年国际窄体!C1` | 1年国际窄体订单卡数量 |
| `市场预测!S4` -> `1年国际宽体!C1` | 1年国际宽体订单卡数量 |
| `1年国内窄体!G2` -> `市场预测!L4` | 1年国内窄体预测展示收入 |
| `1年国内宽体!G2` -> `市场预测!N4` | 1年国内宽体预测展示收入 |
| `1年国际窄体!G2` -> `市场预测!P4` | 1年国际窄体预测展示收入 |
| `1年国际宽体!G2` -> `市场预测!R4` | 1年国际宽体预测展示收入 |

年度订单生成表示例：

- `C1` 引用市场预测中的该标段订单数量。
- `G2` 汇总该 sheet 中全部启用订单卡的总收入，用于回写市场预测展示区。
- 每张订单卡包含航线区域、飞机类型、航线类型、跑道要求、架次、吞吐量、客座率、总收入、单价、账期。
- 每张 sheet 最多包含 `28` 张订单卡。

机场订单公式口径：

- 架次：`RANDBETWEEN(9000,11000)`。
- 客座率：`RANDBETWEEN(60,80)`。
- 吞吐量：`160 × 架次 × 客座率 / 1000000`。
- 单价：`客座率 / 200 × 0.012 × 航线系数 × 跑道系数`。
- 航线系数：国内 `1`，国际 `1.7`。
- 跑道系数：`4C = 1`，`4D = 2`，`4E = 2.4`，`4F = 3`。
- 底层总收入：`单价 × 架次`。
- 订单金额：按 Excel 显示格式四舍五入为整数 `M`，作为系统订单金额。
- 账期：`RANDBETWEEN(2,4)` 季。

由此得到的系统口径：

- 机场订单模板市场为国内市场、国际市场。
- 机场订单模板订单类型为窄体、宽体。
- 国内市场默认开启，国际市场默认关闭，管理员可手动关闭或开启。
- 多年订单数量控制台固定覆盖 `1年~8年 × 国内/国际 × 窄体/宽体`，默认数量全部为 `0`，不自动带入 Excel 示例数量。
- 每个标段订单数量范围为 `0~28`。
- 机场订单总收入在页面和系统主流程中按整数展示 / 保存；底层未取整收入仅保存为扩展字段用于追溯。
- 机场经营页和财报页 Excel 尚未提供前，不把机场版临时接到贵宾版或生产版经营 / 财报模板；机场版首轮仅支持订单模块独立联调。

## 10. 当前疑点与待确认项

以下内容建议在后续需求讨论中继续确认：

### 10.1 0年业务定位

当前表结构里有 `0年经营 / 0年财报`，但汇总从 `1年` 开始。

待确认：

- `0年` 是否为练习年
- `0年` 是否参与最终结果

### 10.2 税率输入交互

Excel 公式只读取 `C24`，但模板视觉上给出三种税率说明。

待确认：

- 产品实现为下拉框更清晰
- 还是完全按 Excel 展示，让用户手动填值

### 10.3 折现费用区域

`O55 = SUM(G55:N56)`

说明折现费用合计跨了两行区域，而不是单行输入。

待确认：

- 第二行具体承载什么业务含义
- 系统页面是否要完全复刻这个结构

### 10.4 经营页阶段与提交边界

Excel 本身只负责计算，不负责流程控制。

因此以下规则不是 Excel 自动给出的，而是系统层需要定义的：

- 哪些区域在 Q1 可编辑
- 哪些区域在 Q2 可编辑
- 提交后如何锁定
- 回退后如何恢复；当前已确认通过管理员 `回退与修正` 处理，分为 `退回重提` 与 `恢复快照` 两类，不改变 Excel 公式本身

### 10.5 财报页校验强度

Excel 会计算 `G22` 和 `K22`，但没有自动拦截机制。

待确认：

- 系统是否在财报提交时强校验 `总资产 = 总负债 + 总权益`
- 若不相等，是否直接禁止提交

## 11. 建议的后续衔接方式

在这份规则底稿之后，建议按以下顺序推进：

1. 先把“已确认规则”和“待确认规则”拆开
2. 再整理《需求共识清单》
3. 最后写正式需求文档

这样可以避免把 Excel 现状、现场玩法、系统设计三者混写在一起。
