# 沙盘经营系统联调与人工验收运行手册（首版）

> 更新日期：2026-03-28  
> 适用方式：基于《正式需求文档（首版）》《接口设计文档（正式版）》《前端开发指南（正式版）》《测试指南（正式版）》与当前 `frontend/ + Go API` 实际实现，定义首版联调、演示与人工验收的最小可执行跑法。  
> 文档定位：本文件回答“环境怎么起、页面怎么进、身份怎么切、主链怎么验”。

## 1. 目标

首版联调运行手册要解决三件事：

1. 让开发、产品、主持人知道当前系统应该从哪里进入
2. 让前后端联调时有一套统一的页面路径与接口冒烟顺序
3. 让人工验收时能按固定链路走通 `0年 -> 1年 -> 财报 -> 汇总 -> 开放下一年`

---

## 2. 适用范围

本手册适用于当前首版范围：

- 玩家经营页
- 玩家财报页
- 管理员汇总页
- 管理员年度控制页
- 管理员初始基线页
- 管理员组数据查看页
- 管理员异常解锁弹窗

本手册不覆盖：

- 现场桌游道具与纸面流程
- 真实登录系统接入
- 生产部署脚本

---

## 3. 环境基线

### 3.1 运行端口

- 前端开发服务：`http://127.0.0.1:5173`
- 后端 API：`http://127.0.0.1:8080`
- 健康检查：`http://127.0.0.1:8080/healthz`

### 3.2 后端启动

在项目根目录执行：

```powershell
go run ./cmd/server -config configs/local.yaml
```

当前本机默认数据库连接取自 `configs/local.yaml`：

- `mysql dsn = root:123456@tcp(127.0.0.1:3306)/sandbox_game`

### 3.3 前端启动

在 `frontend/` 目录执行：

```powershell
npm install
npm run dev
```

## 4. 演示身份与访问方式

### 4.1 浏览器页面入口

玩家端：

- 经营页：`http://127.0.0.1:5173/sandbox-game/player/operating?yearNo=0`
- 财报页：`http://127.0.0.1:5173/sandbox-game/player/report?yearNo=0`

玩家端开发预览入口：

- 经营页预览：`http://127.0.0.1:5173/sandbox-game/player/operating?yearNo=0&preview=1`
- 财报页预览：`http://127.0.0.1:5173/sandbox-game/player/report?yearNo=0&preview=1`

管理员端：

- 汇总页：`http://127.0.0.1:5173/sandbox-game/admin/summary`
- 年度控制页：`http://127.0.0.1:5173/sandbox-game/admin/control`
- 初始基线页：`http://127.0.0.1:5173/sandbox-game/admin/baseline`
- 组数据页：`http://127.0.0.1:5173/sandbox-game/admin/group-data`

### 4.2 当前开发态身份约定

前端开发态已内置最小旁路身份，不依赖真实登录。

玩家页默认请求头：

- `X-Role-Type: GROUP`
- `X-User-Id: 101`
- `X-Username: group01`
- `X-Group-Id: 1`

管理员页默认请求头：

- `X-Role-Type: ADMIN`
- `X-User-Id: 1`
- `X-Username: admin`

说明：

- 玩家端默认视为“第 1 组”
- 管理员端页面已经在 API 层自动附带管理员身份头
- 若只想看页面形态而不依赖真实业务状态，优先使用玩家页 `preview=1`

### 4.3 API 调试身份头

接口调试时统一使用以下请求头。

玩家：

```http
X-Role-Type: GROUP
X-User-Id: 101
X-Username: group01
X-Group-Id: 1
```

管理员：

```http
X-Role-Type: ADMIN
X-User-Id: 1
X-Username: admin
```

## 5. 联调前检查清单

正式联调前，先确认以下 8 项：

1. `8080` 可访问，`/healthz` 返回 `200`
2. `5173` 可访问，首页可正常跳转到玩家经营页
3. 管理员汇总页能正常加载，不出现前端白屏
4. 管理员组数据页能拉到小组列表
5. 玩家经营页顶部年份标签能正常显示
6. 玩家财报页在未开放时符合只读或提示口径
7. `tests/http/sandbox-game/SandboxGame-Smoke.http` 的只读接口段可冒烟通过
8. 当前联调库不是正式比赛库

## 6. 人工验收主链

### 6.1 主链 A：页面与只读关系

1. 打开玩家经营页 `0年`。  
期望：页面整体按 Excel 风格展示，`年初/Q1/Q2/Q3/Q4/年末` 全部可见，但只有当前开放区可编辑。

2. 打开玩家财报页 `0年`。  
期望：如果当前年份经营尚未结束，财报页应保持锁定或提示未开放；若仅需看页面形态，使用 `preview=1` 入口。

3. 打开管理员组数据页。  
期望：默认进入经营页只读视图，可切换年份和页面类型，不要求管理员具备玩家权限。

4. 在管理员组数据页切换为财报视图。  
期望：财报主表与玩家端风格一致，但保持只读。

### 6.2 主链 B：业务推进

1. 管理员进入初始基线页，录入统一初始基线并提交。  
期望：提交成功后页面显示已提交状态、提交人、提交时间，且不可再次编辑。

2. 玩家进入 `0年经营`，依次完成 `Q1 -> Q2 -> Q3 -> Q4 -> 年末`。  
期望：每次只允许提交当前阶段；提交成功后上一阶段锁定；主表保留“核对季末现金”行，但它不阻断提交。

3. 玩家进入 `0年财报` 并完成提交。  
期望：仅绿色手工项可填写；税率只能选 `0.25 / 0.15 / 0`；平衡通过后才能提交。

4. 管理员进入年度控制页并开放 `1年`。  
期望：只有全部未破产组完成本年财报后，才允许开放下一年。

5. 玩家完成 `1年经营 + 1年财报`。  
期望：`1年` 完成后进入正式汇总范围。

6. 管理员进入汇总页查看年度汇总区。  
期望：`0年` 不进入正式汇总；`1年` 已提交财报的小组进入年度汇总。

7. 管理员在组数据页对某组某年执行异常解锁。  
期望：前端允许直接发起解锁；成功后该组对应年份恢复可编辑，财报提交结果与正式汇总快照被撤回。

8. 被解锁组重新完成经营或财报提交。  
期望：重新提交后该年份重新进入有效状态，汇总结果恢复。

### 6.3 主链 C：视觉预览

1. 使用玩家经营页 `preview=1`。  
期望：不依赖真实业务状态也能查看经营页高保真布局。

2. 使用玩家财报页 `preview=1`。  
期望：不依赖真实权限也能查看财报页高保真布局。

3. 使用管理员组数据页切换经营/财报。  
期望：可用于向上级演示“管理员看任意组任一年只读数据”的页面效果。

## 7. `.http` 冒烟脚本使用说明

当前首版联调脚本位于：

- `tests/http/sandbox-game/SandboxGame-Smoke.http`

使用建议：

1. 先执行“只读冒烟段”
2. 再根据当前数据库状态，按顺序执行“写链路示例段”
3. 写接口只建议在演练库执行，不建议直接对正式比赛库操作

脚本当前覆盖：

- 健康检查
- 玩家当前配置与年份标签
- 玩家经营页读取
- 管理员控制页读取
- 管理员小组列表
- 管理员组数据只读查看
- 初始基线提交示例
- `Q1` 经营草稿与提交示例
- 财报草稿与提交示例
- 开放下一年示例
- 异常解锁示例

## 8. 当前边界与风险提醒

1. 玩家经营/财报的真实写入链路依赖当前联调库状态，若数据库已不是初始态，写请求可能返回规则错误。
2. 玩家财报正式页面受年份状态控制，不是任何时刻都能直接打开；仅页面预览时使用 `preview=1`。
3. 管理员端历史解锁日志列表目前尚未单独成页，当前只展示最近一次解锁原因与结果。
4. 当前运行手册基于开发旁路身份，不代表后续接入正式登录系统后的最终运维方式。

## 9. 联调完成判定

本轮 `M3-03` 联调收口，至少满足以下条件：

1. 前后端都能在本机启动
2. 玩家与管理员页面都有稳定入口
3. 管理员组数据页依赖的新接口可返回成功
4. 联调人员能按本手册找到页面、切换身份、理解主链顺序
5. `.http` 冒烟脚本能覆盖当前首版主链涉及的核心接口

说明：

- 若要把 `M3-03` 记为“现场可演示完成”，还需要按本手册在演练库实际走完一次完整主链，并回填结果记录。
