# I7 回退与修正验收清单

## 1. 自动快照

- 玩家提交经营阶段后，`sg_state_snapshot` 生成 `GROUP + AUTO + STAGE_SUBMITTED` 快照。
- 玩家提交财报后，生成 `GROUP + AUTO + REPORT_SUBMITTED` 快照。
- 管理员确认订单池后，生成 `GLOBAL + AUTO + ORDER_POOL_CONFIRMED` 快照。
- 标段完成后，生成 `GLOBAL + AUTO + SEGMENT_COMPLETED` 快照。
- 管理员开放下一年后，生成 `GLOBAL + AUTO + OPEN_NEXT_YEAR` 快照。
- 管理员执行退回重提或恢复快照前，生成 `GROUP + SAFETY + BEFORE_ROLLBACK` 安全快照。
- 回退待重提状态下，玩家重新提交经营阶段后，生成 `GROUP + AUTO + ROLLBACK_STAGE_RESUBMITTED` 快照，并在管理员端显示为回退补提经营。
- 回退待重提状态下，玩家重新提交财报后，生成 `GROUP + AUTO + ROLLBACK_REPORT_RESUBMITTED` 快照，并在管理员端显示为回退补提财报。

## 2. 退回重提

- 在管理员端 `回退与修正 -> 退回重提` 选择小组、年份、经营页/财报页目标并填写原因。
- 提交后目标小组进入 `rollback_pending = true`。
- 原经营页和财报页数据保留，后续结果以失效草稿方式展示。
- 汇总页对应年份展示 `待重提`，不计入有效排名。
- 玩家重新完成该年份财报提交后，系统清除待重提状态。

## 3. 恢复快照

- 在 `回退与修正 -> 恢复快照` 查询并选择单组快照。
- 查看快照详情，填写原因和确认文本 `确认恢复`。
- 恢复后写入 `sg_rollback_log`，并记录来源快照和安全快照。
- 恢复快照后，目标年份之后的汇总和订单交付记录作为失效草稿 / 历史留痕保留，不直接作为当前有效结果；奖惩有效状态按目标快照时点恢复，原奖惩记录和审计信息不物理删除。
- 快照中的旧订单交付不直接恢复为有效交付；回退 / 恢复快照会把目标阶段及之后的当前有效交付标记为“上次提交已失效”，玩家重新推进到对应季度后可重新确认原订单，也可改交其他已选订单。玩家重新提交该季度后，未再次交付的旧失效订单恢复为普通待交付；多次回退 / 恢复快照时，不在玩家订单页累计展示所有历史失效订单。
- 已选订单归属不释放，不重排历史选单顺序，不重新生成订单池。
- 已破产小组不允许通过恢复快照回到 `NORMAL`；破产判定不可撤销。

## 4. 年度控制阻断

- 存在任意小组 `rollback_pending = true` 时，管理员端年度控制显示阻断原因。
- 此时调用开放下一年接口应返回阻断错误。
- 待所有回退补提小组重新完成对应年份财报后，开放下一年恢复正常判断。

## 5. 玩家提示

- 被回退小组进入经营页或财报页时，页面显示回退提示。
- 玩家继续在旧状态提交时，若阶段已变化，接口返回“请刷新页面后重试”。

## 6. 回归验证

- 后端：`go test ./...`
- 前端：`npm run build`
- 人工联调建议覆盖：
  - 本年经营页退回到 `Q2` 后重提。
  - 本年财报页退回后重提。
  - 跨年恢复单组快照。
  - 回退或恢复快照后旧订单交付仅作为历史留痕，已选订单仍归属原小组且可重新选择交付。
  - 重新交付后经营页销售收入只按当前有效交付记录生成。
  - 多次回退 / 恢复快照时，再次失效范围只来自上次重新提交后仍然有效的交付订单，未再次交付的旧失效订单应恢复普通待交付。
  - 回退补提期间开放下一年被阻断。
