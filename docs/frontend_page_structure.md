# 沙盘经营系统正式前端页面结构清单（首版）

> 更新日期：2026-03-31  
> 适用方式：基于当前已确认的业务共识、`docs/requirements_spec.md`、`docs/implementation_plan.md` 与上午讨论形成的页面结论，沉淀首版正式前端页面结构清单。  
> 文档定位：本文件回答“首版前端到底有哪些正式页面、每个页面必须有什么结构、哪些内容明确不做”。  
> 说明：本清单以已确认讨论结论为准，不以现有 Demo 反推页面范围；若 Demo 与本清单冲突，以本清单为准。

## 1. 清单使用原则

- 本清单只覆盖首版正式页面结构，不覆盖视觉稿细节。
- 本清单优先回答“页面边界”和“区块边界”，不展开到字段级设计。
- 本清单用于约束前端页面范围、路由范围和联调范围。
- 首版页面以“高保真 Excel 风格 + 明确业务状态”作为统一方向。

## 2. 首版正式页面总表

| 角色 | 页面名称 | 建议路由 | 是否首版正式页面 | 进入条件 | 页面目标 |
|---|---|---|---|---|---|
| 公共 | 统一登录页 | `/sandbox-game/login` | 是 | 未登录时进入 | 承载用户名密码登录，并按角色自动跳转 |
| 玩家 | 经营页 | `/sandbox-game/player/operating` | 是 | 玩家登录后默认进入；默认打开 `0年经营` | 承载年初/Q1/Q2/Q3/Q4/年末经营填写与阶段提交 |
| 玩家 | 财报页 | `/sandbox-game/player/report` | 是 | 本年经营完成后开放 | 承载自动计算财报结果与绿色手工项填写 |
| 管理员 | 赛前配置页 | `/sandbox-game/admin/setup` | 是 | 比赛未初始化时，管理员登录后默认进入 | 配置本场比赛小组数量并初始化比赛环境 |
| 管理员 | 汇总页 | `/sandbox-game/admin/summary` | 是 | 比赛已初始化后，管理员登录默认进入 | 同页展示年度汇总区与最终排名区 |
| 管理员 | 年度控制页 | `/sandbox-game/admin/control` | 是 | 管理员登录可见 | 管理最终年份、当前开放年份与开放下一年 |
| 管理员 | 通知与奖惩页 | `/sandbox-game/admin/notices` | 是 | 管理员登录可见 | 发送普通通知；按组/年下发或作废奖罚，阶段由系统自动归属 |
| 管理员 | 初始基线页 | `/sandbox-game/admin/baseline` | 是 | 管理员登录可见 | 录入一份共享初始基线模板并提交锁定 |
| 管理员 | 组数据页 | `/sandbox-game/admin/group-data` | 是 | 管理员登录可见 | 按组、按年查看经营/财报数据，并触发异常解锁 |
| 管理员 | 异常解锁弹窗 | 嵌入 `admin/group-data` | 是 | 在组数据页点击“异常解锁” | 选择解锁目标、回退阶段并填写原因，发起某组某年的异常解锁 |

明确不单独做的页面：

- 不做单独“最终排名页面”
- 不做管理员进度总控大盘页面
- 不做“一组一个初始基线页面”
- 不做玩家端分季度分步骤向导页

## 3. 全局结构约束

### 3.1 玩家端全局结构

- 首页默认进入 `0年经营`
- 全部年份标签可见
- 未开放年份标签可见但不可进入，或进入后整体只读
- 玩家端始终保留“主表 + 轻量工作栏”的双区结构
- 主表必须是视觉主体，工作栏只承载辅助信息和动作
- 玩家经营页与财报页各自只维护 `1` 套正式页面结构，不为每一年单独建立新路由或新页面文件
- 顶部年份标签数量由 `finalYear` 和 `get-year-tabs` 返回结果动态决定，前端不得写死年份按钮数量

### 3.2 管理员端全局结构

- 左侧一级菜单首版仅保留：
  - 汇总
  - 年度控制
  - 通知与奖惩
  - 初始基线
  - 组数据
- 不新增“排名”“进度”“导出”等一级菜单
- 管理员端首版不做复杂图表大屏
- 管理员端以“页面清楚、现场好操作”为优先，不追求大后台感

### 3.3 统一登录与跳转原则

- 未登录用户访问业务页时，统一跳转到 `/sandbox-game/login`。
- 登录页只保留最小闭环所需结构：账号输入区、密码输入区、登录按钮、错误提示区。
- 登录页不提供角色手动选择器。
- 玩家登录成功后默认跳转到 `/sandbox-game/player/operating?yearNo=0`。
- 管理员登录成功后，若比赛未初始化则跳转到 `/sandbox-game/admin/setup`；若比赛已初始化则跳转到 `/sandbox-game/admin/summary`。
- 页面右上角或导航区应提供“退出登录”入口。

### 3.4 页面状态控制原则

- 未开放：可见但不可编辑
- 已提交：只读显示
- 已完成：整页只读
- 已破产：历史可看，后续不可编辑
- 异常解锁：按目标页 / 目标阶段恢复可编辑，并使后续结果进入“失效草稿”态

### 3.5 年份页面组织原则

- 前端不生成 `0年经营 / 1年经营 / 2年经营 ...` 多套静态页面文件。
- 玩家经营页通过 `yearNo` 参数切换当前查看年份，财报页同理。
- 管理员修改 `最终年份` 后，前端重新获取 `get-current` 与 `get-year-tabs`，据此刷新年份标签上限。
- 当 `最终年份` 上调时，前端只需要新增标签和切换入口，不需要重新创建页面组件。
- 当 `最终年份` 下调时，前端按新的年份上限收口标签，不要求删除本地页面结构定义。

## 4. 统一登录页

### 4.1 页面定位

- 这是系统唯一公共入口页面
- 未登录状态默认进入本页
- 登录成功后按角色自动跳转，不要求用户手动选择玩家或管理员

### 4.2 必备结构

| 区块 | 是否必需 | 说明 |
|---|---|---|
| 登录标题区 | 是 | 显示系统名称与最小提示文案 |
| 用户名输入区 | 是 | 输入登录名 |
| 密码输入区 | 是 | 输入密码 |
| 登录按钮区 | 是 | 触发登录动作 |
| 错误提示区 | 是 | 展示账号密码错误、账号停用等提示 |

### 4.3 页面行为约束

- 不要求用户手动选择角色。
- 登录成功后由系统依据账号角色自动跳转。
- 玩家默认进入 `0年经营`。
- 管理员在比赛未初始化时默认进入 `赛前配置页`；比赛已初始化后默认进入 `汇总页`。
- 首版不提供注册、找回密码、修改密码等扩展入口。

## 5. 玩家端正式页面结构

### 5.1 玩家经营页

#### 5.1.1 页面定位

- 这是玩家端主页面
- 也是玩家登录后的默认首页
- 一个页面承载本年全部经营阶段，不按季度拆页

#### 5.1.2 必备结构

| 区块 | 是否必需 | 说明 |
|---|---|---|
| 顶部年份标签栏 | 是 | 显示 `0年 ~ 最终年`，全部可见 |
| 页面类型切换入口 | 是 | 经营 / 财报；财报未开放时可见但不可进入 |
| 经营主表 | 是 | 完整展示年初、Q1、Q2、Q3、Q4、年末区 |
| 季末现金展示行 | 是 | 位于主表内部，不做弹窗，不做额外录入框 |
| 通知区 | 是 | 位于右侧工作栏顶端，展示置顶通知与最近通知 |
| 右侧工作栏 | 是 | 展示阶段状态、草稿状态、贷款提醒、正式提交入口 |
| 顶部错误提示区 | 是 | 显示当前阶段缺填或提交失败提示 |

#### 5.1.3 主表必须包含的业务分区

- 年初区
- Q1 区
- Q2 区
- Q3 区
- Q4 区
- 年末区
- 额外收入 / 奖励与额外支出 / 罚款区（奖罚由管理员下发）
- 季末现金展示行

#### 5.1.4 页面行为约束

- `Q1` 时可编辑：年初区 + Q1
- `Q2` 时仅 Q2 可编辑
- `Q3` 时仅 Q3 可编辑
- `Q4` 时仅 Q4 可编辑
- 年末时仅年末区可编辑
- 已提交阶段保持可见但只读
- 未来阶段保持可见但锁定
- 系统展示计算得到的期末现金，供玩家线下自核，不阻断提交
- `额外支出 / 罚款`、`额外收入 / 奖励` 按 `Q1 / Q2 / Q3 / Q4 / 年末 / 总计` 展示，玩家不可修改；财报填写阶段奖罚进入年末列
- `折现费用` 保持玩家可编辑，但不增加年末业务字段；年末位置只显示 `--`
- 奖罚 revision 变化时只局部更新奖罚、派生经营结果和提示，不重新加载整页，不改变焦点、光标或滚动位置
- 若管理员对经营页执行异常解锁：
  - 目标阶段之前的已生效阶段继续只读
  - 目标阶段恢复可编辑
  - 目标阶段之后的经营区保留原值，但显示为 `失效草稿 / 待重新提交`
- `失效草稿` 不计入当前正式结果，只有重新提交后才恢复生效

#### 5.1.5 本页明确不做

- 不拆成 `Q1/Q2/Q3/Q4` 多个页面
- 不做逐步向导式流程页
- 不增加“输入现场现金”的独立弹窗
- 不把季末现金展示移到右侧工作栏

---

### 5.2 玩家财报页

#### 5.2.1 页面定位

- 财报页是与经营页并列的正式页面
- 只在本年经营完成后开放
- 财报提交成功后，本年度完成

#### 5.2.2 必备结构

| 区块 | 是否必需 | 说明 |
|---|---|---|
| 顶部年份标签栏 | 是 | 与经营页保持一致 |
| 页面类型切换入口 | 是 | 经营 / 财报切换 |
| 财报主表 | 是 | 尽量贴近 Excel 财报结构 |
| 自动计算区 | 是 | 只读显示 |
| 绿色手工项区 | 是 | 在制品 / 成品 / 材料 / 税率 |
| 通知区 | 是 | 位于右侧工作栏顶端，展示置顶通知与最近通知 |
| 年末奖罚摘要 | 是 | 只读展示年末奖励、年末罚款和奖罚明细入口 |
| 右侧工作栏 | 是 | 平衡校验、税率说明、提交入口 |
| 校验提示区 | 是 | 显示平衡校验是否通过 |

#### 5.2.3 页面行为约束

- 未开放时：财报标签可见但不可进入
- 已开放未提交时：绿色手工项可编辑
- 已提交后：整页只读
- 税率只能下拉选择 `0.25 / 0.15 / 0`
- 提交必须通过 `总资产 = 总负债 + 总权益`
- 财报填写期间管理员新下发或作废的奖罚统一归入年末；页面静默局部合并后，使用玩家当前未保存手工输入重新计算本地财报预览，不覆盖输入、不改变焦点和滚动位置
- 财报正式提交后不再接收直接奖罚操作；管理员必须先退回财报
- 若因经营页异常解锁导致财报失效，财报标签应回到锁定态；此前财报手工项保留为 `失效草稿`，待重新走到财报阶段时自动回填
- 若仅财报页被异常解锁，财报页应直接恢复为可编辑状态，并回填此前保留的手工草稿

#### 5.2.4 本页明确不做

- 不做独立“财报预览页”
- 不做额外的年度累计财报页
- 不允许税率自由输入其他值

## 6. 管理员端正式页面结构

### 6.1 汇总页

#### 6.1.1 页面定位

- 汇总页是管理员端默认主页面
- 汇总页与最终排名区在同一个页面内
- 不单独拆一个“排名页”

#### 6.1.2 必备结构

| 区块 | 是否必需 | 说明 |
|---|---|---|
| 页面头部状态区 | 是 | 展示最终年份、当前开放年份、共享基线提交状态等摘要 |
| 年度汇总区 | 是 | 按正式年份展示所有组正式汇总数据 |
| 最终排名区 | 是 | 位于页面下方，未开放时显示状态提示 |

#### 6.1.3 年度汇总区结构要求

- 按“组”为行
- 按“年份”为列组
- 每个正式年份下固定展示：
  - 收入
  - 利润
  - 权益
- 同行展示经营状态
- `已破产` 使用红色标签
- 不提供年份切换器；首版默认在一个大表内展示全部正式年份

#### 6.1.4 最终排名区结构要求

- 位于同页下方
- 仅在最终年份满足开放条件后显示有效排名
- 未满足条件时显示状态提示，不跳转页面
- 首版最小展示字段：
  - 排名
  - 小组

#### 6.1.5 本页明确不做

- 不做单独排名页面
- 不做导出按钮
- 不做复杂图表区
- 不做实时动态排行榜

---

### 6.2 年度控制页

#### 6.2.1 页面定位

- 只承载年份推进相关控制
- 不承载复杂现场进度大盘

#### 6.2.2 必备结构

| 区块 | 是否必需 | 说明 |
|---|---|---|
| 当前配置区 | 是 | 显示最终年份、当前开放年份 |
| 最终年份设置区 | 是 | 修改最终年份 |
| 开放下一年动作区 | 是 | 执行“开放下一年” |
| 阻断原因提示区 | 是 | 不可开放时展示原因摘要 |

#### 6.2.3 页面行为约束

- 只允许管理员访问
- 页面只做年度推进，不展示分组进度明细大盘
- 当不满足开放条件时，展示阻断原因，但不新增复杂流程控制图

---

### 6.3 初始基线页

#### 6.3.1 页面定位

- 该页是“一份共享模板”
- 不是“每组一页”
- 提交后按组应用到全部小组

#### 6.3.2 必备结构

| 区块 | 是否必需 | 说明 |
|---|---|---|
| 基线状态区 | 是 | 显示是否已提交、提交人、提交时间 |
| 共享模板主表 | 是 | 以接近 Excel 的单页模板录入 |
| 提交动作区 | 是 | 提交并锁定 |

#### 6.3.3 页面行为约束

- 提交前可编辑
- 提交后锁定只读
- 不提供组切换器
- 不做逐组复制页面

#### 6.3.4 本页明确不做

- 不做“第一组基线 / 第二组基线 / ……”多页结构
- 不做提交后反复编辑

---

### 6.4 通知与奖惩页

#### 6.4.1 页面定位

- 这是管理员发送普通通知与下发奖惩的统一入口
- 页面同时承载展示型消息和计算型奖惩，但交互上必须分区

#### 6.4.2 必备结构

| 区块 | 是否必需 | 说明 |
|---|---|---|
| 普通通知发送区 | 是 | 支持全体广播或单组通知，自由文本 |
| 奖惩下发区 | 是 | 选择组、年份、类型、金额与原因；阶段由系统按该组当前状态自动显示 |
| 影响预览弹窗 | 是 | 展示调整前后现金、利润、所得税、所有者权益与是否触发破产 |
| 已发记录区 | 是 | 查看最近普通通知与奖惩记录，显示有效 / 已作废 / 快照失效状态，并提供合规的作废入口 |
| 发送结果提示区 | 是 | 展示发送成功或失败结果 |

#### 6.4.3 页面行为约束

- 普通通知支持 `全体小组` 与 `单个小组`
- 普通通知允许自由文本，不限制模板
- 普通通知允许广播赛事事件信息，例如某组已破产
- 奖惩下发必须显式选择：组、年份、类型、金额和原因；管理员不手工选择季度
- 页面显示服务端根据当前状态解析出的 `Q1 / Q2 / Q3 / Q4 / 年末` 标签；财报填写和草稿阶段显示 `年末（财报填写中）`
- 奖惩下发应支持填写原因说明，但原因说明不进入 Excel 主表
- 点击下发或作废前打开影响预览确认弹窗；若会触发破产，确认按钮显示“确认下发并执行破产判定”或对应作废警告
- 奖惩记录不可编辑或物理删除；未破产且当前可处理时允许填写原因后作废
- 财报正式提交或年份完成后提示先退回；已破产时下发和作废按钮永久禁用，不提供解除破产入口
- 不做 WebSocket；玩家页面可见时每 `3` 秒轻量检查 revision，隐藏暂停，重新可见时立即检查
- 玩家端使用固定右下角提示，不插入改变页面高度的顶部消息条，不触发页面跳回顶部

#### 6.4.4 本页明确不做

- 不做已读未读管理
- 不做附件上传
- 不做复杂筛选检索中心
- 不做审批流或撤回审批

---

### 6.5 组数据页

#### 6.5.1 页面定位

- 管理员查看任意组、任意年数据的统一入口
- 页面从“所有组的起点”进入，不是一组一页

#### 6.5.2 必备结构

| 区块 | 是否必需 | 说明 |
|---|---|---|
| 查询选择区 | 是 | 小组、年份、页面类型 |
| 数据预览区 | 是 | 默认展示经营页，只读预览 |
| 页面类型切换区 | 是 | 经营 / 财报 |
| 当前状态摘要区 | 是 | 展示当前年份状态、财报状态、最近一次异常解锁摘要 |
| 破产记录区 | 条件必需 | 奖罚触发破产时显示原因、关联奖罚和“查看破产快照”入口；不得显示为正式财报提交 |
| 异常解锁动作区 | 是 | 管理员发起异常解锁 |

#### 6.5.3 页面行为约束

- 默认页面类型为经营页
- 管理员可切换查看经营页或财报页
- 预览区尽量复用玩家页面结构，但保持只读
- 破产快照详情只读展示玩家最新已保存草稿、奖罚前后经营 / 财报计算结果、现金变化、时间和原因；不进入正常财报提交列表、汇总或排名
- 已破产小组不显示可用的异常解锁、奖罚下发或奖罚作废入口
- 异常解锁按钮不依赖前端先做复杂可解锁判断
- 是否允许解锁以管理员现场判断 + 服务端硬校验为准
- 解锁成功后，页面应刷新当前组当前年的经营 / 财报状态，并让管理员立即看到“已失效待重提”结果

#### 6.5.4 本页明确不做

- 不做“每组独立后台主页”
- 不做复杂解锁条件预判提示树
- 不在首版首屏强制展示大块日志表

### 6.6 异常解锁弹窗

#### 6.6.1 页面定位

- 这是 `组数据页` 的配套动作弹窗
- 不是单独页面

#### 6.6.2 必备结构

| 区块 | 是否必需 | 说明 |
|---|---|---|
| 目标信息区 | 是 | 显示组、年份、当前查看页面 |
| 解锁目标选择区 | 是 | `经营页` / `财报页` |
| 经营阶段选择区 | 条件必需 | 当目标为 `经营页` 时显示 `Q1 / Q2 / Q3 / Q4 / 年末` |
| 影响说明区 | 是 | 根据选择动态展示本次解锁的影响范围 |
| 解锁原因输入区 | 是 | 管理员必填 |
| 二次确认区 | 是 | 确认执行异常解锁 |

#### 6.6.3 页面行为约束

- 解锁目标必选
- 当目标为 `经营页` 时，阶段必选
- 解锁原因必填
- 提交前展示二次确认
- 影响说明区需动态区分：
  - `经营页异常解锁`：提示“目标阶段重新开放，后续经营阶段与财报结果失效但保留草稿”
  - `财报页异常解锁`：提示“经营结果保持不变，财报结果失效并恢复编辑”
- 前端不做复杂可解锁判断树，只负责收集必要输入并展示服务端返回结果
- 成功后回到组数据页并刷新当前目标数据

#### 6.6.4 前端页面与交互改造清单

- `admin/group-data`：异常解锁入口从“只填原因”升级为“目标类型 + 阶段 + 原因”。
- `admin/group-data`：成功解锁后应刷新当前预览，明确显示当前页已进入待重提状态。
- 玩家经营页：新增 `失效草稿` 展示语义，但不清空后续阶段原值。
- 玩家财报页：支持“经营回退后锁定并保留草稿”和“财报解锁后直接回填草稿”两类表现。
- 目标化错误提示：至少区分 `经营页无需解锁`、`财报页无需解锁`、`目标尚未正式提交`、`下一年已开放`。
- 交互表达尽量轻量，不在 Excel 主表中央新增大面积说明模块。

## 7. 页面之间的关系清单

### 7.1 玩家端

```text
统一登录页
  -> 玩家登录成功后进入 0年经营
  -> 切换年份
  -> 在当前年内切换 经营 / 财报
  -> 经营完成后本年财报开放
```

### 7.2 管理员端

```text
汇总
  -> 只看正式汇总与最终排名状态

年度控制
  -> 设最终年份
  -> 开放下一年

初始基线
  -> 录入共享模板
  -> 提交后锁定

组数据
  -> 选择组
  -> 选择年份
  -> 查看经营或财报
  -> 触发异常解锁
```

## 8. 首版前端页面开发顺序建议

1. 统一登录页
2. 玩家经营页
3. 玩家财报页
4. 管理员汇总页
5. 管理员年度控制页

- 这个顺序与主业务链一致
- 汇总页应先于年度控制页完成，因为它是管理员最先看到的主页面
- 组数据页与异常解锁应放在控制链之后实现
