# 玩家端经营页文字层级与格子间距优化开发说明

> 更新日期：2026-07-27
> 适用范围：玩家端经营页主表 `frontend/src/components/sandbox-game/player/OperatingSheet.vue`
> 当前任务：`I16-01` 冻结口径，只写文档，不修改正式前端代码；后续实现任务为 `I16-02`。

## 1. 背景

玩家端经营页当前已经按 Excel 风格整页展示，核心结构、颜色语义、阶段锁定和输入逻辑均已落地。后续优化不应重做页面，也不应把经营页改成卡片式表单，而是在现有表格基础上优化文字层级、字号、字重、行距、对齐方式和格子内部留白。

用户本轮明确的目标是：

- 不使用新的 demo 页面方向替代现有正式页面。
- 不改变经营页字段顺序、列结构、公式、接口和提交逻辑。
- 在原有前端页面基础上，把不同类型文字做出明确分类。
- 每类文字确定字号、字重、行距、对齐方式和上下左右留白。
- 整体让玩家看表、读说明、连续填写时更舒服。

本次讨论中用户举例的典型单元格包括：

```html
<td class="group-title" colspan="2">1. 支付上年度所得税</td>
<td class="section-band band-quarter" rowspan="40">每季度工作</td>
<td class="note-cell" colspan="2">贵宾厅拆除 1M / 间</td>
<td class="note-cell center">第一季度</td>
<td class="note-cell center" colspan="3">调整公司战略，制定当年经营和工作计划</td>
<td class="note-cell center" colspan="4">一般企业 25%，支线机场贵宾 15%</td>
```

这些单元格当前大多落在 `group-title`、`section-band`、`note-cell`、`center` 等少数类名里，但业务语义并不完全相同。后续优化重点是给这些文字建立稳定分类，而不是简单把所有文字统一放大。

## 2. 设计边界

### 2.1 本轮要做

- 只针对玩家端经营页主表。
- 建立经营页文字层级规范。
- 明确各类文字的字号、字重、行距、对齐方式、padding 和最小高度建议。
- 明确短句 / 长句说明的对齐规则。
- 明确后续代码实现时需要新增或复用的语义类。
- 保留当前 Excel 风格表格，不重做页面。

### 2.2 本轮不做

- 不修改后端接口。
- 不修改经营页保存、提交、校验、订单联动、奖罚联动和公式计算。
- 不修改原始 Excel 文件。
- 不改变经营页字段顺序、阶段顺序和业务结构。
- 不把玩家端财报页、订单页、管理员端页面纳入本轮。
- 首版不大幅调整表格列宽。
- 不用多套中文字体族制造层级。
- 不用新颜色替代现有业务颜色语义。

### 2.3 与 Excel 风格的关系

经营页仍然保持高保真 Excel 风格。
本优化只解决网页端可读性和填写舒适度问题，不改变 Excel 公式链。
如果视觉优化与 Excel 原始样式存在差异，应以“规则正确、数据一致、流程稳定”为前提，优先保证玩家能清楚阅读和填写。

## 3. 核心设计原则

### 3.1 统一字体族，不混用字体

后续不建议为不同文字类型使用不同中文字体族，例如标题用黑体、内容用宋体、说明用楷体。
正式页面继续使用现有系统无衬线字体族，通过字号、字重、行距、对齐和留白建立层级。

建议字体族保持：

```css
font-family: "Microsoft YaHei", "Segoe UI", Arial, sans-serif;
```

### 3.2 标题更醒目，但不要让所有文字都变成标题

二级任务标题可以明显放大、加粗、居中。
普通内容、流程说明、规则说明也可以放大和加粗，但字重应分层，避免整张表所有文字都很重。

### 3.3 短标签居中，长说明优先左对齐

短标签用于定位，适合居中，例如：

- `第一季度`
- `总计`
- `计划收入`
- `市场投入`

长说明用于阅读，优先左对齐，例如：

- `调整公司战略，制定当年经营和工作计划`

规则参数说明按长度区分：

- 短句居中。
- 长句左对齐。

### 3.4 通过内部留白改善格子观感，首版不优先改列宽

用户提出“细长格子要稍微变宽一点，上下都留空余”。
实现时首版优先通过以下方式改善观感：

- 增加 `padding`
- 增加 `line-height`
- 设置合适的 `min-height`

不优先直接修改 `colgroup` 列宽。
原因是表格列宽会影响整列所有行，牵动范围较大。若首版上线后仍觉得标题列或说明列过窄，再单独做列宽专项微调。

### 3.5 当前业务颜色语义保持不变

现有颜色语义继续保留：

- 绿色：可编辑输入格。
- 灰色：锁定 / 只读。
- 黄色 / 橙色：计算、提醒或重点核对。
- 蓝色：当前输入焦点。
- 红色：输入错误。

文字和间距优化不得覆盖这些语义。

## 4. 文字分类与样式口径

### 4.1 一级区域标题

对应现有类名：

```html
<td class="section-band band-quarter" rowspan="40">每季度工作</td>
```

业务语义：

- 大区块视觉锚点。
- 告诉玩家当前区域属于年初工作、每季度工作、年末工作或其他收支。

建议样式：

| 项 | 口径 |
|---|---|
| 字号 | `14px ~ 15px` |
| 字重 | `700` |
| 行距 | `1.25` |
| 对齐 | 居中 |
| 方向 | 继续竖排 |
| 字距 | `1.5px ~ 2px` |
| 留白 | 保持区域感，避免文字贴边 |

说明：

- 该类标题已经通过竖排、背景色和 rowspan 形成强视觉锚点，不需要过度放大。
- 若字号过大，竖排文字会显得拥挤。

### 4.2 二级任务标题

对应现有类名：

```html
<td class="group-title" colspan="2">1. 支付上年度所得税</td>
```

业务语义：

- 某一个经营动作块的标题。
- 玩家扫表时用于快速识别“这一块在做什么”。

用户确认方向：

- 做成居中。
- 字体稍微大一点。
- 首选可以做到 `16px`。
- 格子上下左右要有空余。

建议样式：

| 项 | 口径 |
|---|---|
| 字号 | 首选 `16px`；若真实长标题换行过多，可回调到 `15px` |
| 字重 | `700` |
| 行距 | `1.45` |
| 对齐 | 居中 |
| 上下留白 | `10px ~ 12px` |
| 左右留白 | `12px` |
| 最小高度 | 建议 `40px ~ 44px` |

说明：

- 二级任务标题是本轮最应该强化的文字。
- 首版不为二级标题单独调整列宽，先通过 padding、line-height 和 min-height 改善“细长格子”的观感。
- 若实现后长标题换行导致表格高度明显膨胀，需要回看真实页面后再决定是否从 `16px` 回调到 `15px`。

### 4.3 普通业务内容

示例：

```html
<td class="note-cell" colspan="2">贵宾厅拆除 1M / 间</td>
```

业务语义：

- 短业务项。
- 单位价格项。
- 行内项目名。
- 玩家只需快速识别，不需要阅读长句。

用户确认方向：

- 做成居中。
- 格子放大一点。
- 上下有空余。

建议新增语义类：

```html
<td class="note-cell item-label" colspan="2">贵宾厅拆除 1M / 间</td>
```

建议样式：

| 项 | 口径 |
|---|---|
| 字号 | `14px` |
| 字重 | `500` |
| 行距 | `1.5` |
| 对齐 | 居中 |
| 上下留白 | `9px ~ 10px` |
| 左右留白 | `10px ~ 12px` |
| 最小高度 | 建议 `36px` |

说明：

- 普通业务内容不建议使用 `16px`，否则会和二级任务标题争抢层级。
- 普通业务内容只适用于短内容；如果是长句，应归入流程说明或规则参数说明。

### 4.4 阶段短标签

示例：

```html
<td class="note-cell center">第一季度</td>
```

业务语义：

- 阶段定位。
- 表头或局部短标签。
- 玩家用来确定当前列、当前阶段或当前统计项。

用户确认方向：

- 居中。
- 格子放大一点。
- 文字放大一点。
- 上下有空余。

建议新增语义类：

```html
<td class="note-cell period-label center">第一季度</td>
```

建议样式：

| 项 | 口径 |
|---|---|
| 字号 | `14px ~ 15px` |
| 字重 | `700` |
| 行距 | `1.4` |
| 对齐 | 居中 |
| 上下留白 | `9px ~ 10px` |
| 左右留白 | `10px` |
| 最小高度 | 建议 `36px` |

说明：

- 阶段短标签可以比普通业务内容更粗。
- 不建议全部固定到 `16px`，否则阶段标签会比部分任务标题更抢眼。

### 4.5 流程说明

示例：

```html
<td class="note-cell center" colspan="3">调整公司战略，制定当年经营和工作计划</td>
```

业务语义：

- 告诉玩家需要做什么动作。
- 通常是完整短句或长句。
- 玩家需要阅读理解，而不是只看一个短标签。

用户确认方向：

- 优先左对齐。
- 格子放大一点。
- 文字放大。
- 文字加粗。
- 上下有空余。

建议新增语义类：

```html
<td class="note-cell instruction-note" colspan="3">调整公司战略，制定当年经营和工作计划</td>
```

建议样式：

| 项 | 口径 |
|---|---|
| 字号 | `14px` |
| 字重 | `600` |
| 行距 | `1.55` |
| 对齐 | 左对齐 |
| 上下留白 | `10px ~ 12px` |
| 左右留白 | `12px` |
| 最小高度 | 建议 `38px ~ 42px` |

说明：

- 流程说明建议使用 `600`，不建议全部使用 `700`，避免说明文字变得像标题。
- 如果某条流程说明极短，仍可保留居中，但首版默认以左对齐为主。

### 4.6 规则参数说明

示例：

```html
<td class="note-cell center" colspan="4">一般企业 25%，支线机场贵宾 15%</td>
```

业务语义：

- 描述税率、利率、单位、限制、规则口径等参数。
- 常包含数字、百分比、单位或条件。

用户确认方向：

- 短句居中。
- 长句左对齐。
- 格子放大一点。
- 文字放大。
- 文字加粗。
- 上下有空余。

建议新增语义类：

```html
<td class="note-cell rule-note rule-note-short" colspan="4">一般企业 25%，支线机场贵宾 15%</td>
```

或：

```html
<td class="note-cell rule-note rule-note-long" colspan="4">较长规则说明文字</td>
```

建议样式：

| 项 | 短句口径 | 长句口径 |
|---|---|---|
| 字号 | `14px` | `14px` |
| 字重 | `600` | `600` |
| 行距 | `1.5` | `1.55` |
| 对齐 | 居中 | 左对齐 |
| 上下留白 | `10px` | `10px ~ 12px` |
| 左右留白 | `12px` | `12px` |
| 数字显示 | 等宽数字 | 等宽数字 |

短句 / 长句判定建议：

- 首版采用人工语义标注，不写自动字数判断逻辑。
- 单行短规则、不会明显换行的规则说明，可标记为 `rule-note-short`。
- 包含较长句子、多个条件、可能换行的规则说明，标记为 `rule-note-long`。

### 4.7 输入数字与计算数字

业务语义：

- 玩家手工填写的数字。
- 系统计算的金额、数量、合计、季末现金等。

建议样式：

| 类型 | 字号 | 字重 | 行距 | 对齐 | 留白 |
|---|---:|---:|---:|---|---|
| 输入数字 | `14px` | `500` | `1.4` | 居中 | 输入框最小高度 `34px ~ 36px` |
| 计算数字 | `14px` | `700` | `1.4` | 居中 | 上下 `8px ~ 10px`，左右 `10px` |

统一增加：

```css
font-variant-numeric: tabular-nums;
```

说明：

- 首版不把经营页数字从居中改成右对齐。
- 等宽数字可以提升金额和数量横向核对稳定性。
- 输入焦点仍沿用蓝色描边 / 浅蓝光晕，不覆盖绿色、红色、灰色等业务底色。

### 4.8 提醒强调行

对应现有类名：

```html
<td class="reminder-cell" colspan="9">请将短期贷款右移一格</td>
```

业务语义：

- 需要玩家特别注意的提示。
- 视觉优先级高于普通说明。

建议样式：

| 项 | 口径 |
|---|---|
| 字号 | `15px` |
| 字重 | `700 ~ 800` |
| 行距 | `1.5` |
| 对齐 | 居中 |
| 上下留白 | `10px ~ 12px` |
| 左右留白 | `12px` |

说明：

- 提醒强调行可继续保持黄色 / 橙色视觉语义。
- 不在本轮新增提醒规则，只统一考虑上下左右留白。

## 5. 后续实现建议

### 5.1 优先通过 CSS 变量集中控制

建议在 `OperatingSheet.vue` 的 `.sheet-frame` 或相近根节点中增加经营页文字变量：

```css
.sheet-frame {
  --operating-section-title-font-size: 14px;
  --operating-group-title-font-size: 16px;
  --operating-body-font-size: 14px;
  --operating-note-font-size: 14px;
  --operating-cell-padding-y: 10px;
  --operating-cell-padding-x: 12px;
}
```

好处：

- 后续微调可以集中改变量。
- 不需要在很多类里重复写固定值。
- 方便如果用户验收后希望把二级标题从 `16px` 回调到 `15px`。

### 5.2 保留原类名，补充语义修饰类

不建议大面积删除现有类名。
建议保留现有基础类，再补充语义修饰类：

```html
<td class="group-title">...</td>
<td class="note-cell item-label">...</td>
<td class="note-cell period-label center">...</td>
<td class="note-cell instruction-note">...</td>
<td class="note-cell rule-note rule-note-short">...</td>
<td class="note-cell rule-note rule-note-long">...</td>
```

这样既能复用现有样式，也能让后续维护者看出文字语义。

### 5.3 首版不依赖自动识别

不要写前端逻辑自动判断“文字长度超过多少就左对齐”。
经营页是固定模板，首版应在模板中人工标注语义类。

原因：

- 自动判断会受版本文案差异影响。
- 有些短文本虽然短，但语义上仍可能是规则说明。
- 手动标注更可控，也更符合当前 Excel 模板固定的特点。

### 5.4 首版不大幅调整列宽

虽然用户提出“细长格子稍微变宽一点”，但列宽调整会影响整张表。
首版建议先只改格子内部：

- padding
- min-height
- line-height
- 字号和字重

实现后如果仍明显感觉某些二级任务标题列过窄，再单独讨论列宽微调。

## 6. 验收标准

后续 `I16-02` 实现后，至少按以下标准验收：

1. 二级任务标题明显比普通内容更醒目，且居中显示。
2. 二级任务标题上下左右有留白，不贴边。
3. 普通业务内容居中，短内容看起来规整。
4. 阶段短标签居中，能清楚承担表头 / 阶段定位作用。
5. 流程说明优先左对齐，长句阅读比原来更自然。
6. 规则参数说明短句居中、长句左对齐，数字和百分比更容易核对。
7. 输入数字和计算数字使用等宽数字，不影响整数校验和输入焦点。
8. 绿色可编辑、灰色锁定、黄色 / 橙色提醒、蓝色焦点、红色错误等业务颜色语义不被破坏。
9. 页面没有明显文字裁切、重叠、异常换行。
10. 经营页整体高度可接受，不能因为留白过大导致滚动明显失控。
11. 宽屏和常见笔记本宽度下均能正常阅读；若小屏触发横向滚动，应与现有 Excel 表格行为一致。

## 8. 待实现时重点关注

- `note-cell center` 当前承载语义过多，开发时需要逐处判断并加上 `item-label`、`period-label`、`instruction-note` 或 `rule-note`。
- `group-title` 有些是 `colspan`，有些是 `rowspan`，实现二级标题居中和最小高度时需要确认多行合并格不会挤压。
- `section-band` 是竖排大区块标题，不能直接套用二级任务标题的 `16px` 口径。
- `reminder-cell` 仍属于高强调提示，不应和普通说明混为一类。
- 数字等宽只影响显示稳定性，不应改变值、格式化规则和提交 payload。
