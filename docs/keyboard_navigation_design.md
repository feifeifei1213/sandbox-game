# 玩家端 + 管理员端统一方向键导航开发说明

> 更新日期：2026-07-24
> 状态：已完成开发口径文档，待进入前端开发
> 适用范围：玩家端经营页、玩家端财报页、玩家端订单页市场投入；管理员端赛前配置页字典修改、初始基线录入页、订单管理页数量控制、订单管理页标段释放顺序。
> 文档定位：本文件是 `docs/input_navigation_design.md` 与 `docs/admin_input_navigation_design.md` 的方向键导航补充口径，只定义前端输入交互，不改变保存、提交、后端校验、订单公式、页面布局或业务流程。

## 1. 背景

`I14-01` 已完成玩家端 `Enter` 跳下一格和管理员端普通数字输入 `Enter` 结束输入态；`I15-02` 已完成管理员端指定连续录入区域的 `Enter` 跳下一格、自动展开和当前格高亮。

经过继续讨论，玩家端和管理员端指定连续录入区域都需要支持方向键跳格：

- `ArrowDown` 可以跳到输入顺序中的下一个格子。
- `ArrowUp` 可以退回到输入顺序中的上一个格子。

这个能力本质上是对既有“输入导航”的补充，而不是新增保存、提交或复杂 Excel 编辑器能力。

本次优化解决的问题是：

1. 连续录入时可以用方向键向下继续填写。
2. 发现上一格填错时，可以用方向键向上退回修改。
3. 玩家端和管理员端指定连续录入区域的键盘手感统一。
4. 保持当前格蓝色高亮，让用户明确知道正在填写哪一个格子。

本次优化不解决以下问题：

- 不把 `Enter` 或方向键做成保存。
- 不把 `Enter` 或方向键做成提交。
- 不把 `Enter` 或方向键做成“保存数量并刷新预览”。
- 不把 `Enter` 或方向键做成“保存顺序”。
- 不把 `Enter` 或方向键做成“确认初始化比赛”。
- 不引入完整 Excel 编辑器能力。
- 不接管整个玩家端或整个管理员端的所有输入框。
- 不接管按钮、下拉框、复选框、搜索框、确认文本框或多行文本框。
- 不修改任何业务数据结构、后端接口、订单生成规则、财报公式或 Excel 公式链。

## 2. 总体口径

### 2.1 键位语义

在本次纳入范围的连续录入区域内，键位语义统一如下：

| 按键 | 行为 |
|---|---|
| `Enter` | 跳到输入顺序中的下一个可编辑输入框 |
| `ArrowDown` | 跳到输入顺序中的下一个可编辑输入框 |
| `ArrowUp` | 跳到输入顺序中的上一个可编辑输入框 |

说明：

- `Enter` 保持既有“下一格”语义。
- `ArrowDown` 与 `Enter` 同向。
- `ArrowUp` 是反向退回。
- 本次不新增 `Shift + Enter`、`Tab`、`Shift + Tab` 的自定义跳转。

### 2.2 通用跳转规则

无论玩家端还是管理员端，只要是本次明确接管的连续录入区域，都必须遵守以下规则：

- 当前输入框先结束输入态，再移动焦点。
- 跳转时只在当前页面 / 当前模块 / 当前指定区域内查找候选输入框。
- 候选输入框必须是 `HTMLInputElement`。
- 候选输入框必须没有 `disabled`。
- 候选输入框必须没有 `readonly`。
- 候选输入框不能是 `type="hidden"`。
- 候选输入框必须仍在当前 DOM 中。
- 候选输入框必须可见。
- 候选输入框必须可聚焦。
- 候选输入框必须属于当前页面明确标记的连续录入区域。
- 跳转后聚焦目标输入框，并尽量选中文本，方便用户直接覆盖输入。

以下输入框或控件不参与跳转：

- 搜索框。
- 文本确认框。
- 普通原因输入。
- 跳过原因输入。
- 快照恢复原因输入。
- 字典方案下拉框。
- 沙盘版本下拉框。
- 年份下拉框。
- 市场筛选下拉框。
- 订单类型筛选下拉框。
- 所得税税率下拉框。
- 复选框。
- 按钮。
- `textarea`。
- 自动计算值。
- 只读展示值。
- 锁定格。
- 隐藏格。
- 未开放阶段输入格。
- 正在保存、生成、释放、提交等处理中被禁用的输入框。

### 2.3 边界行为

如果当前输入框已经是当前区域内最后一个可编辑输入框：

- 再按 `Enter` 时只结束输入态。
- 再按 `ArrowDown` 时只结束输入态。
- 不循环回第一个输入框。
- 不跳到按钮。
- 不触发保存、提交、生成、释放、选单或交付动作。

如果当前输入框已经是当前区域内第一个可编辑输入框：

- 再按 `ArrowUp` 时只结束输入态。
- 不循环到最后一个输入框。
- 不跳到按钮。
- 不触发保存、提交、生成、释放、选单或交付动作。

### 2.4 中文输入法处理

赛前配置页字典修改输入的是中文文本，玩家端和管理员端也可能在某些输入框中遇到输入法组合态，因此方向键导航必须保留输入法保护。

规则：

- 当 `event.isComposing === true` 时，不处理 `Enter` / `ArrowDown` / `ArrowUp` 跳转。
- 当 `event.key === 'Process'` 时，不处理 `Enter` / `ArrowDown` / `ArrowUp` 跳转。
- 只有中文输入法确认完成后的普通按键才执行结束输入态 / 跳转。

特别说明：

- 中文输入法候选词常用 `ArrowUp` / `ArrowDown` 选择候选项。
- 如果组合态下误接管方向键，会造成“用户想选候选词，焦点却跳到别的格子”的问题。
- 因此字典修改区域必须优先保护输入法组合态。

### 2.5 数字输入框方向键默认行为

浏览器对 `type="number"` 输入框有默认行为：按 `ArrowUp` / `ArrowDown` 可能会让数字自动加一或减一。

本次确认后的口径是：

- 在明确接管方向键导航的连续录入区域内，`ArrowUp` / `ArrowDown` 的语义是“跳格”，不是“数值加减”。
- 因此一旦判断当前按键应由输入导航接管，就必须调用 `event.preventDefault()`。
- 这样可以避免出现“数字偷偷变了，同时又跳格”的异常体验。

注意：

- 这个接管只发生在本文件列出的连续录入区域。
- 未纳入范围的普通数字输入框，仍保持既有页面行为。

### 2.6 当前格高亮

本次统一方向键导航覆盖的连续录入区域都应保留当前格高亮。

高亮口径统一为：

```text
蓝色描边 / 浅蓝光晕 = 当前正在输入
```

注意：

- 高亮是叠加样式，不替换原业务底色。
- 绿色仍然表示可编辑。
- 红色仍然表示校验错误。
- 灰色仍然表示锁定、只读或禁用。
- 黄色 / 橙色等已有提示语义不能被覆盖。
- 不在玩家端或管理员端全局增加高亮，只在本文件列出的连续录入区域加。

## 3. 玩家端覆盖范围

|---|---|---|---|---|
| 玩家经营页 | 经营表格内可编辑数字输入格 | 跳到下一个可编辑数字输入格 | 跳到上一个可编辑数字输入格 | 做 |
| 玩家财报页 | 手工数字输入格 | 跳到下一个可编辑数字输入格 | 跳到上一个可编辑数字输入格 | 做 |
| 玩家订单页 | 当前年份市场投入矩阵数字输入格 | 跳到下一个可编辑数字输入格 | 跳到上一个可编辑数字输入格 | 做 |

### 3.2 玩家经营页

玩家经营页跳转只在经营主表内发生。

跳转顺序：

```text
当前模块内，按页面 DOM 顺序从前到后；反向时按同一顺序从后到前。
```

规则：

- 只跳当前页面中带有输入导航标记的可编辑数字输入格。
- 只跳当前阶段或当前已开放范围内可编辑的输入格。
- 未开放阶段输入格自动跳过。
- 只读联动格自动跳过。
- 管理员下发奖惩只读展示格自动跳过。
- 失效草稿中不可编辑的格子自动跳过。
- 当前格存在整数校验错误时仍允许跳走，错误样式保留。
- 跳转不触发草稿保存。
- 跳转不触发阶段提交。

边界规则：

- 最后一个可编辑格按 `Enter` / `ArrowDown` 只失焦。
- 第一个可编辑格按 `ArrowUp` 只失焦。
- 不循环。

### 3.3 玩家财报页

玩家财报页只让手工数字输入格参与跳转。

参与跳转的输入项：

- 制品。
- 成品。
- 材料。
- 企业认证得分。
- 生产人力得分。
- 关账速度得分。

不参与跳转的控件：

- 所得税税率下拉框。
- 自动计算值。
- 平衡校验结果。
- 保存按钮。
- 提交按钮。

规则：

- `Enter` / `ArrowDown` 跳到下一个可编辑手工输入格。
- `ArrowUp` 跳到上一个可编辑手工输入格。
- 已提交或不可编辑时，输入框不参与跳转。
- 当前格存在整数校验错误时仍允许跳走，错误样式保留。
- 跳转不触发草稿保存。
- 跳转不触发财报提交。

边界规则：

- 最后一个可编辑格按 `Enter` / `ArrowDown` 只失焦。
- 第一个可编辑格按 `ArrowUp` 只失焦。
- 不循环。

### 3.4 玩家订单页

玩家订单页只允许当前年份市场投入矩阵参与跳转。

参与跳转：

- 当前年份市场投入区中的可编辑数字输入框。

不参与跳转：

- 市场预测展示区。
- 订单卡片。
- 本组已选订单。
- 交付面板。
- 选择订单按钮。
- 放弃本轮按钮。
- 交付订单按钮。

规则：

- `Enter` / `ArrowDown` 按市场投入矩阵当前页面顺序跳到下一格。
- `ArrowUp` 按市场投入矩阵当前页面顺序跳到上一格。
- 关闭市场的投入格跳过。
- 已提交投入后变成不可编辑的投入格跳过。
- 未到市场投入阶段或不允许提交投入时，输入格不参与跳转。
- 当前格存在整数校验错误时仍允许跳走，错误样式保留。
- 跳转不触发市场投入提交。
- 跳转不触发选单、放弃或交付动作。

边界规则：

- 最后一个可编辑格按 `Enter` / `ArrowDown` 只失焦。
- 第一个可编辑格按 `ArrowUp` 只失焦。
- 不循环。

### 4.3 赛前配置页 / 业务显示字典

字典修改区域的跳转顺序按当前筛选结果决定，而不是简单 DOM 顺序。

跳转顺序：

```text
当前筛选结果中的分类顺序 -> 分类内 displayOrder 顺序
```

规则：

- 没有搜索、没有开启“只看已修改”时，按全量字典顺序跳转。
- 正在搜索时，只在搜索结果内跳转。
- 开启“只看已修改”时，只在当前筛选结果内跳转。
- 不强行跳到被搜索条件隐藏的字段。
- 不可编辑字典项不参与跳转。
- 目标输入框所在分类折叠时，先展开分类，再等待 DOM 更新，然后聚焦目标输入框。
- 中文输入法组合态下不接管 `Enter` / `ArrowDown` / `ArrowUp`。

按键行为：

- `Enter` / `ArrowDown`：当前字典项 -> 当前筛选结果中的下一个可编辑字典项。
- `ArrowUp`：当前字典项 -> 当前筛选结果中的上一个可编辑字典项。

边界规则：

- 最后一个可编辑字典项按 `Enter` / `ArrowDown` 只失焦。
- 第一个可编辑字典项按 `ArrowUp` 只失焦。
- 不循环。

### 4.4 初始基线录入页

初始基线页是共享初始基线模板，页面本质是一张从上到下的数字录入表。

跳转顺序：

```text
从上到下，按 fieldDefs 当前页面顺序；反向时从下到上。
```

规则：

- `Enter` / `ArrowDown` 跳到下一个可编辑基线输入框。
- `ArrowUp` 跳到上一个可编辑基线输入框。
- 页面加载中不存在的输入框不参与跳转。
- `view.editable === false` 时被禁用的输入框不参与跳转。
- 已提交并锁定后的输入框不参与跳转。
- 当前格存在整数校验错误时仍允许跳走，错误样式保留。

边界规则：

- 最后一个可编辑基线输入框按 `Enter` / `ArrowDown` 只失焦。
- 第一个可编辑基线输入框按 `ArrowUp` 只失焦。
- 不跳到“提交并应用到全部小组”按钮。
- 不触发提交。

### 4.5 订单管理页 / 数量控制

订单数量控制区的 DOM 渲染顺序与用户确认的录入顺序不同，因此必须使用显式业务顺序，不能简单使用 DOM 顺序。

已确认录入顺序：

```text
阶段 -> 年份 -> 市场 -> 订单类型
```

也就是先填完某一阶段下某一年份数量这一整列，再进入下一年份数量列。

示例：

```text
本地市场 - 订单类型 A - 1年数量
本地市场 - 订单类型 B - 1年数量
本地市场 - 订单类型 C - 1年数量
本地市场 - 订单类型 D - 1年数量
区域市场 - 订单类型 A - 1年数量
区域市场 - 订单类型 B - 1年数量
区域市场 - 订单类型 C - 1年数量
区域市场 - 订单类型 D - 1年数量
国内市场 - 订单类型 A - 1年数量
国内市场 - 订单类型 B - 1年数量
国内市场 - 订单类型 C - 1年数量
国内市场 - 订单类型 D - 1年数量
全球市场 - 订单类型 A - 1年数量
全球市场 - 订单类型 B - 1年数量
全球市场 - 订单类型 C - 1年数量
全球市场 - 订单类型 D - 1年数量
然后进入：
本地市场 - 订单类型 A - 2年数量
本地市场 - 订单类型 B - 2年数量
...
```

技术口径：

```ts
for (const stage of forecastStages) {
  for (const yearNo of stage.years) {
    for (const market of marketOptions) {
      for (const orderType of orderTypeOptions) {
        keys.push(forecastInputKey(stage.forecastStageCode, yearNo, market.code, orderType.code))
      }
    }
  }
}
```

按键行为：

- `Enter` / `ArrowDown`：沿显式业务顺序向后找下一个可编辑数量格。
- `ArrowUp`：沿显式业务顺序向前找上一个可编辑数量格。

跳过规则：

- 已确认年份整列锁定，即 `isForecastYearLocked(yearNo) === true`。
- 正在保存数量，即 `savingForecastControl === true`。
- 正在生成订单池，即 `generatingPool === true`。
- 禁用、只读、隐藏的输入框。
- 不存在于当前模板选项内的市场或订单类型。

边界规则：

- 最后一个可编辑数量格按 `Enter` / `ArrowDown` 只失焦。
- 第一个可编辑数量格按 `ArrowUp` 只失焦。
- 不触发“保存数量并刷新预览”。

### 4.6 订单管理页 / 标段顺序 / 释放顺序

标段释放顺序是纵向数字表。

跳转顺序：

```text
sortedItems[0].releaseSequenceNo
-> sortedItems[1].releaseSequenceNo
-> sortedItems[2].releaseSequenceNo
-> ...
```

反向时按同一顺序从后往前。

按键行为：

- `Enter` / `ArrowDown`：跳到下一行可编辑释放顺序输入框。
- `ArrowUp`：跳到上一行可编辑释放顺序输入框。

跳过规则：

- 市场未开启，即 `!item.marketEnabled`。
- 当前配置不可更新，即 `!config?.canUpdateConfig`。
- 正在保存顺序，即 `savingConfig === true`。
- 正在生成订单池，即 `generatingPool === true`。
- 禁用、只读、隐藏的输入框。

边界规则：

- 最后一个可编辑释放顺序输入框按 `Enter` / `ArrowDown` 只失焦。
- 第一个可编辑释放顺序输入框按 `ArrowUp` 只失焦。
- 不触发“保存顺序”。

## 5. 技术实现建议

### 5.1 通用工具扩展

当前已有工具文件：

```text
frontend/src/utils/input-navigation.ts
```

建议在现有能力基础上补充方向概念。

推荐类型：

```ts
type InputNavigationDirection = 'next' | 'previous'
```

推荐新增或调整的工具函数：

```ts
resolveInputNavigationDirection(event: KeyboardEvent): InputNavigationDirection | null
focusAdjacentInputFromList(
  event: KeyboardEvent,
  inputs: Array<HTMLInputElement | null | undefined>,
  direction: InputNavigationDirection,
): void
handleSequentialInputNavigation(event: KeyboardEvent): void
```

语义：

- `resolveInputNavigationDirection`
  - `Enter` / `ArrowDown` 返回 `next`。
  - `ArrowUp` 返回 `previous`。
  - 其他按键返回 `null`。
  - 输入法组合态返回 `null`。
- `focusAdjacentInputFromList`
  - 用于字典、订单数量控制等自定义序列场景。
  - 页面负责传入有业务顺序的输入框列表。
  - 工具负责过滤不可聚焦输入框、查找目标、聚焦、选中文本、边界失焦。
- `handleSequentialInputNavigation`
  - 用于 DOM 顺序即录入顺序的区域。
  - 从当前 `data-enter-nav-scope` 内查找 `input[data-enter-nav]`。
  - 根据方向查找前一个或后一个可编辑输入框。

已有函数保留：

```ts
confirmInputOnEnter(event: KeyboardEvent): void
focusNextInputOnEnter(event: KeyboardEvent): void
focusInputElement(input: HTMLInputElement | null | undefined): boolean
canFocusEnterInput(input: HTMLInputElement | null | undefined): input is HTMLInputElement
shouldHandleEnterNavigation(event: KeyboardEvent): boolean
```

说明：

- 可以保留 `focusNextInputOnEnter` 兼容旧调用。
- 新页面建议逐步改用 `handleSequentialInputNavigation`。
- 管理员普通数字输入框继续使用 `confirmInputOnEnter`，不进入方向键跳格。

### 5.3 不建议的实现方式

不建议做全局键盘监听：

- 玩家端和管理员端都有按钮、下拉框、文本域等不应被跳格接管的控件。
- 全局监听容易影响浏览器和组件自身键盘行为。
- 字典中文输入法需要局部组合态保护。
- 订单数量控制存在显式业务顺序，不能用全局 DOM 顺序表达。

不建议把按钮纳入跳转链：

- 最后一格跳到保存按钮后，用户可能下意识再按一次回车误触发保存。
- 本次设计的底线是：键盘跳格不触发任何业务动作。

不建议让边界循环：

- 最后一格循环回第一格容易让用户误以为还没填完。
- 第一格按上键循环到最后一格也容易造成定位混乱。
- 首版边界统一做失焦，更稳妥。

## 6. 验收清单

### 6.1 玩家端经营页

- Q1 阶段输入格按 `Enter` 跳到下一个 Q1 可编辑输入格。
- Q1 阶段输入格按 `ArrowDown` 跳到下一个 Q1 可编辑输入格。
- Q1 阶段输入格按 `ArrowUp` 跳到上一个 Q1 可编辑输入格。
- Q2/Q3/Q4 未开放时不会跳到锁定格。
- 年末未开放时不会跳到年末输入格。
- 当前输入格有蓝色描边 / 浅蓝光晕。
- 输入小数后可以跳走，但原格保留错误样式。
- 最后一个可编辑输入格按 `Enter` / `ArrowDown` 只失焦。
- 第一个可编辑输入格按 `ArrowUp` 只失焦。
- 不触发草稿保存。
- 不触发阶段提交。

### 6.2 玩家端财报页

- 制品输入后按 `Enter` / `ArrowDown` 跳到成品。
- 成品输入后按 `ArrowUp` 跳回制品。
- 所得税税率下拉框不参与跳转。
- 企业认证得分、生产人力得分、关账速度得分可按页面顺序跳转。
- 当前输入格有焦点高亮。
- 最后一格按 `Enter` / `ArrowDown` 只失焦。
- 第一格按 `ArrowUp` 只失焦。
- 不触发财报提交。

### 6.3 玩家端订单页

- 市场投入输入后按 `Enter` / `ArrowDown` 跳到下一个可编辑投入格。
- 市场投入输入后按 `ArrowUp` 跳到上一个可编辑投入格。
- 关闭市场的投入格被跳过。
- 已提交投入后不可编辑的投入格被跳过。
- 当前投入格有焦点高亮。
- 最后一格按 `Enter` / `ArrowDown` 只失焦。
- 第一格按 `ArrowUp` 只失焦。
- 不提交市场投入。
- 不选择订单。
- 不交付订单。

### 6.4 管理员赛前配置页 / 字典修改

- 当前字典输入框按 `Enter` / `ArrowDown` 跳到当前筛选结果中的下一个可编辑字典输入框。
- 当前字典输入框按 `ArrowUp` 跳到当前筛选结果中的上一个可编辑字典输入框。
- 如果目标输入框在折叠分类中，系统先展开分类，再聚焦目标输入框。
- 搜索框不参与跳转。
- “只看已修改”开启时，只在筛选结果内跳转。
- 只读字段、不可编辑字段不参与跳转。
- 中文输入法组合态下，`Enter` / `ArrowDown` / `ArrowUp` 不触发跳格。
- 当前字典输入框有蓝色高亮。
- 空值红色错误样式不被蓝色高亮覆盖。

### 6.5 管理员初始基线录入页

- 第一行输入后按 `Enter` / `ArrowDown` 跳到第二行输入框。
- 第二行输入后按 `ArrowUp` 跳回第一行输入框。
- 按页面从上到下 / 从下到上顺序连续跳转。
- 已提交锁定后，输入框不可编辑且不参与跳转。
- 最后一行输入框按 `Enter` / `ArrowDown` 只失焦。
- 第一行输入框按 `ArrowUp` 只失焦。
- 不触发提交。
- 当前输入格显示蓝色高亮。
- 小数错误红色样式仍然保留。

### 6.6 管理员订单管理页 / 数量控制

- 在 `本地市场 - 订单类型 A - 1年数量` 按 `Enter` / `ArrowDown`，跳到 `本地市场 - 订单类型 B - 1年数量`。
- 在 `本地市场 - 订单类型 B - 1年数量` 按 `ArrowUp`，跳回 `本地市场 - 订单类型 A - 1年数量`。
- 本地市场 1 年数量填完后，跳到区域市场 1 年数量。
- 当前年份这一列全部市场、全部订单类型填完后，才进入下一年份数量列。
- 已锁定年份整列被跳过。
- 正在保存数量或生成订单池时不发生跳转。
- 最后一个可编辑数量格按 `Enter` / `ArrowDown` 只失焦。
- 第一个可编辑数量格按 `ArrowUp` 只失焦。
- 当前数量格显示蓝色高亮。
- 方向键不会导致数字自动加一或减一。
- 不触发“保存数量并刷新预览”。

### 6.7 管理员订单管理页 / 标段顺序 / 释放顺序

- 第一行释放顺序输入后按 `Enter` / `ArrowDown`，跳到下一行可编辑释放顺序。
- 第二行释放顺序输入后按 `ArrowUp`，跳回上一行可编辑释放顺序。
- 市场未开启的行被跳过。
- 不可更新或保存中状态下的输入框被跳过。
- 最后一个可编辑释放顺序按 `Enter` / `ArrowDown` 只失焦。
- 第一个可编辑释放顺序按 `ArrowUp` 只失焦。
- 当前释放顺序格显示蓝色高亮。
- 方向键不会导致数字自动加一或减一。
- 不触发“保存顺序”。

## 7. 与既有文档的关系

本文件是方向键导航的统一补充口径，优先级高于以下旧文档中关于“方向键导航暂不纳入”的描述：

- `docs/input_navigation_design.md`
- `docs/admin_input_navigation_design.md`

- `docs/input_navigation_design.md` 仍作为 `I14-01` 的历史基线，记录玩家端 `Enter` 跳下一格和管理员普通数字输入 `Enter` 失焦的首版口径。
- `docs/admin_input_navigation_design.md` 仍作为 `I15-01 / I15-02` 的历史基线，记录管理员端四个指定区域 `Enter` 跳格、自动展开和高亮的口径。

- 未纳入本文件范围的管理员普通输入框，仍保持 `I14-01` 的 `Enter` 失焦口径，不做方向键跳格。
