# 沙盘经营系统最小状态机 v0.1

> 更新日期：2026-05-27
> 用途：把当前已确认的流程状态沉淀成最小状态机，作为正式需求文档、接口设计和数据模型设计的直接依据。  
> 说明：本文件描述的是“首版最小可用状态机”，不追求重型工作流，而追求规则清晰、边界可实现。  
> 边界：本文件主要定义流程状态，不依赖 Excel 单元格显示名称的最终版本；后续命名微调通常不影响本状态机。

## 1. 适用对象

- 玩家组年度经营页
- 玩家组年度订单页
- 玩家组年度财报页
- 管理员年度控制
- 管理员订单管理
- 管理员异常解锁
- 管理员汇总口径生效/失效

---

## 2. 状态机设计原则

### 2.1 首版只保留一条主链

首版以“年份”为主状态对象，每个 `组 + 年` 都按以下主链流转：

`未开放 -> 经营中 -> 待财报 -> 财报中 -> 已完成`

### 2.2 叠加态不进入主链

以下状态不作为新的年份主链节点，而作为叠加态或管理动作处理：

- `已破产`
- `异常解锁中`
- `回退补提中`
- `正式年份订单竞标中`

这样做的原因是：

- 避免把首版做成重型流程引擎
- 保证玩家端和管理员端的判断逻辑可控
- 让“流程状态”和“异常状态”分层实现
- 订单竞标是正式年份经营前置流程，不替代经营页 `Q1/Q2/Q3/Q4/年末` 主链

## 3. 年份主状态定义

| 状态编码 | 状态名称 | 含义 | 玩家端表现 | 管理员端表现 |
|---|---|---|---|---|
| `LOCKED` | 未开放 | 该年份尚未被管理员开放，玩家不可进入或不可编辑 | 标签可见，不可进入或仅可查看锁定态 | 可查看是否已开放 |
| `OPERATING` | 经营中 | 该年份经营页已开放，玩家可按阶段提交 Q1/Q2/Q3/Q4/年末 | 当前开放阶段可编辑，已提交阶段只读，未来阶段锁定 | 可查看本组本年经营进度 |
| `REPORT_PENDING` | 待财报 | 本年经营已完成，财报页已具备开放条件 | 经营页只读，财报页可进入 | 可看到该组等待提交财报 |
| `REPORTING` | 财报中 | 玩家已进入财报填写阶段，但尚未完成财报提交 | 财报自动项显示，绿色手工项可填 | 可查看财报未完成状态 |
| `COMPLETED` | 已完成 | 本年财报提交成功，本年度结果正式生效 | 本年经营页和财报页只读 | 该年数据计入汇总 |

---

## 4. 年份主状态流转

| 当前状态 | 触发事件 | 前置条件 | 目标状态 | 结果 |
|---|---|---|---|---|
| `LOCKED` | 管理员开放该年 | 上一年已允许进入下一年；该组未破产 | `OPERATING` | 玩家可开始本年经营 |
| `OPERATING` | 年末提交成功 | Q1/Q2/Q3/Q4/年末提交已全部完成且通过当前阶段必填校验 | `REPORT_PENDING` | 本年经营锁定，财报页开放 |
| `REPORT_PENDING` | 玩家进入财报页并开始填写 | 财报页已开放；该组未破产 | `REPORTING` | 财报进入待提交状态 |
| `REPORTING` | 财报提交成功 | 财报手工项已完成；平衡校验通过 | `COMPLETED` | 本年结果生效并计入汇总 |

说明：

- `REPORT_PENDING` 与 `REPORTING` 分开，是为了把“已开放但还没动”和“已开始填但未提交”区分开。
- 如果首版实现时想更轻，也可把这两个状态在数据库中合并，但需求含义应保留。
- 经营阶段提交后展示的系统期末现金仅用于玩家线下自检，不作为状态流转前置条件。
- `0年` 不需要订单前置流程。
- `1年 ~ 最终年` 在 `Q1` 正式提交前，必须完成本年订单前置流程；订单前置流程不改变年份主状态，仍归属于 `OPERATING` 下的前置校验。

---

## 5. 经营阶段子状态

年份主状态中的 `OPERATING`，内部再分一层最小阶段状态，用于控制哪些区域可编辑。

| 阶段编码 | 阶段名称 | 可编辑范围 | 提交后结果 |
|---|---|---|---|
| `Q1_OPEN` | Q1 可填 | `年初区 + Q1` | Q1 提交成功后进入 `Q2_OPEN` |
| `Q2_OPEN` | Q2 可填 | `Q2` | Q2 提交成功后进入 `Q3_OPEN` |
| `Q3_OPEN` | Q3 可填 | `Q3` | Q3 提交成功后进入 `Q4_OPEN` |
| `Q4_OPEN` | Q4 可填 | `Q4` | Q4 提交成功后进入 `YEAR_END_OPEN` |
| `YEAR_END_OPEN` | 年末可填 | `年末区手工项` | 年末提交成功后年份主状态进入 `REPORT_PENDING` |

说明：

- 不单独存在“年初提交”阶段。
- `Q1` 阶段提交时一并校验 `年初区 + Q1`。
- 已提交阶段变为只读。
- 未到达的未来阶段保持可见但锁定。

## 6. 财报子状态

年份主状态中的财报部分采用以下最小子状态：

| 子状态编码 | 子状态名称 | 含义 |
|---|---|---|
| `REPORT_LOCKED` | 财报未开放 | 本年经营未完成，财报页不可填 |
| `REPORT_OPEN` | 财报可填 | 本年经营已完成，财报自动项已带出，手工项可填写 |
| `REPORT_SUBMITTED` | 财报已提交 | 财报提交成功，本年完成 |

映射关系：

- 年份状态为 `OPERATING` 时，财报子状态必然是 `REPORT_LOCKED`
- 年份状态为 `REPORT_PENDING` 或 `REPORTING` 时，财报子状态为 `REPORT_OPEN`
- 年份状态为 `COMPLETED` 时，财报子状态为 `REPORT_SUBMITTED`

---

## 7. 破产叠加态

`已破产` 不作为年份主链中的普通节点，而是叠加在某个组账户上的全局经营状态。

### 7.1 触发条件

- 在经营阶段提交节点，若现金流断裂，则破产
- 在最终年份，若所有者权益为负，则破产

### 7.2 破产后的系统行为

| 维度 | 行为 |
|---|---|
| 当前年份 | 停止继续填写 |
| 后续年份 | 全部不可再开放、不可填写 |
| 后续订单竞标 | 不参与后续年份或后续未开始标段的订单竞标与选单 |
| 历史数据 | 保留，只读 |
| 玩家端 | 可查看历史数据，不可编辑 |
| 管理员汇总 | 标记 `已破产` |

### 7.3 状态处理方式

- 一旦破产，后续不再推进正常年份主链
- 如果已破产，则管理员“开放下一年”动作对该组无效
- 如果任意未破产小组处于 `回退补提中`，管理员不能开放下一年；必须等该组重新提交到当前开放年份要求后再继续开年。

## 8. 正式年份订单前置状态

线上订单是正式年份经营前置流程，不单独改变年份主状态。建议按 `1年~8年 + 市场 + 订单类型` 维护多年订单数量控制台与市场预测，按 `年` 维护订单生成批次状态，按 `年 + 市场` 维护市场开启状态，按 `组 + 年 + 市场 + 订单类型` 维护投入与标段流程状态，并在经营页 `Q1` 进入/提交时统一校验本年订单前置是否完成。

### 8.0Z 多年订单数量控制台与市场预测

- 多年订单数量控制台是订单数量主来源，固定覆盖 `1年~8年 × 四个市场 × 四类产品`。
- 市场预测由多年订单数量控制台和订单生成公式链产生，固定按 `1~3年 / 4~5年 / 6~8年` 三段展示，不受管理员配置的最终年份裁剪。
- 每年订单池生成时只读取该年份、管理员已手动开启市场的控制台数量；未开启市场即使控制台有数量，也不生成订单、不进入抢单。
- 市场预测和控制台不直接推进年份主状态；只有当年订单池确认、投入提交、选单完成后，才影响正式年份 `Q1` 前置校验。

### 8.0A 年度市场开启状态

| 状态编码 | 状态名称 | 含义 |
|---|---|---|
| `ENABLED` | 已开启 | 该市场可读取多年控制台中的当年订单数量、生成订单池并参与抢单 |
| `DISABLED` | 未开启 | 该市场不生成订单池、不进入标段释放顺序、不参与抢单 |

说明：

- 本地市场默认 `ENABLED`。
- 区域市场、全国市场、全球市场默认 `DISABLED`。
- 管理员可在订单池确认前手动开启或关闭市场；订单池确认后，本年市场开启状态锁定。
- 市场开启完全以管理员当年手动状态为准，不因多年订单数量控制台中存在订单数量而自动开启。
- 未开启市场仍出现在玩家当前订单模板的完整市场投入表中，但对应输入框禁用并由系统自动按 `0` 提交；绕过前端提交非 `0` 时提交失败。
- 管理员可按 `年份 + 市场` 配置单市场投入上限；空值表示无上限，非空时必须为非负整数。
- 已有任意小组提交本年市场投入后，本年市场开启状态和单市场投入上限锁定。

### 8.0 年度订单生成状态

| 状态编码 | 状态名称 | 含义 |
|---|---|---|
| `NOT_GENERATED` | 未生成 | 当年订单池尚未生成 |
| `PREVIEW_GENERATED` | 已生成预览 | 管理员已生成预览订单池，可覆盖重生成 |
| `POOL_CONFIRMED` | 订单池已确认 | 管理员确认订单池，生成批次、随机种子和订单明细已固化 |
| `INVESTMENT_READY` | 投入已就绪 | 所有未破产小组已提交当年当前订单模板的全部市场投入 |
| `SEQUENCE_READY` | 顺序已生成 | 系统已为应开标段生成选单顺序 |
| `SELECTING` | 开标中 | 至少一个标段已释放或正在选单 |
| `COMPLETED` | 竞标完成 | 当年所有应开标段均已完成或跳过 |

说明：

- 预览阶段可反复重生成；确认订单池后不允许修改数量或重新生成。
- 释放第一个标段后，标段释放顺序锁定。
- 未开启市场不参与订单池生成状态推进，也不占用有效释放顺序。
- 订单生成状态仍是订单前置状态，不替代年份主状态。

### 8.1 标段状态

| 状态编码 | 状态名称 | 含义 |
|---|---|---|
| `NOT_REQUIRED` | 无需订单 | 仅用于 `0年` 或无需进入该标段抢单的场景 |
| `MARKET_DISABLED` | 市场未开启 | 该标段所属市场未开启，不生成订单、不进入开标 |
| `NO_ORDER_CONFIG` | 未配置订单 | 所属市场已开启，但该标段订单数量为 `0`，不进入开标 |
| `WAITING_INVESTMENT` | 等待投入 | 等待所有未破产小组提交当年当前订单模板的全部市场投入 |
| `SEQUENCE_READY` | 顺序已生成 | 系统已按规则生成该标段基础顺序及全部有效轮次顺序 |
| `WAITING_RELEASE` | 等待释放 | 标段顺序已生成，但尚未轮到该标段开标 |
| `SELECTING` | 选单中 | 当前标段某一轮已开启，玩家按本轮顺序选择订单 |
| `ROUND_READY` | 下一轮待开启 | 当前轮已结束，后续存在有效轮次，等待管理员开启下一轮 |
| `COMPLETED` | 标段选单完成 | 全部有效轮次结束、订单池选空或后续资格全部消失 |
| `SKIPPED` | 已跳过 | 该标段订单数量大于 `0`，但因所有未破产小组该标段投入均为 `0` 等流程原因跳过 |

### 8.2 标段状态流转

| 当前状态 | 触发事件 | 前置条件 | 目标状态 |
|---|---|---|---|
| `NOT_REQUIRED` | 市场未开启 | 该市场为 `DISABLED` | `MARKET_DISABLED` |
| `NOT_REQUIRED` | 标段未配置订单 | 市场已开启，但订单数量为 `0` | `NO_ORDER_CONFIG` |
| `WAITING_INVESTMENT` | 全部未破产小组提交市场投入 | 每组已完整提交当前订单模板全部投入，含明确的 `0` | `SEQUENCE_READY` |
| `WAITING_INVESTMENT` | 系统跳过标段 | 订单数量大于 `0`，但所有未破产小组该标段投入均为 `0` | `SKIPPED` |
| `SEQUENCE_READY` | 按管理员配置释放顺序排队 | 订单池已确认；选单顺序已固定 | `WAITING_RELEASE` |
| `WAITING_RELEASE` | 管理员手动释放标段 | 已轮到该标段；符合预设释放顺序 | 第一轮 `SELECTING` |
| `SELECTING` | 当前轮顺序走完 | 仍有后续有效轮次且订单池未空 | `ROUND_READY` |
| `ROUND_READY` | 管理员点击“开启下一轮” | 下一轮存在有资格小组且订单池未空 | 下一轮 `SELECTING` |
| `SELECTING` | 最后一个有效轮次走完 | 本轮全部小组已选择/放弃/被管理员代跳过/因破产失去资格 | `COMPLETED` |
| `SELECTING` | 订单池提前选空 | 当前标段无可选订单，当前轮剩余机会和未来轮次终止 | `COMPLETED` |
| `ROUND_READY` | 后续资格全部消失 | 后续轮次无有效参与小组 | `COMPLETED` |

### 8.3 订单前置完成判断

- `0年`：订单前置视为 `NOT_REQUIRED`。
- 正式年份：本年全部应开标段均为 `COMPLETED` 或 `SKIPPED`，且未开启市场为 `MARKET_DISABLED`、未配置订单标段为 `NO_ORDER_CONFIG`，则本年订单前置完成。
- 只有订单前置完成后，玩家才允许进入或提交正式年份经营页 `Q1`。
- 某组在某标段投入为 `0` 时，不参与该标段任何轮次；相关标段结束或跳过后，对该组视为该标段订单前置已完成。
- 市场龙头当前标段投入为 `0` 时同样无资格；龙头只改变有资格小组的基础顺序。若市场龙头已破产，则按没有有效市场龙头处理。
- 订单状态只约束正式年份 `Q1` 进入/提交，不改变 `Q2/Q3/Q4/年末/财报` 的主链状态。

### 8.3.1 选单轮次状态

贵宾服务版和生产制造版按当前标段投入确定轮次资格：投入 `1~2 / 3~5 / 6~8 / >=9` 分别参加 `1 / 2 / 3 / 4` 轮；机场版暂时保持一轮。建议按 `标段 + 轮次 + 小组` 维护最小轮次状态：

| 状态编码 | 状态名称 | 含义 |
|---|---|---|
| `WAITING` | 待选择 | 有资格但尚未轮到 |
| `CURRENT` | 当前选择 | 当前轮到该小组选单 |
| `SELECTED` | 已选择 | 已在本轮选择一个订单 |
| `PASSED` | 已放弃 | 玩家主动放弃本轮，后续有资格轮次仍可参加 |
| `ADMIN_SKIPPED` | 管理员跳过 | 管理员代为跳过本轮长时间未操作的小组 |
| `INELIGIBLE_BANKRUPT` | 破产失去资格 | 顺序生成后破产，当前或未来轮次自动失效 |

说明：

- 首版不做玩家端 WebSocket；年度订单页和管理员订单页通过 `3` 秒自动轮询同步标段状态。
- 玩家端年度订单页轮询为静默刷新，不进入整页加载态，不重置滚动位置，避免玩家查看订单池时页面跳回顶部。
- 玩家端不展示排序依据、其他小组完整顺序或未来轮次参与名单；管理员端纵向查看第一至第四轮完整明细。
- 每个标段只生成一次基础顺序，第二至第四轮只按资格过滤，不重新排序或随机。
- 玩家放弃前二次确认但不要求原因，只影响当前轮；管理员跳过继续强制填写原因，也只影响当前轮。
- 顺序生成后小组破产时，已选订单与已完成轮次保留，未完成轮次自动失效；若其为当前小组则自动推进，其他小组不重排。

### 8.4 订单选择与交付状态

建议对已选择订单维护最小状态：

| 状态编码 | 状态名称 | 含义 |
|---|---|---|
| `SELECTED` | 已选择 | 订单已被本组选中，尚未交付 |
| `DELIVERED` | 已交付 | 订单已在当前经营季度确认交付，并进入该季度当前有效销售收入汇总 |
| `UNFINISHED` | 未完成 | 年末仍未交付，状态保留但暂不阻断财报 |

说明：

- 处罚规则暂未确定，首版不因 `UNFINISHED` 自动计算罚款或阻断财报。
- 账期字段首版只展示，不参与经营页应收账款自动计算。
- 交付操作绑定当前经营季度；单个订单不能拆分到多个季度，一个季度可交付多个完整订单。
- 系统不再校验玩家手填销售收入是否匹配订单金额；订单交付成功后，按该季度当前有效已交付订单金额合计生成经营页销售收入。
- 回退或恢复快照后，目标阶段及后续阶段旧交付记录只作为历史留痕 / 草稿参考，对应订单恢复为待交付 / 可重新交付。
- 若后续确认处罚规则，应作为订单状态后的规则钩子接入，不改变现有年份主链。
- 标段全部有效轮次结束后仍未被选择的订单池记录标记为 `UNSELECTED_EXPIRED`，只用于审计，不进入交付、汇总或市场龙头计算。

### 8.5 经营页记录型字段状态

以下字段不进入年份主状态主链，但都需要字段级的“可编辑 / 已锁定 / 失效草稿”判断：

| 字段 | 当前定位 | 跨年规则 | 锁定规则 | 回退/快照规则 |
|---|---|---|---|---|
| 项目进度更新 | 当年留痕记录 | 不跨年承接 | 随对应经营阶段提交后锁定 | 回退到目标阶段后，目标阶段及后续记录恢复可编辑；旧值保留为失效草稿 |
| 新市场培育 | 市场级年度记录 | 有效累计跨年继承 | 当有效累计达到门槛后锁定 | 回退/快照只看当前有效累计，不看失效草稿 |
| 资质认证 | 资质状态记录 | 已解锁状态跨年继承 | 一旦有效状态为解锁即锁定 | 回退/快照只看当前有效状态，不看失效草稿 |

说明：

- 这三类字段都不改变 `LOCKED / OPERATING / REPORT_PENDING / REPORTING / COMPLETED` 的年份主状态。
- 它们只影响当前页可编辑性、锁定态显示和跨年承接结果。
- 其中“新市场培育”和“资质认证”会在后续年份继续展示历史有效状态，但不应因为失效草稿而误判当前锁定状态。

## 9. 异常解锁动作

`异常解锁` 是管理员动作，不是常规状态。

产品入口上，异常解锁并入管理员端 `回退与修正` 页面，作为 `退回重提` 模式；新增的 `恢复快照` 模式见第 10 节。

### 9.1 触发条件

- 仅管理员可执行
- 仅针对 `某组 + 某年`
- 仅允许在 `下一年尚未开放前` 执行
- 必须明确本次解锁目标：`OPERATING` / `REPORT`
- 当目标为 `OPERATING` 时，必须明确目标阶段：`Q1 / Q2 / Q3 / Q4 / YEAR_END`
- 仅允许对“已正式提交”的目标阶段或财报结果执行异常解锁
- 退回重提不要求管理员填写原因；系统自动记录默认原因 `管理员退回重提`

### 9.2 经营页异常解锁

| 维度 | 解锁结果 |
|---|---|
| 目标前已生效阶段 | 保持有效且只读 |
| 目标阶段 | 回到可编辑态 |
| 目标后经营阶段 | 结果失效，但保留原值为 `失效草稿` |
| 财报 | 结果失效，手工值保留为 `失效草稿`，并重新锁定，等待重新到达财报阶段 |
| 汇总 | 若该年已计入，则临时撤回 |
| 破产 | 不允许通过异常解锁撤销；已破产小组拒绝解锁 |
| 日志 | 必须记录目标类型、目标阶段、系统默认原因或退回说明、操作人、时间 |

第 9 步订单数量留痕随季度 scope 参与回退：退回到 `Qn` 后，`Qn` 及后续季度的记录随经营草稿恢复可编辑，`Qn` 之前的记录保持有效且只读；补提生成新提交版本与自动快照，原提交及回退前安全快照保留。该记录不支持脱离阶段状态机的字段级直接修改。

### 9.3 财报页异常解锁

| 维度 | 解锁结果 |
|---|---|
| 经营页已生效阶段 | 保持不变 |
| 财报 | 结果失效，财报页恢复可编辑，手工值保留为 `失效草稿` |
| 汇总 | 若该年已计入，则临时撤回 |
| 破产 | 不允许通过异常解锁撤销；已破产小组拒绝解锁 |
| 日志 | 必须记录目标类型、系统默认原因或退回说明、操作人、时间 |

### 9.4 失效草稿规则

- `失效草稿` 不是正式结果。
- `失效草稿` 不计入经营结果、财报结果、汇总结果与下一年正式结转。
- 重新提交成功后，当前提交结果覆盖生效，草稿状态解除。
- 首版保留操作日志与提交日志，不做完整历史版本库。

### 9.5 解锁后的重新提交流程

1. 管理员执行异常解锁。
2. 玩家按目标页或目标阶段重新进入提交流程。
3. 若为经营页异常解锁，则必须从目标阶段开始，依次重提后续阶段、年末与财报。
4. 若为财报页异常解锁，则只需重新提交财报。
5. 重提完成后，汇总与正式状态重新生效。

### 9.6 与快照回退的关系

- `异常解锁 / 退回重提` 不依赖历史快照，只按目标阶段恢复可编辑状态，并保留后续数据为失效草稿。
- `恢复快照` 依赖历史快照，以快照载荷作为草稿来源，适合某组从后续年份回到早期阶段重新推进。
- 两者都不清空玩家已填写数据，恢复后的数据均为待重提 / 失效草稿，都要求重新提交后才重新生效；快照中的旧经营结果、旧订单交付和旧销售收入不直接恢复为当前有效结果。

### 9.7 首版明确不做

- 不做字段级回退
- 不做系统自动全局恢复
- 不做字段级回滚
- 不做整年直接回到 `Q1_OPEN`

## 10. 单组快照回退

`单组快照回退` 是管理员动作，不是普通主状态。它会让目标小组进入 `回退补提中` 叠加态，直到该组重新提交完成目标节点之后的必要阶段。

### 10.1 快照类型

| 快照类型 | 含义 | 首版用途 |
|---|---|---|
| `GROUP` | 单组快照 | 恢复某个小组到历史阶段 |
| `GLOBAL` | 全局快照 | 记录订单池确认、标段完成、开放下一年等全局节点，首版用于审计和后续全局恢复扩展 |
| `SAFETY` | 回退前安全快照 | 每次回退前自动生成，防止误操作后无法追溯 |

### 10.2 快照生成节点

- 单组经营阶段提交成功后生成单组快照。
- 单组财报提交成功后生成单组快照。
- 管理员执行退回重提或恢复快照前生成单组安全快照。
- 管理员确认订单池后生成全局快照。
- 每个标段完成后生成全局快照。
- 管理员开放下一年后生成全局快照。
- 管理员可手动创建单组快照或全局快照。

快照在本场比赛内不自动清理。

### 10.3 单组恢复规则

| 维度 | 规则 |
|---|---|
| 回退粒度 | 按 `Q1 / Q2 / Q3 / Q4 / YEAR_END / REPORT` 等阶段级节点，不做字段级回退 |
| 跨年 | 允许某组从后续年份回退到早期年份 |
| 数据处理 | 目标节点之后的数据保留为 `失效草稿`，不清空 |
| 全局年份 | 不回退全局当前开放年份 |
| 玩家操作 | 被回退组从目标阶段开始重新提交，旧页面提交应被拒绝并提示刷新 |
| 写锁 | 回退执行期间短暂锁定目标组写操作 |
| 连续回退 | 允许；退回重提由系统自动记录默认原因，恢复快照仍需填写原因；每次都必须生成回退前安全快照 |
| 草稿来源 | 退回重提以当前库中目标阶段数据为草稿基础；恢复快照以历史快照载荷为草稿基础；两者都不直接生成有效结果 |

### 10.4 订单边界

- 单组快照回退不回滚订单竞标结果。
- 已选订单保留归属，不释放给其他小组。
- 不重算市场龙头。
- 不重排历史选单顺序。
- 不重新生成已确认订单池。
- 目标阶段及后续阶段的旧订单交付记录保留为历史留痕 / 草稿参考，但不作为当前有效交付；对应订单恢复为待交付 / 可重新交付。
- 玩家重新经营到对应季度后，可以重新交付原订单，也可以改交其他仍归属本组的已选订单；经营页销售收入只按重新确认后的当前有效交付记录生成。
- 后续年份已选订单标记为失效但不释放；该组重新走到对应年份时继续作为订单来源。
- 如果目标小组尚未参与某个已生成顺序的标段，系统不强制所有小组等待；管理员负责现场节奏控制，系统只做提示。

### 10.5 奖惩、汇总与破产

- 普通通知不回退。
- 奖惩是独立于玩家提交的管理员业务事件；普通退回重提时，全部有效奖惩继续保留，并在对应阶段重新进入计算。
- 恢复快照时，奖惩有效状态按目标快照时点恢复；奖惩原始记录和审计信息始终保留。
- 单条奖惩纠错只能在管理员“通知与奖惩”页面执行作废，不依赖回退隐式失效。
- 目标节点之后的正式汇总撤回，汇总页显示 `待重提`，不计入当前排名。
- 已确认破产不可通过退回重提或恢复快照撤销；已破产小组禁止继续下发或作废奖惩，系统不提供解除破产状态。

### 10.5.1 奖惩动作状态矩阵

| 小组当前状态 | 下发奖惩 | 作废奖惩 | 系统归属 |
|---|---|---|---|
| `Q1_OPEN / Q2_OPEN / Q3_OPEN / Q4_OPEN` | 允许 | 允许 | 当前季度 |
| `YEAR_END_OPEN` | 允许 | 允许 | `YEAR_END` |
| 财报填写中 / 草稿未正式提交 | 允许 | 允许 | `YEAR_END` |
| 财报正式提交 / 年份完成 | 禁止，必须先退回 | 禁止，必须先退回 | - |
| `BANKRUPT` | 永久禁止 | 永久禁止 | - |

奖惩下发或作废后必须立即按最新有效事件重新计算；若所得税后现金小于 `0`，立即生成破产快照并进入不可撤销的 `BANKRUPT` 状态。

### 10.6 开放下一年阻断

只要存在任意未破产小组处于 `回退补提中 / 待重提`，管理员不能开放下一年。

## 11. 汇总生效规则

| 条件 | 是否计入汇总 |
|---|---|
| `0年` 已完成 | 否 |
| `1年~最终年` 经营未完成 | 否 |
| `1年~最终年` 财报未提交 | 否 |
| `1年~最终年` 状态为 `COMPLETED` | 是 |
| 某年被异常解锁后未重提财报 | 否 |
| 某组快照回退后目标节点之后结果未重提 | 否 |
| 某组已破产但历史某年已完成 | 已完成的历史正式年份仍保留在汇总中 |

补充说明：

- 首版不展示实时排名。
- 最终排名以最终年份 `所有者权益` 为准。
- 排名展示发生在管理员汇总页的最终结果口径上。

## 12. 关键禁用规则

以下操作在首版中应被明确禁止：

| 禁止操作 | 原因 |
|---|---|
| 玩家自行开放下一年 | 年度推进由管理员统一控制 |
| `0年` 发起订单竞标 | `0年` 是引导年，不需要线上订单 |
| 正式年份未完成订单前置即提交 Q1 | 会破坏订单来源、市场投入、标段释放顺序和经营页订单总额的一致性 |
| 未开启市场提交非零市场投入 | 未开启市场不参与订单生成和抢单，玩家端禁用输入并由系统自动按 `0` 提交 |
| 当前标段投入为 `0` 的小组参与选单，包括市场龙头 | 与标段投入决定参与资格的规则冲突 |
| 一个小组在同一标段同一轮选择多个订单 | 当前规则为每组每轮最多一单 |
| 管理员跳过预设释放顺序直接释放后续标段 | 会破坏开标前已配置的标段顺序 |
| 当前标段处于选单中或下一轮待开启时释放下一标段 | 当前规则要求先完成当前标段全部有效轮次 |
| 第一轮结束后系统自动开启下一有效轮次 | 第二至第四轮由管理员点击“开启下一轮” |
| 强制选完或自动补足某标段订单池 | 当前规则允许订单池提前选空，也允许有效轮次完成后仍有未选订单 |
| 玩家撤销已选订单 | 首版规则不支持撤销 |
| 管理员代玩家选择订单 | 首版只支持管理员代跳过，不支持代选 |
| 玩家绕过阶段提交流程强行推进后续阶段 | 会破坏阶段锁定和年份状态一致性 |
| 财报未完成即计入汇总 | 会破坏汇总口径 |
| 下一年已开放后再解锁上一年 | 会破坏跨年一致性 |
| 存在回退补提小组时开放下一年 | 会导致落后小组无法按规则追平 |
| 破产组继续经营后续年份 | 与破产淘汰规则冲突 |

## 13. 对技术设计的最小要求

基于本状态机，后续系统设计至少需要支持：

- `组 + 年` 维度的年份主状态
- `组 + 年` 维度的经营阶段子状态
- `组 + 年` 维度的财报子状态
- `年份 + 市场 + 订单类型` 维度的订单池生成状态与标段释放状态
- `年份 + 市场` 维度的市场开启状态
- `组 + 年 + 市场` 维度的市场投入、选单资格和订单前置完成状态
- `年份 + 市场 + 订单类型` 维度的选单顺序、释放顺序与随机结果记录
- `组 + 年 + 市场 + 订单类型 + 订单` 维度的订单选择与交付状态
- `组` 维度的破产标记
- 异常解锁日志
- 状态快照与回退日志
- 提交日志
- 汇总生效/失效判断
