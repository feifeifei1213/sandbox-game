## 2. 产品定位与首版范围

### 2.1 产品定位

- 本项目首版服务于公司活动场景，核心价值偏向：
  - 经营演练
  - 规则教学
  - 财务结果反馈
- 首版目标不是完整替代桌游流程，而是先把：
  - 玩家经营填写
  - 财报填写
  - 管理员汇总与控制
  这几部分电子化并走通。

### 2.2 首版范围

首版交付范围如下：

| 模块 | 是否纳入首版 | 说明 |
|---|---|---|
| 统一登录页 | 是 | 最小用户名密码登录闭环，按角色自动跳转 |
| 玩家端经营页 | 是 | 高保真 Excel 风格；支持季度/年末填写与提交 |
| 玩家端年度订单 | 是 | `1年` 起按市场进行订单竞标、市场投入提交与订单选择；`0年` 不需要线上订单 |
| 玩家端财报页 | 是 | 高保真 Excel 风格；支持自动计算 + 手工项填写 |
| 管理员汇总页 | 是 | 汇总正式年份收入/利润/权益与经营状态 |
| 管理员年度控制 | 是 | 管理最终年份、开放下一年 |
| 管理员订单管理 | 是 | 上传/解析订单推算 Excel、配置订单数量、生成订单池、开放市场竞标与查看状态 |
| 管理员通知与奖惩 | 是 | 发送普通通知，按组/年/季下发奖励与罚款 |
| 管理员初始基线 | 是 | 录入共享初始基线模板并提交锁定 |
| 管理员组数据查看 | 是 | 查看任一组任一年数据 |
| 异常解锁 | 是 | 定向异常修正机制 |
| 自动保存草稿 | 是 | 每 5 分钟自动保存一次草稿 |
| 排名大屏 / 复杂图表 | 否 | 首版不做 |
| 导出能力 | 否 | 首版不做 |
| 桌游流程完全电子化 | 否 | 首版不做 |
| 通用历史回退引擎 | 否 | 首版只做定向异常解锁，不做任意快照回退 |

### 2.3 首版方案判断

首版采用 `轻中型方案`：

- 页面层：高保真 Excel 风格
- 规则层：以 Excel 为主依据，但按业务规则实现
- 流程层：中等复杂度状态流转
- 存储层：业务字段存储 + 页面映射

## 3. 角色与权限需求

### 3.1 角色定义

| 角色 | 数量 | 核心职责 |
|---|---|---|
| 玩家组账号 | 赛前初始化配置 | 填写经营页、提交阶段、填写财报 |
| 管理员账号 | 1 | 赛前初始化、年度控制、查看汇总、初始化基线、异常解锁 |

### 3.2 权限边界

| 功能 | 玩家组 | 管理员 |
|---|---|---|
| 查看本组经营数据 | 是 | 是 |
| 查看其他组经营数据 | 否 | 是 |
| 查看汇总页 | 否 | 是 |
| 提交季度/年末 | 是 | 否 |
| 提交财报 | 是 | 否 |
| 查看本年订单池 | 是 | 是 |
| 提交各市场投入 | 是 | 否 |
| 按顺序选择订单 | 是 | 否 |
| 赛前初始化比赛 | 否 | 是 |
| 上传/解析订单 Excel | 否 | 是 |
| 配置订单数量并生成订单池 | 否 | 是 |
| 开放/关闭市场竞标 | 否 | 是 |
| 录入初始基线 | 否 | 是 |
| 开放下一年 | 否 | 是 |
| 异常解锁 | 否 | 是 |
| 查看通知 | 是 | 是 |
| 发送普通通知 | 否 | 是 |
| 下发奖励 / 罚款 | 否 | 是 |

### 3.3 数据隔离要求

- 玩家组之间数据严格隔离，不能查看彼此经营数据。
- 管理员可查看所有组数据。
- 汇总页仅管理员可见。
- 管理员可通过普通通知向全体玩家广播赛事事件信息，例如 `第一小组已破产`。
- 上述广播属于赛事信息公开，不等同于开放其他组的经营明细数据。
### 3.4 首版登录要求

- 系统提供统一登录页。
- 用户通过用户名和密码登录。
- 系统根据账号角色自动跳转，不要求用户手动选择角色。
- 玩家登录成功后默认进入 `0年经营`。
- 管理员登录成功后，若比赛尚未初始化，则默认进入“赛前配置页”；若比赛已初始化，则默认进入管理端首页，首版管理端首页默认落在 `汇总页`。
- 管理员默认入口的判断以后端当前已初始化的小组主数据为准，不依赖前端本地缓存或额外手工开关。
- 系统应提供退出登录能力，退出后返回统一登录页。
- 首版登录只做最小认证闭环，不扩展以下复杂账号能力：
  - 自助注册
  - 找回密码
  - 修改密码
  - 多角色切换
  - 细粒度账号管理后台

## 4. 核心业务对象

| 对象 | 说明 |
|---|---|
| 组 | 一个参赛小组，对应一个系统操作账号 |
| 年 | 包括 `初始基线`、`0年`、`1年~最终年` |
| 阶段 | `Q1/Q2/Q3/Q4/年末` |
| 财报 | 本年经营结束后开放的年度财报页面 |
| 汇总 | 管理员侧汇总的正式年度结果 |
| 通知 | 管理员发送给全体或单个小组的消息，不参与经营计算 |
| 奖惩 | 管理员按 `组 + 年 + 季` 下发的奖励或罚款，参与经营计算 |
| 订单生成控制 | 管理员按 `年份 + 市场 + 订单类型` 控制订单数量，并据此生成订单池 |
| 订单池 | 某年某市场可供玩家选择的订单集合，订单被选后锁定，不再对其他组可选 |
| 市场竞标 | 玩家按市场提交市场投入，系统据此生成该市场选单顺序 |
| 市场龙头 | 从 `2年` 起，每个市场以上一年该市场已选订单金额最高的小组作为优先选单方；若并列则随机确定 |
| 订单选择 | 玩家在轮到本组时从当前市场可选订单中选择 `1` 个订单 |
| 订单交付状态 | 已选订单的交付跟踪状态，首版先记录状态，处罚规则暂不自动计算 |
| 经营状态 | 正常 / 已破产 |
| 年份状态 | 参见 `docs/minimal_state_machine.md` |

## 5. 年度与比赛口径需求

### 5.1 年份定义

| 年份 | 口径 | 是否参与汇总排名 |
|---|---|---|
| 初始基线 | 管理员录入的基线年 | 否 |
| 0年 | 引导年 / 非排名年 | 否 |
| 1年 ~ 最终年 | 正式比赛年 | 是 |

### 5.2 初始基线

- 由管理员以共享模板单页录入或确认。
- 提交成功后按组应用到全部小组。
- 提交后锁定，不可修改。
- 用于后续年度衔接基线。

### 5.3 0年

- 流程上与正式年份一致。
- 支持填写、提交、财报。
- 参与到 `1年` 的数据传递。
- 不进入正式汇总和最终排名。
- 不需要线上订单，也不进入订单竞标流程。
- `0年` 经营相当于管理员带领玩家熟悉规则的年份；`0年财报` 作为进入 `1年` 的初始/承接基线。

### 5.4 正式胜负规则

- 正式汇总年份从 `1年` 开始。
- 最终年份 `所有者权益` 最高的公司获胜。
- 首版不展示过程中的实时排名。
- 最终年份完成后，管理员汇总页可展示最终排名。
- 线上订单从 `1年` 开始参与正式经营流程。
- `1年` 的订单选择顺序按各市场当年市场投入从高到低确定；市场投入相同的小组用随机方式确定先后。
- `2年` 起，每个市场先判断上一年该市场市场龙头；市场龙头优先，其余小组再按当年该市场市场投入排序。

### 5.5 最终年份与动态扩年规则

- 系统不为 `0年 / 1年 / 2年 / ...` 分别生成独立页面文件。
- 玩家经营页与玩家财报页各自只维护 `1` 套正式页面结构，通过 `yearNo` 切换年份数据视图。
- 管理员设置 `最终年份` 后，系统应以该值作为玩家端和管理员端“年份标签上限”。
- 当管理员把 `最终年份` 从较小值上调到更大值时，系统必须自动补齐全部小组缺失的未来年份运行状态记录，确保后续年份可被正常打开。
- 自动补齐出的未来年份默认口径如下：
  - 年份类型：`FORMAL`
  - 年份主状态：`LOCKED`
  - 经营阶段状态：`Q1_OPEN`
  - 财报状态：`REPORT_LOCKED`
  - 不计入正式汇总
  - 经营提交版本号、财报提交版本号初始为 `0`
- 当管理员把 `最终年份` 下调到较小值时，只要不小于 `当前开放年份` 即允许修改。
- 下调 `最终年份` 时，系统不物理删除已经存在的未来年份数据；页面与接口仅按新的 `最终年份` 作为可见上限。
- 修改 `最终年份` 不应自动改变 `当前开放年份`。
- 年份空间的扩展与收口属于管理员控制能力的一部分，不属于玩家端流程动作。

## 6. 玩家端需求

### 6.1 页面总体要求

- 玩家端经营页采用高保真 Excel 风格整页布局。
- 玩家端新增独立 `年度订单` 页面，用于正式年份订单竞标、市场投入提交、按顺序选择订单与查看本组订单状态。
- 玩家端财报页采用高保真 Excel 风格整页布局。
- 首页默认进入 `0年经营`。
- 年份标签全部可见。
- 未开放年份不可进入或不可编辑。
- 页面允许存在轻量右侧工作栏，但主表必须始终是视觉主体。
- 玩家经营页与财报页的右侧工作栏顶部都必须保留 `通知区`，优先展示管理员最新通知。

### 6.1.1 年度订单页

- `年度订单` 是独立玩家页面，不嵌入经营页主表。
- `0年` 不显示订单竞标入口或显示为无需订单的只读说明。
- `1年 ~ 最终年` 进入经营页 `Q1` 提交前，必须先完成本年订单选择流程。
- 玩家可在年度订单页查看当前年各市场订单池，按市场和订单类型筛选。
- 订单市场固定为：
  - 本地市场
  - 区域市场
  - 全国市场
  - 全球市场
- 每个市场的订单类型固定为：
  - 代办过检
  - 两舱贵宾
  - 商务贵宾
  - 会员定制
- 玩家在各市场分别提交市场投入；提交后不允许修改。
- 当管理员关闭市场投入并生成选单顺序后，玩家按本组顺序在对应市场选择订单。
- 每个市场只进行 `1` 轮选择：每个有该市场投入的小组最多选择 `1` 个订单；所有参与小组轮完后，该市场抢单结束。
- 未被选择的订单保留为未选状态，不要求必须被全部选完。
- 某市场没有任何小组投入时，直接跳过该市场抢单阶段。
- 玩家未在某市场投入时，不参与该市场排序和选单。
- 玩家只能看到订单池中仍可选择的订单，以及本组已选择订单；不显示其他组已选择的订单明细。
- 玩家选择订单后不能撤销；首版也不提供管理员撤销订单选择能力。
- 本组已选订单在经营页中作为订单来源，经营页不再让玩家自由决定正式年份订单总额。
- 已选订单交付季度由玩家在经营页自行安排，但不允许把同一订单拆分到多个季度交付。
- 当某季度销售收入等于某个已选订单金额时，系统可将该订单标记为已交付。
- 若年末仍未完成交付，订单标记为 `UNFINISHED`，但首版允许继续提交财报。
- 未完成交付的处罚规则暂不确定；首版只保留状态与后续规则接入口。

### 6.2 经营页填写与提交

#### 6.2.1 阶段结构

- 不做单独“年初提交”。
- `Q1 提交` 时一并处理 `年初区 + Q1 区`。
- `Q2/Q3/Q4` 各自单独提交。
- `年末区` 单独提交。

#### 6.2.2 阶段显示与锁定

| 当前所处阶段 | 年初区 | Q1 | Q2 | Q3 | Q4 | 年末 |
|---|---|---|---|---|---|---|
| Q1 | 可编辑 | 可编辑 | 只读锁定 | 只读锁定 | 只读锁定 | 只读锁定 |
| Q2 | 只读 | 只读 | 可编辑 | 只读锁定 | 只读锁定 | 只读锁定 |
| Q3 | 只读 | 只读 | 只读 | 可编辑 | 只读锁定 | 只读锁定 |
| Q4 | 只读 | 只读 | 只读 | 只读 | 可编辑 | 只读锁定 |
| 年末 | 只读 | 只读 | 只读 | 只读 | 只读 | 可编辑 |

#### 6.2.3 手工项与默认值

- 所有手工填写项默认空值。
- `0` 必须由用户显式填写。
- 首版只做：
  - 顶部错误提示
  - 未填项高亮
- 不做重型校验清单面板。

#### 6.2.4 通知与奖惩展示

- 玩家经营页右侧工作栏顶部必须显示通知区。
- 通知区首版最小结构为：
  - `1` 条置顶通知
  - 最近通知列表
- 普通通知可用于流程提醒、赛事播报、主持人口径说明等，不参与经营计算。
- 经营页中的 `额外支出 / 罚款` 与 `额外收入 / 奖励` 保留 Excel 原位置，但改为只读展示。
- `额外支出 / 罚款` 与 `额外收入 / 奖励` 的数值由管理员下发后自动带入对应季度，不再由玩家手工填写。
- `折现费用` 继续由玩家填写。
### 6.3 财报页需求

#### 6.3.1 开放条件

- 本年经营全部完成后，财报页才开放。
- 年末提交成功后，应立即开放本年财报页。

#### 6.3.2 财报展示与填写边界

- 财报页自动带出 Excel 可计算结果。
- 首版以当前 Excel 中绿色单元格定义手工输入边界。
- 当前已确认手工项包括：
  - 在制品
  - 成品
  - 材料
  - 所得税税率
- 财报页右侧工作栏顶部也应显示通知区，保持与经营页一致的通知入口。

#### 6.3.3 税率输入规则

- 所得税税率采用下拉框。
- 允许值仅为：
  - `0.25`
  - `0.15`
  - `0`

#### 6.3.4 财报提交条件

- 财报手工项已完成。
- 必须通过平衡校验：`总资产 = 总负债 + 总权益`。
- 财报提交成功后，本年度完成。

### 6.4 自动保存与正式提交

- 首版自动保存采用轻量方案：每 `5` 分钟自动保存一次草稿。
- 季度提交 / 年末提交 / 财报提交，才是正式提交动作。
- 首版不做复杂自动保存失败交互设计。
- 自动保存的目标是减少误操作损失，不等于协同编辑级可靠性保障。

### 6.5 右侧工作栏需求

| 页面 | 工作栏内容 |
|---|---|
| 经营页 | 通知区、阶段状态、季末现金展示说明、贷款提醒 |
| 财报页 | 通知区、平衡校验、税率说明、财报提交 |

## 7. 管理员端需求

### 7.1 菜单范围

首版管理员端仅包括：

- 汇总
- 年度控制
- 订单管理
- 通知与奖惩
- 初始基线
- 组数据

### 7.2 汇总页

#### 7.2.1 汇总口径

- 汇总页正式口径来自各组各年“已提交财报”的结果。
- 汇总从 `1年` 开始显示，不显示 `0年`。
- 当前核心指标为：
  - 收入
  - 利润
  - 权益

#### 7.2.2 展示要求

- 页面上方展示“年度汇总区”，展示各组正式年份结果。
- 增加 `经营状态` 列。
- 已破产组显示红色 `已破产` 标签。
- 页面下方展示“最终排名区”。
- 仅在最终年份满足开放条件后显示有效排名；未满足条件时显示状态提示。

### 7.3 年度控制

- `最终年份` 为配置项，由管理员设定。
- `当前开放年份` 为运行时状态，由管理员控制。
- 管理员可手动开放下一年。
- 玩家不可自行开放下一年。
- 当管理员上调 `最终年份` 时，系统应自动补齐新增正式年份的初始状态空间。
- 年份标签数量应以当前 `最终年份` 为准动态变化，而不是前端写死。

### 7.4 初始基线

- 管理员在单页共享模板中录入初始基线。
- 提交后按组应用到全部小组。
- 提交后锁定。
- 提交后不可修改。

### 7.4.1 管理员赛前初始化比赛

- 管理员端提供“赛前配置页”或等价初始化入口，用于在比赛开始前配置本场比赛的小组数量。
- 管理员在赛前配置页确认小组数量后，系统初始化本场比赛的小组主数据、账号数据与各年份初始状态数据。
- 比赛未初始化前，管理员登录后默认进入赛前配置页。
- 小组数量配置仅在比赛开始前生效；初始化完成后，系统以后端已初始化的小组主数据作为唯一运行依据。
- 首版建议直接以后端 `sg_group` 的实际记录数推断 `initialized` 与 `groupCount`，不再额外维护一套运行期“配置真相”。
- 比赛开始后，不支持动态增减小组数量。
- 初始化流程应以单事务完成，一次性创建小组主数据、账号数据与各年份状态；任一步失败都必须整体回滚，不得留下半成品。
- 初始化成功后，管理员账号继续保留 `admin`，玩家账号按 `group01 ~ groupNN` 规则自动生成。
- 初始化完成后，系统默认进入“`0年` 已开放、`1年 ~ 最终年` 已预置但锁定待开放”的初始状态。
- 初始化接口在比赛已初始化后不得重复执行；如需调整小组数量，应重新初始化新的比赛环境或新的比赛库。
- 管理员提交初始基线时，系统按当前已初始化的小组集合进行扇出应用。
- 汇总页、最终排名区、组数据页、通知与奖惩目标范围，均按实际初始化的小组数据动态展示。
- 玩家侧仅在比赛完成初始化后进入正常参赛流程。

### 7.5 组数据查看

- 管理员可查看任意组、任意年、任意页面的数据。
- 首版不要求做复杂进度总控面板。
- 现场进度主要通过主持人口头控制。

### 7.5.1 订单管理

- 管理员端新增 `订单管理` 页面或等价菜单入口。
- 订单生成依据为 `道具-订单推算（服务企业）.xlsx`。
- 当前 Excel 作为订单生成/推算工具，不作为系统运行时实时公式引擎。
- 管理员可上传订单推算 Excel，系统解析后展示预览和错误列表。
- 管理员确认后，系统按当前解析结果和数量控制生成订单池。
- 首版管理员可配置的订单生成参数先限定为：`年份 + 市场 + 订单类型` 的订单数量。
- 订单均价、波动系数、最小/最大订单数量等复杂参数首版暂不做页面配置，后续如需要再扩展。
- 管理员只能更新尚未开放竞标、尚未生成选单顺序、尚未发生玩家选择的年份/市场订单池。
- 若某年份/市场已经开放竞标、已经进入选单或已经有玩家选单，则不允许覆盖更新订单池。
- 当管理员选择覆盖未来年份订单池时，应以新上传或新配置结果整体覆盖该年份/市场未开始部分的订单池。
- 管理员可按市场开放/关闭市场投入。
- 管理员关闭某市场投入后，系统生成该市场选单顺序。
- 管理员可查看各市场的市场投入、选单顺序、市场龙头、订单选择进度和未交付订单状态。
- 首版不做复杂订单撤销、订单交易、导出与实时大屏。

### 7.6 异常解锁

#### 7.6.1 触发条件

- 仅管理员可执行。
- 仅针对 `某组 + 某年`。
- 仅允许在 `下一年尚未开放前` 执行。
- 管理员必须显式选择本次解锁目标：
  - `OPERATING`：经营页异常解锁
  - `REPORT`：财报页异常解锁
- 当目标为 `OPERATING` 时，管理员还必须选择回退阶段：
  - `Q1`
  - `Q2`
  - `Q3`
  - `Q4`
  - `YEAR_END`
- 仅允许回退到“已正式提交”的目标阶段或财报结果。
- 管理员必须填写解锁原因。
- 系统必须保留异常解锁审计记录。

#### 7.6.2 输入项

| 输入项 | 是否必填 | 说明 |
|---|---|---|
| `groupId` | 是 | 目标组 |
| `yearNo` | 是 | 目标年份 |
| `unlockTargetType` | 是 | `OPERATING` / `REPORT` |
| `targetStageCode` | 条件必填 | 当 `unlockTargetType = OPERATING` 时必填 |
| `reason` | 是 | 管理员填写的异常解锁原因 |

#### 7.6.3 经营页异常解锁

- 管理员选择 `OPERATING + 目标阶段` 后，系统按该阶段执行定向回退。
- 早于目标阶段的已生效经营结果继续有效，并保持只读。
- 目标阶段恢复为可编辑状态。
- 晚于目标阶段的经营阶段结果全部失效，但页面中的原值不清空，保留为 `失效草稿`。
- 本年财报结果同步失效；财报手工项原值不清空，保留为 `失效草稿`。
- `失效草稿` 具有以下约束：
  - 不计入当前有效经营结果
  - 不计入当前有效财报结果
  - 不计入管理员汇总
  - 不计入下一年的正式结转
  - 只有在玩家重新走到对应阶段并重新提交后，才重新生效
- 若该年破产结论由被失效的后续结果触发，异常解锁后应临时恢复为 `NORMAL`，待重新提交后再重新判定。

#### 7.6.4 财报页异常解锁

- 管理员选择 `REPORT` 时，不回退经营页的已生效阶段。
- 财报结果失效，财报页恢复可编辑。
- 财报手工项原值不清空，保留为 `失效草稿`，玩家可在此基础上修改后重新提交。
- 该年汇总结果同步失效。
- 若该年破产结论由财报结果触发，异常解锁后应临时恢复为 `NORMAL`，待财报重新提交后再重新判定。

#### 7.6.5 解锁后的重新提交流程

1. 管理员在组数据页发起异常解锁。
2. 玩家看到目标页或目标阶段重新开放。
3. 若为经营页异常解锁，玩家必须从目标阶段开始，依次重新提交：
   - 目标阶段
   - 后续经营阶段
   - 年末
   - 财报
4. 若为财报页异常解锁，玩家只需重新提交财报。
5. 只有在重新提交完成后，该年才重新计入正式汇总。

#### 7.6.6 后端实现规则清单

- 接口请求体必须正式承载 `unlockTargetType` 与 `targetStageCode`，不得继续使用只有 `groupId + yearNo + reason` 的年份级通用解锁口径。
- 服务端状态机必须区分 `有效结果` 与 `失效草稿`，不能用“清空后续值”代替本需求。
- 当目标为 `OPERATING` 时，必须按 `Q1 / Q2 / Q3 / Q4 / YEAR_END` 做阶段级回退，而不是只恢复“当前最新阶段可编辑”。
- 经营页回退后，后续经营阶段与财报必须同时失效；但原值保留，可作为重新开放时的草稿回填来源。
- 汇总、破产状态、下一年结转口径都必须只读取 `有效结果`，不能读取 `失效草稿`。
- 异常解锁日志必须至少记录：目标组、目标年份、解锁目标类型、目标阶段、原因、操作人、操作时间、解锁前后状态摘要。
- 服务端错误提示必须目标化，例如：
  - `经营页当前无需解锁`
  - `财报页当前无需解锁`
  - `目标阶段尚未正式提交，不能解锁`
  - `下一年已开放，不能再解锁本年`
- 必须补齐单元测试 / 集成测试，覆盖经营页回退、财报页解锁、失效草稿保留、汇总失效、破产恢复等关键场景。

#### 7.6.7 前端页面与交互改造清单

- 管理员 `组数据页` 的异常解锁弹窗必须新增：
  - 解锁目标类型选择
  - 当目标为 `OPERATING` 时显示经营阶段选择
  - 影响说明区
  - 解锁原因输入区
  - 二次确认
- 管理端错误提示必须与目标类型一致，不再使用笼统的“当前年份已处于可编辑状态”覆盖所有场景。
- 玩家经营页在经营页异常解锁后必须同时表达 3 类状态：
  - 已生效且只读的历史阶段
  - 当前重新开放可编辑的目标阶段
  - 保留原值但已失效、需重新提交的后续阶段
- 玩家财报页在经营页异常解锁后应恢复为未生效状态；此前手工值保留为草稿，待重新到达财报阶段时自动回填。
- 玩家财报页在财报页异常解锁后应直接打开为可编辑状态，并回填此前保留的手工草稿。
- 前端展示应尽量保持 Excel 高保真布局，不在主表中央增加大段说明；状态提示应优先放在阶段标题、页签状态、右侧工作栏或提交区。

## 8. 核心业务规则

### 8.1 提交校验规则

| 提交动作 | 校验范围 |
|---|---|
| Q1 提交 | `年初 + Q1`；正式年份还需本年订单选择流程已完成 |
| Q2 提交 | `Q2` |
| Q3 提交 | `Q3` |
| Q4 提交 | `Q4` |
| 年末提交 | `年末区手工项` |

补充规则：

- 已提交且已锁定的历史阶段，不重复做必填完整性校验。
- 每次经营阶段提交后，系统返回当期计算的期末现金，供玩家线下自行核对。

### 8.1.1 线上订单与市场竞标规则

#### 8.1.1.1 适用范围

- 线上订单只适用于 `1年 ~ 最终年`。
- `0年` 不需要订单，不参与市场投入排序和订单选择。
- 订单竞标按市场独立执行，不做全年统一订单池。
- 四个市场固定为：本地市场、区域市场、全国市场、全球市场。
- 每个市场下固定四类订单：代办过检、两舱贵宾、商务贵宾、会员定制。

#### 8.1.1.2 订单池生成

- 管理员通过订单管理维护订单池。
- 首版优先支持控制订单数量：按 `年份 + 市场 + 订单类型` 配置数量。
- 管理员上传 Excel 后，系统读取当前保存值并生成固定订单池；不得在运行时持续依赖 Excel 随机公式。
- 订单卡片首版字段至少包括：年份、市场、订单类型、订单金额、数量、单价、账期。
- 当前订单推算 Excel 未稳定提供直接成本和交付季度，因此首版不从订单推算文件生成直接成本或交付季度。
- 直接成本继续由玩家在经营页填写。
- 交付季度由玩家在经营页自行安排。

#### 8.1.1.3 市场投入与参与资格

- 玩家按市场分别提交市场投入。
- 市场投入提交后不允许修改。
- 某组在某市场没有投入，则不参与该市场选单。
- 某市场没有任何小组投入时，管理员可直接跳过该市场订单选择阶段。
- 各市场投入合计进入经营页年初区的 `市场投入`。

#### 8.1.1.4 选单排序

- `1年`：按该市场当年市场投入从高到低排序。
- `1年` 市场投入相同：通过随机方式确定先后，并记录随机结果。
- `2年` 起：该市场上一年市场龙头优先选择，其余参与小组再按该市场当年市场投入从高到低排序。
- `2年` 起若市场龙头没有当年该市场投入，则不参与该市场选单，也不享受优先权。
- 若上一年该市场没有任何已选订单，则本年不产生市场龙头优先权，直接按当年市场投入排序。
- 市场龙头定义为：上一年该市场已选订单金额最高的小组。
- 若上一年该市场已选订单金额并列最高，则随机确定其中一个为市场龙头，并记录随机结果。

#### 8.1.1.5 选单轮次

- 每个市场只进行 `1` 轮选择。
- 每个参与小组在该市场最多选择 `1` 个订单。
- 按排序依次选择；某个订单被选后立即锁定，不再对后续小组可选。
- 所有参与小组轮完后，该市场抢单结束。
- 市场订单池未被选完时，不继续追加轮次；剩余订单保持未选状态。
- 玩家选择订单后不可撤销；首版管理员也不提供撤销选单能力。

#### 8.1.1.6 与经营页联动

- 正式年份本组订单选择流程未完成时，不允许提交 `Q1`。
- 本组在四个市场已选订单金额合计进入经营页 `订单总额`。
- 经营页只消费订单模块提供的订单来源，不替代订单模块的选单流程。
- 订单不允许分季度拆分交付。
- 某季度销售收入等于某个已选订单金额时，可标记该订单已交付。
- 年末未交付订单标记为 `UNFINISHED`，但暂不阻断财报提交。
- 未交付处罚规则暂定；首版只保存订单交付状态，预留后续处罚计算接入口。

### 8.2 季末现金展示规则

- 经营页主表保留“核对季末现金”展示行。
- 系统按当前经营数据计算 `Q1/Q2/Q3/Q4` 的季度期末现金。
- 玩家自行对照线下沙盘现金进行核对。
- 系统不采集现场现金，也不因现金差异阻断提交。

### 8.3 贷款提醒

- 每个季度提交后，系统提醒玩家关注贷款更新。
- 该提醒仅为提醒，不做强制拦截。
- 不区分当前是否存在贷款，都统一提醒。

### 8.4 通知与奖惩

#### 8.4.1 普通通知

- 管理员可发送普通通知。
- 普通通知支持：
  - 发送给全体小组
  - 发送给单个小组
- 普通通知允许自由文本，不限制为固定模板。
- 普通通知可用于：
  - 提醒准备开启下一年
  - 催促提交经营或财报
  - 广播赛事事件，例如 `第一小组已破产`
- 普通通知只负责展示，不参与经营计算、财报计算和汇总计算。

#### 8.4.2 奖惩通知

- 奖励与罚款改为管理员下发，不再由玩家手工填写。
- 奖惩必须绑定到：
  - 目标小组
  - 年份
  - 季度
- 奖惩最小字段包括：
  - 类型：`奖励 / 罚款`
  - 金额
  - 原因说明
  - 下发人
  - 下发时间
- 奖惩属于计算型业务事件，必须参与：
  - 经营页当期计算
  - 财报结果承接
  - 管理员汇总口径
- 若同一组同一季度存在多条奖励或罚款，系统应按类型分别合计后展示到经营页对应单元格。

#### 8.4.3 玩家页展示与编辑边界

- 经营页中 `额外支出 / 罚款`、`额外收入 / 奖励` 保留现有 Excel 布局位置。
- 上述两类单元格改为玩家只读。
- 玩家在右侧通知区查看具体奖惩原因，不要求把长说明塞入 Excel 主表。
- `折现费用` 仍由玩家填写，不转移给管理员。

#### 8.4.4 奖惩与阶段锁定关系

- 若目标季度当前仍未正式提交，管理员可直接下发奖惩并立即生效。
- 若目标季度已经正式提交并锁定，管理员不得直接修改该季度已生效奖惩结果。
- 对已锁定季度补发或更正奖惩时，应先走异常解锁，再由玩家重新提交该季度及后续阶段。
### 8.5 破产规则

#### 8.5.1 触发条件

以下任一条件满足，则判定破产：

- 在经营阶段提交节点，现金流断裂
- 在最终年份，所有者权益为负

#### 8.5.2 破产后的行为

- 该组后续所有年份和财报不可再填写。
- 已提交历史数据保留。
- 玩家仍可查看历史数据，但不可编辑。
- 管理员汇总页标记该组 `已破产`。

## 9. 状态流转需求

状态流转以 `docs/minimal_state_machine.md` 为准。

### 9.1 年份主状态

`未开放 -> 经营中 -> 待财报 -> 财报中 -> 已完成`

### 9.2 经营阶段子状态

`Q1_OPEN -> Q2_OPEN -> Q3_OPEN -> Q4_OPEN -> YEAR_END_OPEN`

### 9.3 财报子状态

`REPORT_LOCKED -> REPORT_OPEN -> REPORT_SUBMITTED`

### 9.4 叠加态与动作

- `已破产`：组级叠加态
- `异常解锁`：管理员动作，不作为普通主状态

## 10. 计算规则与实现约束

### 10.1 总体原则

- 当前以确认版 Excel 作为规则基线。
- 系统不直接把 Excel 当运行引擎。
- 系统按 `业务字段 + 计算规则` 实现。
- 每个关键计算字段应保留对应的 Excel 来源说明。

### 10.2 存储与映射原则

- 数据存储以业务字段为主。
- 不按 Excel 每个单元格直接建库存储。
- 前端通过字段到页面位置的映射还原 Excel 风格页面。
- 年份页面采用“动态年份视图”模式，而不是“每一年一套独立页面文件”模式。
- 后端负责维护可运行的年份状态空间；前端负责按 `finalYear + yearNo` 组织标签与切换。

### 10.3 规则变更边界

若后续只是少量公式调整，应优先通过集中修改规则映射或计算逻辑完成。

若变更已经影响以下内容，则应按需求变更重新确认：

- 字段结构
- 流程状态
- 汇总口径
- 跨表联动语义

## 11. 外部依赖与变更管理

### 11.1 当前外部依赖

| 事项 | 当前状态 | 处理方式 |
|---|---|---|
| Excel 中部分单元格名称 / 显示名称待调整 | 待外部输入 | 收到最终版后补字段命名映射；若仅改标签则不推翻现有需求 |

### 11.2 变更处理原则

- 若只是名称展示调整，应优先通过标签映射更新。
- 若名称调整同时改变业务语义、字段边界或汇总口径，则必须回到需求确认流程。
- 任何规则调整、范围变化、UI 方向变化，都应同步更新：
  - 本文档
  - `docs/requirements_consensus_checklist.md`
  - `docs/minimal_state_machine.md`
  - `docs/implementation_plan.md`

### 11.3 测试 / 演练支持边界

- 正式比赛规则保持不变，管理员开放下一年仍以“全部未破产组完成当前开放年份财报”为前提。
- 单组演练库 / 单组演练模式仅用于开发、测试、联调、验收与公式回归，不作为正式比赛规则放宽方案。
- 不建议为了方便单组演练而改动正式库中的年度推进规则，也不建议引入“按组独立推进年份”的正式业务规则。
- 推荐采用环境隔离方式支持演练：
  - 正式比赛库
  - 多组演练库
  - 单组演练库 / 单组演练模式
- 单组演练环境推荐只初始化：
  - `1` 个管理员账号
  - `1` 个玩家组账号
- 单组演练环境应支持重复执行 `0年 -> 最终年` 的单链路推演。
- 若后续 Excel 公式或字段名称调整，优先通过独立配置、初始化流程与映射文档收口，避免反向污染正式比赛环境。
- 正式比赛环境的小组数量通过管理员端赛前初始化流程配置；运行期不支持动态增减小组数量。
- 赛前初始化完成后，系统以后端已生成的小组主数据作为唯一运行依据。

## 12. 首版明确不做

| 项目 | 原因 |
|---|---|
| 导出功能 | 用户已明确首版不做 |
| 订单均价/波动系数/最小最大订单数量配置 | 订单模块首版先做数量控制，复杂生成参数后续再扩展 |
| 订单选择撤销 | 用户已确认首版不做玩家撤销，管理员撤销也暂不做 |
| 强制选完订单池 | 当前规则为每市场一轮选单，剩余订单不强制选完 |
| 未交付订单处罚自动计算 | 处罚规则暂未确定，首版只记录交付状态 |
| 通用历史纠错引擎 | 首版过重 |
| 任意快照回滚 / 历史版本库 | 首版不做 |
| 字段级回滚 | 管理复杂度过高 |
| 复杂排名图表或大屏 | 首版仅做基础汇总 |
| 去年规则文档中的认证/小巨人/贷款上限等完整电子化 | 不属于首版项目范围 |
| 桌游流程完全电子化 | 当前只做经营与财报系统，不做桌面流程全替代 |
| 整年重开（直接回退至 Q1_OPEN） | 与定向异常解锁不是同一能力，当前仍需单独确认风险与主持人操作边界，本轮先不做 |

## 13. 首版验收基线

### 13.1 业务验收

- 玩家可完成 `0年` 到正式年份的经营填写、阶段提交、财报填写。
- 玩家在 `0年` 不需要订单；从 `1年` 起可在年度订单页完成市场投入和订单选择。
- 管理员可上传/解析订单推算 Excel，配置各年各市场各订单类型数量，并生成固定订单池。
- 系统可按本地、区域、全国、全球四个市场分别生成选单顺序；无投入市场可跳过。
- `1年` 按市场投入排序；`2年` 起市场龙头优先，再按市场投入排序；并列通过随机结果收口。
- 每个市场只选一轮，每个参与小组最多选 `1` 单，剩余订单不强制选完。
- 玩家与管理员可通过统一登录页完成登录，并按角色自动进入对应首页。
- 管理员可完成初始基线录入、最终年份设置、下一年开放。
- 管理员上调 `最终年份` 后，系统可自动扩展未来年份空间，玩家端和管理员端年份标签随之增加。
- 管理员可在赛前配置页完成比赛初始化，并按初始化结果生成对应的小组、账号与各年份初始状态数据。
- 比赛开始后不支持动态增减小组数量；如需调整，应重新初始化新的比赛环境或新的比赛库。
- 新增年份在被正式开放前应保持可见但锁定。
- 汇总页可在正式年份展示收入/利润/权益与经营状态。
- 经营页能展示系统计算的季末现金，供玩家线下自检。
- 财报平衡校验能阻断错误提交。
- 异常解锁能按 `经营页 / 财报页` 定向生效；经营页可回退至指定阶段，后续结果失效但保留草稿。
- 破产规则能阻断后续经营。
- 正式年份未完成订单选择时，系统能阻断 `Q1` 提交。
- 已选订单能汇总为经营页订单总额，订单未交付时能保留 `UNFINISHED` 状态且不阻断财报提交。

### 13.2 页面验收

- 经营页与财报页为高保真 Excel 风格整页布局。
- 未开放阶段可见但锁定。
- 右侧工作栏存在但不破坏主表主体性。
