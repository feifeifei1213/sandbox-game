## 2. 产品定位与首版范围

### 2.1 产品定位

- 本项目首版服务于公司活动场景，核心价值偏向：
  - 经营演练
  - 规则教学
  - 财务结果反馈
- 首版目标不是完整替代桌游流程，而是先把：
  - 玩家经营填写
  - 财报填写
  - 管理员汇总与控制
  这几部分电子化并走通。

### 2.2 首版范围

首版交付范围如下：

| 模块 | 是否纳入首版 | 说明 |
|---|---|---|
| 统一登录页 | 是 | 最小用户名密码登录闭环，按角色自动跳转 |
| 玩家端经营页 | 是 | 高保真 Excel 风格；支持季度/年末填写与提交 |
| 玩家端年度订单 | 是 | `1年` 起查看市场预测、提交市场投入、按市场-订单类型标段竞标与选择订单；`0年` 不需要线上订单 |
| 玩家端财报页 | 是 | 高保真 Excel 风格；支持自动计算 + 手工项填写 |
| 管理员汇总页 | 是 | 汇总正式年份收入/利润/权益与经营状态 |
| 管理员年度控制 | 是 | 管理最终年份、开放下一年 |
| 管理员订单管理 | 是 | 维护多年订单数量控制台与市场预测，按当年市场开启状态生成/确认订单池、配置标段释放顺序、控制开标与查看状态 |
| 管理员通知与奖惩 | 是 | 发送普通通知，按组/年/季下发奖励与罚款 |
| 管理员初始基线 | 是 | 录入共享初始基线模板并提交锁定 |
| 管理员组数据查看 | 是 | 查看任一组任一年数据 |
| 管理员回退与修正 | 是 | 合并“退回重提”和“恢复快照”，用于单组阶段级修正 |
| 沙盘版本包选择 | 是 | 赛前选择内置版本包；已落地贵宾服务版，下一步新增生产制造版 |
| 异常解锁 | 是 | 作为“回退与修正”中的轻量“退回重提”模式保留 |
| 自动保存草稿 | 是 | 每 5 分钟自动保存一次草稿 |
| 排名大屏 / 复杂图表 | 否 | 首版不做 |
| 导出能力 | 否 | 首版不做 |
| 桌游流程完全电子化 | 否 | 首版不做 |
| 单组快照回退 | 是 | 只做单组、阶段级快照恢复；不做字段级回退，不做自动全局回退 |

### 2.3 首版方案判断

首版采用 `轻中型方案`：

- 页面层：高保真 Excel 风格
- 规则层：以 Excel 为主依据，但按业务规则实现
- 流程层：中等复杂度状态流转
- 存储层：业务字段存储 + 页面映射

## 3. 角色与权限需求

### 3.1 角色定义

| 角色 | 数量 | 核心职责 |
|---|---|---|
| 玩家组账号 | 赛前初始化配置 | 填写经营页、提交阶段、填写财报 |
| 管理员账号 | 1 | 赛前初始化、年度控制、查看汇总、初始化基线、回退与修正 |

### 3.2 权限边界

| 功能 | 玩家组 | 管理员 |
|---|---|---|
| 查看本组经营数据 | 是 | 是 |
| 查看其他组经营数据 | 否 | 是 |
| 查看汇总页 | 否 | 是 |
| 提交季度/年末 | 是 | 否 |
| 提交财报 | 是 | 否 |
| 查看本年订单池 | 是 | 是 |
| 提交各标段市场投入 | 是 | 否 |
| 按顺序选择订单 | 是 | 否 |
| 赛前初始化比赛 | 否 | 是 |
| 选择沙盘版本包 | 否 | 是，仅比赛初始化前 |
| 导入订单生成控制台参数 | 否 | 是 |
| 维护多年订单数量控制台并生成订单池 | 否 | 是 |
| 开放/关闭市场竞标 | 否 | 是 |
| 录入初始基线 | 否 | 是 |
| 开放下一年 | 否 | 是 |
| 回退与修正 | 否 | 是 |
| 异常解锁 | 否 | 是 |
| 查看通知 | 是 | 是 |
| 发送普通通知 | 否 | 是 |
| 下发奖励 / 罚款 | 否 | 是 |

### 3.3 数据隔离要求

- 玩家组之间数据严格隔离，不能查看彼此经营数据。
- 管理员可查看所有组数据。
- 汇总页仅管理员可见。
- 管理员可通过普通通知向全体玩家广播赛事事件信息，例如 `第一小组已破产`。
- 上述广播属于赛事信息公开，不等同于开放其他组的经营明细数据。
### 3.4 首版登录要求

- 系统提供统一登录页。
- 用户通过用户名和密码登录。
- 系统根据账号角色自动跳转，不要求用户手动选择角色。
- 玩家登录成功后默认进入 `0年经营`。
- 管理员登录成功后，若比赛尚未初始化，则默认进入“赛前配置页”；若比赛已初始化，则默认进入管理端首页，首版管理端首页默认落在 `汇总页`。
- 管理员默认入口的判断以后端当前已初始化的小组主数据为准，不依赖前端本地缓存或额外手工开关。
- 系统应提供退出登录能力，退出后返回统一登录页。
- 首版登录只做最小认证闭环，不扩展以下复杂账号能力：
  - 自助注册
  - 找回密码
  - 修改密码
  - 多角色切换
  - 细粒度账号管理后台

## 4. 核心业务对象

| 对象 | 说明 |
|---|---|
| 组 | 一个参赛小组，对应一个系统操作账号 |
| 年 | 包括 `初始基线`、`0年`、`1年~最终年` |
| 阶段 | `Q1/Q2/Q3/Q4/年末` |
| 财报 | 本年经营结束后开放的年度财报页面 |
| 汇总 | 管理员侧汇总的正式年度结果 |
| 通知 | 管理员发送给全体或单个小组的消息，不参与经营计算 |
| 奖惩 | 管理员按 `组 + 年 + 季` 下发的奖励或罚款，参与经营计算 |
| 订单模板 | 由当前沙盘版本包绑定的订单结构定义，控制市场列表、订单类型、最大订单数、默认开启市场、预测展示、订单字段和订单生成公式 |
| 市场开启 | 管理员手动控制订单市场是否开启；默认开启状态由订单模板定义；未开启市场不生成订单、不进入抢单 |
| 多年订单数量控制台 | 管理员按 `1年~8年 + 当前订单模板市场 + 当前订单模板订单类型` 配置订单卡片数量，是市场预测与年度正式订单池的共同数量来源 |
| 市场预测 | 系统基于多年订单数量控制台和当前订单模板生成公式产生的趋势展示，固定按 `1~3年 / 4~5年 / 6~8年` 三段展示，不受管理员最终年份裁剪 |
| 订单生成控制 | 管理员每年开始前手动开启市场，系统从多年订单数量控制台读取当年已开启市场的订单数量，并按当前订单模板公式链生成订单池 |
| 标段 | 某年某市场某订单类型的开标单元；标段数量由订单模板决定，其中未开启市场对应标段不参与订单生成和开标 |
| 订单池 | 某年某标段可供玩家选择的订单集合，订单被选后锁定，不再对其他组可选 |
| 市场竞标 | 玩家按 `市场 + 订单类型` 提交市场投入；未开启市场在玩家端禁用并由系统自动按 `0` 提交，系统只对已开启且已配置订单的标段生成选单顺序 |
| 市场龙头 | 从 `2年` 起，每个市场以上一年该市场已选订单金额最高的小组作为优先选单方；若并列则随机确定 |
| 标段释放顺序 | 管理员配置同一年内各市场-订单类型标段的开标先后顺序 |
| 订单选择 | 玩家在轮到本组时从当前标段可选订单中选择 `1` 个订单 |
| 订单交付状态 | 已选订单的交付跟踪状态，首版先记录状态，处罚规则暂不自动计算 |
| 沙盘版本包 | 由系统内置的字段模板、公式版本、流程版本组合；管理员只在赛前选择，初始化后锁定，不允许运行中切换 |
| 字段模板版本 | 控制经营页、财报页的字段结构、稳定编码和默认显示名称；订单页结构由订单模板控制 |
| 公式规则版本 | 控制经营页、财报页、汇总和订单生成计算口径；订单生成公式可由订单模板独立绑定 |
| 流程规则版本 | 控制年份、季度、财报、订单开标等流程口径；当前贵宾、生产与机场订单流程均沿用通用流程版本 |
| 业务显示字典 | 管理员维护的页面业务名称显示配置，只改变经营页/财报页/订单页等业务字段、市场、订单类型的显示名，不改变字段含义、公式、数据和流程 |
| 字典方案 | 可复用的业务显示名称模板，必须绑定沙盘版本包；可新建、编辑、删除，供以后新比赛选择 |
| 当前比赛字典快照 | 比赛初始化时从版本默认字典或自定义字典方案复制出的当前比赛显示名称；比赛中解锁修改或应用方案时只改变该快照 |
| 经营状态 | 正常 / 已破产 |
| 年份状态 | 参见 `docs/minimal_state_machine.md` |

## 5. 年度与比赛口径需求

### 5.1 年份定义

| 年份 | 口径 | 是否参与汇总排名 |
|---|---|---|
| 初始基线 | 管理员录入的基线年 | 否 |
| 0年 | 引导年 / 非排名年 | 否 |
| 1年 ~ 最终年 | 正式比赛年 | 是 |

### 5.2 初始基线

- 由管理员以共享模板单页录入或确认。
- 提交成功后按组应用到全部小组。
- 提交后锁定，不可修改。
- 用于后续年度衔接基线。

### 5.3 0年

- 流程上与正式年份一致。
- 支持填写、提交、财报。
- 参与到 `1年` 的数据传递。
- 不进入正式汇总和最终排名。
- 不需要线上订单，也不进入订单竞标流程。
- `0年` 经营相当于管理员带领玩家熟悉规则的年份；`0年财报` 作为进入 `1年` 的初始/承接基线。

### 5.4 正式胜负规则

- 正式汇总年份从 `1年` 开始。
- 最终年份 `所有者权益` 最高的公司获胜。
- 首版不展示过程中的实时排名。
- 最终年份完成后，管理员汇总页可展示最终排名。
- 线上订单从 `1年` 开始参与正式经营流程。
- `1年` 的订单选择顺序按当前标段市场投入从高到低确定；市场投入相同的小组用随机方式确定先后。
- `2年` 起，每个市场先判断上一年该市场市场龙头；市场龙头优先，其余小组再按当前标段市场投入排序。

### 5.5 最终年份与动态扩年规则

- 系统不为 `0年 / 1年 / 2年 / ...` 分别生成独立页面文件。
- 玩家经营页与玩家财报页各自只维护 `1` 套正式页面结构，通过 `yearNo` 切换年份数据视图。
- 管理员设置 `最终年份` 后，系统应以该值作为玩家端和管理员端“年份标签上限”。
- 当管理员把 `最终年份` 从较小值上调到更大值时，系统必须自动补齐全部小组缺失的未来年份运行状态记录，确保后续年份可被正常打开。
- 自动补齐出的未来年份默认口径如下：
  - 年份类型：`FORMAL`
  - 年份主状态：`LOCKED`
  - 经营阶段状态：`Q1_OPEN`
  - 财报状态：`REPORT_LOCKED`
  - 不计入正式汇总
  - 经营提交版本号、财报提交版本号初始为 `0`
- 当管理员把 `最终年份` 下调到较小值时，只要不小于 `当前开放年份` 即允许修改。
- 下调 `最终年份` 时，系统不物理删除已经存在的未来年份数据；页面与接口仅按新的 `最终年份` 作为可见上限。
- 修改 `最终年份` 不应自动改变 `当前开放年份`。
- 年份空间的扩展与收口属于管理员控制能力的一部分，不属于玩家端流程动作。

## 6. 玩家端需求

### 6.1 页面总体要求

- 玩家端经营页采用高保真 Excel 风格整页布局。
- 玩家端新增独立 `年度订单` 页面，用于正式年份订单竞标、市场投入提交、按顺序选择订单与查看本组订单状态。
- 玩家端财报页采用高保真 Excel 风格整页布局。
- 首页默认进入 `0年经营`。
- 年份标签全部可见。
- 未开放年份不可进入或不可编辑。
- 页面允许存在轻量右侧工作栏，但主表必须始终是视觉主体。
- 玩家经营页与财报页的右侧工作栏顶部都必须保留 `通知区`，优先展示管理员最新通知。

### 6.1.1 年度订单页

- `年度订单` 是独立玩家页面，不嵌入经营页主表。
- `0年` 不显示订单竞标入口或显示为无需订单的只读说明。
- `1年 ~ 最终年` 进入或提交经营页 `Q1` 前，必须先完成本年订单竞标流程。
- 玩家可在年度订单页查看市场预测；市场预测固定按 `1~3年 / 4~5年 / 6~8年` 三段展示当前订单模板下的市场与订单类型趋势，不因管理员把最终年份配置为 `3年` 或 `5年` 而裁剪。
- 玩家端市场预测展示应贴近对应订单 Excel 的竖状柱状图口径：每个阶段下按市场分图，横轴为年份，柱子区分订单类型，并展示预测金额/订单量摘要；不采用纯文字卡片作为首版主要展示。
- 市场预测来自管理员维护的多年订单数量控制台和订单生成公式链，是玩家进行市场投入决策的依据，不展示其他小组经营数据。
- 玩家可在年度订单页查看当前年各市场订单池，按市场和订单类型筛选。
- 贵宾订单模板 `VIP_ORDER_TEMPLATE_V1` 的订单市场为：
  - 本地市场
  - 区域市场
  - 全国市场
  - 全球市场
- 贵宾订单模板 `VIP_ORDER_TEMPLATE_V1` 的订单类型为：
  - 代办过检
  - 两舱贵宾
  - 商务贵宾
  - 会员定制
- 机场订单模板 `AIRPORT_ORDER_TEMPLATE_V1` 的订单市场为：
  - 国内市场
  - 国际市场
- 机场订单模板 `AIRPORT_ORDER_TEMPLATE_V1` 的订单类型为：
  - 窄体
  - 宽体
- 每个 `市场 + 订单类型` 组合视为一个独立标段；贵宾模板每年最多 `16` 个标段，机场模板每年最多 `4` 个标段。
- 贵宾模板本地市场默认开启，区域市场、全国市场、全球市场默认关闭；机场模板国内市场默认开启，国际市场默认关闭；管理员可在当年订单生成前手动开启或关闭。
- 未开启市场仍在玩家市场投入表中显示，但该市场下全部投入输入框禁用，系统自动按 `0` 提交；若绕过前端提交非 `0`，服务端禁止提交。
- 未开启市场不生成订单池、不进入标段释放顺序、不进入抢单流程。
- 管理员可按 `年份 + 市场` 配置单市场投入上限；未配置表示无上限，已关闭市场不启用上限。
- 单市场投入上限单位为 `M`，必须为非负整数。
- 玩家端展示每个市场的开启状态和投入上限；无上限显示“无上限”，未开启显示“未开启”。
- 管理员可配置标段释放顺序，玩家按当前释放标段逐个参与选单。
- 玩家在正式年份开标前一次性提交当前订单模板下全部 `市场 + 订单类型` 投入值；贵宾模板为 `16` 项，机场模板为 `4` 项；提交后不允许修改。
- 已开启市场的投入值均必填，允许填 `0`；未开启市场由系统自动补 `0`。市场投入必须为非负整数，空值或小数不允许提交。
- 已开启且配置了上限的市场，该市场下所有订单类型投入合计不得超过单市场投入上限。
- 市场投入提交入口独立于经营页；提交后自动带入经营页年初市场投入区域并只读展示，继续参与 Excel 费用公式链。
- 当所有未破产小组均已提交市场投入、当年订单池已确认、标段释放顺序已配置后，管理员才可开始释放标段。
- 玩家按本组在当前释放标段的顺序选择订单。
- 每个标段只进行 `1` 轮选择：每个有该标段投入的小组最多选择 `1` 个订单；所有参与小组轮完后，该标段抢单结束。
- `2年` 起，上一年度该市场市场龙头即使本年该市场下某产品投入为 `0`，也仍在该市场下各标段优先选单。
- 未被选择的订单保留为未选状态，不要求必须被全部选完。
- 未开启市场的标段状态应展示为 `市场未开启` 或等价文案，不应展示为 `已跳过`。
- 已开启市场中，某标段订单数量为 `0` 时展示为 `未配置订单` 或等价文案，不进入开标；只有订单数量大于 `0` 但因全员无投入等流程原因未进入选单时，才展示为 `已跳过`。
- 普通小组未在某标段投入时，不参与该标段排序和选单。
- 玩家端和管理员端都展示当前标段完整选单顺序；排序依据不对玩家展示。
- 玩家端展示各小组在当前标段的选单状态，包括无资格、待选择、当前选择、已选择、已放弃、管理员跳过。
- 玩家可看到当前标段订单池；已被其他组选择的订单显示为灰色不可选，但不显示被哪个小组选走。
- 管理员可查看完整选单明细，包括哪个小组选了哪个订单。
- 页面状态同步首版采用自动轮询，不做 WebSocket；轮询间隔先固定为 `3` 秒，选择成功后当前页面立即刷新。
- 自动轮询应采用静默刷新：不得触发整页加载态、不得卸载当前订单内容、不得导致页面滚动位置回到顶部。
- 只有当前轮到的小组可以选择订单；后端必须校验“是否轮到本组”和“订单是否仍可选”。
- 当前轮到的小组可以放弃本标段；放弃后不能反悔，本标段不再回到该小组。
- 如果当前小组长时间不操作，管理员可以代为跳过该小组当前标段选择，但不能代选订单；代跳过必须记录日志。
- 玩家选择订单后不能撤销；首版也不提供管理员撤销订单选择能力。
- 本组已选订单在经营页中作为订单来源，经营页不再让玩家自由决定正式年份订单总额。
- 玩家在年度订单页或本组订单展示区对已选订单执行交付操作，交付时绑定当前经营季度。
- 已选订单不允许分季度拆分交付；同一季度可以交付多个完整订单。
- 系统校验当前季度销售收入必须等于本季度交付订单金额合计；校验通过后，将对应订单标记为已交付。
- 若年末仍未完成交付，订单标记为 `UNFINISHED`，但首版允许继续提交财报。
- 未完成交付的处罚规则暂不确定；首版只保留状态与后续规则接入口。
- 机场沙盘版经营页 / 财报页未接入前，机场订单可独立完成配置、开标、选单、放弃、锁定和市场龙头联调；订单交付按钮保留但置灰不可点击。

### 6.2 经营页填写与提交

#### 6.2.1 阶段结构

- 不做单独“年初提交”。
- `Q1 提交` 时一并处理 `年初区 + Q1 区`。
- `Q2/Q3/Q4` 各自单独提交。
- `年末区` 单独提交。

#### 6.2.2 阶段显示与锁定

| 当前所处阶段 | 年初区 | Q1 | Q2 | Q3 | Q4 | 年末 |
|---|---|---|---|---|---|---|
| Q1 | 可编辑 | 可编辑 | 只读锁定 | 只读锁定 | 只读锁定 | 只读锁定 |
| Q2 | 只读 | 只读 | 可编辑 | 只读锁定 | 只读锁定 | 只读锁定 |
| Q3 | 只读 | 只读 | 只读 | 可编辑 | 只读锁定 | 只读锁定 |
| Q4 | 只读 | 只读 | 只读 | 只读 | 可编辑 | 只读锁定 |
| 年末 | 只读 | 只读 | 只读 | 只读 | 只读 | 可编辑 |

#### 6.2.3 手工项与默认值

- 所有手工填写项默认空值。
- `0` 必须由用户显式填写。
- 所有用户手工填写的数字必须为整数，不允许小数；适用于金额、数量、费用、成本、投入、上限、分数等手工数字输入。
- 所得税税率下拉、系统计算结果、系统生成订单单价、历史/导入/公式结果展示不受“手工数字必须为整数”限制。
- 前端应将可编辑数字输入限制为整数输入，并在输入小数时提示；后端提交接口必须做硬校验，防止绕过前端。
- 首版只做：
  - 顶部错误提示
  - 未填项高亮
- 不做重型校验清单面板。

#### 6.2.4 第 9 步订单数量留痕

- 生产制造版将原“9. 下新供应链订单”提醒改为四类产品、四个季度的手工数量记录；四类为：基础产品、标准产品、精密产品、智能产品。
- 贵宾服务版将原“9. 下新服务订单”提醒改为四类服务、四个季度的手工数量记录；四类为：代办过检服务、两舱贵宾服务、商务贵宾服务、会员定制服务。
- 每格单位为“个”，默认空值；当前季度四项均为必填，没有订单时必须显式填写 `0`。
- 每格只允许非负整数，不允许负数、小数或文本；前端限制输入，后端保存草稿和阶段提交时再次硬校验。
- 记录按 `小组 + 年份 + 季度 + 产品/服务类型` 独立保存，不向下一年复制或结转；新年度首次打开时保持空值。
- 该记录仅作为线下空桶订单的经营留痕凭证，不生成订单卡，不占用订单池，不参与市场竞标、选单或交付，不影响现金、收入、成本、财报、汇总和排名公式。
- 管理员通过现有阶段级“退回重提”或“恢复快照”回退到对应季度后，目标季度及后续季度的该记录随经营页一起恢复可编辑；目标季度之前的记录保持有效且只读。
- 回退修改后必须按现有阶段顺序重新提交；修改前提交、回退前安全快照和修改后提交均保留，不新增字段级直接修改或字段级回退入口。

#### 6.2.5 通知与奖惩展示

- 玩家经营页右侧工作栏顶部必须显示通知区。
- 通知区首版最小结构为：
  - `1` 条置顶通知
  - 最近通知列表
- 普通通知可用于流程提醒、赛事播报、主持人口径说明等，不参与经营计算。
- 经营页中的 `额外支出 / 罚款` 与 `额外收入 / 奖励` 保留 Excel 原位置，但改为只读展示。
- `额外支出 / 罚款` 与 `额外收入 / 奖励` 的数值由管理员下发后自动带入对应季度，不再由玩家手工填写。
- `折现费用` 继续由玩家填写。
### 6.3 财报页需求

#### 6.3.1 开放条件

- 本年经营全部完成后，财报页才开放。
- 年末提交成功后，应立即开放本年财报页。

#### 6.3.2 财报展示与填写边界

- 财报页自动带出 Excel 可计算结果。
- 首版以当前 Excel 中绿色单元格定义手工输入边界。
- 当前已确认手工项包括：
  - 在制品
  - 成品
  - 材料
  - 所得税税率
- 财报页右侧工作栏顶部也应显示通知区，保持与经营页一致的通知入口。

#### 6.3.3 税率输入规则

- 所得税税率采用下拉框。
- 允许值仅为：
  - `0.25`
  - `0.15`
  - `0`

#### 6.3.4 财报提交条件

- 财报手工项已完成。
- 必须通过平衡校验：`总资产 = 总负债 + 总权益`。
- 财报提交成功后，本年度完成。

### 6.4 自动保存与正式提交

- 首版自动保存采用轻量方案：每 `5` 分钟自动保存一次草稿。
- 季度提交 / 年末提交 / 财报提交，才是正式提交动作。
- 首版不做复杂自动保存失败交互设计。
- 自动保存的目标是减少误操作损失，不等于协同编辑级可靠性保障。

### 6.5 右侧工作栏需求

| 页面 | 工作栏内容 |
|---|---|
| 经营页 | 通知区、阶段状态、季末现金展示说明、贷款提醒 |
| 财报页 | 通知区、平衡校验、税率说明、财报提交 |

## 7. 管理员端需求

### 7.1 菜单范围

首版管理员端仅包括：

- 汇总
- 年度控制
- 订单管理
- 通知与奖惩
- 初始基线
- 组数据

### 7.2 汇总页

#### 7.2.1 汇总口径

- 汇总页正式口径来自各组各年“已提交财报”的结果。
- 汇总从 `1年` 开始显示，不显示 `0年`。
- 当前核心指标为：
  - 收入
  - 利润
  - 权益

#### 7.2.2 展示要求

- 页面上方展示“年度汇总区”，展示各组正式年份结果。
- 增加 `经营状态` 列。
- 已破产组显示红色 `已破产` 标签。
- 页面下方展示“最终排名区”。
- 仅在最终年份满足开放条件后显示有效排名；未满足条件时显示状态提示。

### 7.3 年度控制

- `最终年份` 为配置项，由管理员设定。
- `当前开放年份` 为运行时状态，由管理员控制。
- 管理员可手动开放下一年。
- 玩家不可自行开放下一年。
- 当管理员上调 `最终年份` 时，系统应自动补齐新增正式年份的初始状态空间。
- 年份标签数量应以当前 `最终年份` 为准动态变化，而不是前端写死。

### 7.4 初始基线

- 管理员在单页共享模板中录入初始基线。
- 提交后按组应用到全部小组。
- 提交后锁定。
- 提交后不可修改。

### 7.4.1 管理员赛前初始化比赛

- 管理员端提供统一的 `赛前配置` 页面，用于在比赛开始前配置本场比赛的小组数量、最终年份、沙盘版本包、业务显示字典，并提供初始基线入口。
- `赛前配置` 推荐采用向导式流程：`比赛基础信息 -> 选择版本包 -> 选择/编辑字典方案 -> 初始基线入口 -> 确认初始化`，避免管理员在多个页面之间来回确认。
- 管理员在赛前配置页确认小组数量、最终年份、沙盘版本包和当前显示名称后，系统初始化本场比赛的小组主数据、账号数据、当前比赛字典快照与各年份初始状态数据。
- 比赛未初始化前，管理员登录后默认进入赛前配置页。
- 小组数量配置仅在比赛开始前生效；初始化完成后，系统以后端已初始化的小组主数据作为唯一运行依据。
- 首版建议直接以后端 `sg_group` 的实际记录数推断 `initialized` 与 `groupCount`，不再额外维护一套运行期“配置真相”。
- 比赛开始后，不支持动态增减小组数量。
- 沙盘版本包仅允许在比赛初始化前选择；初始化完成后锁定，不支持运行中切换。
- 初始化前初始基线应由管理员完成；首版不做强制拦截，确认初始化时只提示管理员核对初始基线状态。
- 已落地 `VIP_SERVICE_V1` 贵宾服务版：经营页字段、财报页字段与订单页字段均采用贵宾服务版显示口径，公式规则与流程规则继续共用当前通用版本。
- 本轮新增方案为 `PRODUCTION_V1` 生产制造版：经营页字段与财报页字段从 `shengchan` 分支的生产制造口径提取；订单字段暂时继续绑定 `VIP_ORDER_TEMPLATE_V1`，仍显示代办过检、两舱贵宾、商务贵宾、会员定制等贵宾订单字段。
- `PRODUCTION_V1` 订单字段属于临时兼容口径；等拿到生产版订单字段后，再新增或替换为 `PRODUCTION_ORDER_TEMPLATE_V1`，不得直接把临时字段伪装成最终生产版订单字段。
- 下一阶段新增 `AIRPORT_V1` 机场沙盘版：订单模板绑定 `AIRPORT_ORDER_TEMPLATE_V1`；经营页模板和财报页模板暂为待接入，不套用贵宾版或生产版字段，玩家进入经营页 / 财报页时显示占位页且不允许填写提交。
- 新增生产制造版时不直接修改已发布的 `VIP_SERVICE_V1`。
- 赛前初始化页默认选中哪个版本仍待用户最终确认；建议实现时先保留当前默认 `VIP_SERVICE_V1`，管理员可手动选择 `PRODUCTION_V1`。
- 初始化流程应以单事务完成，一次性创建小组主数据、账号数据与各年份状态；任一步失败都必须整体回滚，不得留下半成品。
- 初始化成功后，管理员账号继续保留 `admin`，玩家账号按 `group01 ~ groupNN` 规则自动生成。
- 初始化完成后，系统默认进入“`0年` 已开放、`1年 ~ 最终年` 已预置但锁定待开放”的初始状态。
- 初始化接口在比赛已初始化后不得重复执行；如需调整小组数量，应重新初始化新的比赛环境或新的比赛库。
- 管理员提交初始基线时，系统按当前已初始化的小组集合进行扇出应用。
- 汇总页、最终排名区、组数据页、通知与奖惩目标范围，均按实际初始化的小组数据动态展示。
- 玩家侧仅在比赛完成初始化后进入正常参赛流程。
- 初始化完成后，赛前配置页转为当前比赛配置只读页，展示版本包、小组数量、最终年份、初始化时间、当前比赛字典快照、公式版本与只读公式参数、初始基线入口和字段名称修改记录。
- 初始化完成后，最终年份仍沿用现有 `年度控制` 页面修改；赛前配置页只读展示最终年份，并提示如需调整请进入年度控制。

#### 7.4.1A 业务显示字典

- 业务显示字典只负责页面显示名称，不负责字段结构、字段含义、公式规则或流程规则。
- 字典可修改范围：
  - 经营页业务字段显示名
  - 财报页业务字段显示名
  - 初始基线业务字段显示名
  - 市场显示名
  - 订单类型显示名
  - 订单页业务字段显示名
  - 市场预测图表中的市场和订单类型显示名
- 字典不允许修改：
  - 稳定字段编码
  - 字段含义、字段类型、是否必填、阶段归属和页面位置
  - 公式计算方式、公式参数和跨年承接口径
  - 流程状态、阶段名称、按钮、菜单、错误提示和系统状态文案
- 市场稳定编码由当前订单模板定义；贵宾订单模板为 `LOCAL / REGIONAL / NATIONAL / GLOBAL`，机场订单模板为 `DOMESTIC / INTERNATIONAL`，管理员只允许改显示名，不允许运行期新增或删除。
- 订单类型稳定编码由当前订单模板定义；贵宾订单模板为 `AGENCY_INSPECTION / TWO_CABIN_VIP / BUSINESS_VIP / MEMBER_CUSTOM`，机场订单模板为 `NARROW_BODY / WIDE_BODY`，管理员只允许改显示名，不允许运行期新增或删除。
- 经营页和财报页字段结构固定，只允许改显示名，不允许新增字段、隐藏字段或调整字段位置。
- 字典方案必须绑定沙盘版本包；不同版本包的字段结构可能不同，首版不做跨版本字典方案直接套用。
- 字典方案可以新建、编辑、删除；删除或编辑字典方案默认不影响当前比赛字典快照。
- 比赛初始化时，系统把管理员当前选择和编辑后的显示名称复制为 `当前比赛字典快照`。
- 初始化后若需要修改当前比赛显示名称，管理员可在赛前配置页点击 `解锁修改显示名称`，修改当前比赛字典快照。
- 初始化后可将某个同版本包字典方案 `应用到当前比赛`，采用整体覆盖当前比赛字典快照的方式；操作前必须二次确认并展示变更数量和变更详情。
- 初始化后可将当前比赛显示名称 `另存为字典方案`，供以后新比赛复用。
- 初始化后可恢复为当前版本包默认名称；该操作立即影响当前比赛显示名称，必须二次确认并记录日志。
- 字典显示名不允许为空；同一类业务名称原则上不允许重复；业务上不限制显示名长度，但页面必须支持换行、截断或悬浮提示，避免长名称挤坏布局。
- 管理员端字段名称配置表默认不展示稳定字段编码，只展示分类、所属页面/区块、当前名称和修改后名称；稳定编码仅在系统内部和必要的高级详情中使用。
- 每次初始化后修改当前比赛字典快照、应用方案或恢复默认名称，都必须记录字段名称修改日志，至少包含操作人、操作时间、影响范围、变更数量、来源方案和字段前后名称。
- 字典修改后，玩家端和管理员端应静默同步新显示名称；不得清空草稿、重置输入状态、改变当前年份/页签、弹窗打断玩家或导致页面滚动到顶部。

### 7.5 组数据查看

- 管理员可查看任意组、任意年、任意页面的数据。
- 首版不要求做复杂进度总控面板。
- 现场进度主要通过主持人口头控制。

### 7.5.1 订单管理

- 管理员端新增 `订单管理` 页面或等价菜单入口。
- 订单生成依据由当前订单模板决定：贵宾订单模板依据 `道具-订单推算（服务企业）.xlsx`，机场订单模板依据 `机场沙盘订单.xlsx`。
- 系统应内置并实现对应 Excel 的订单生成公式链，不把 Excel 文件作为运行时实时计算引擎。
- 订单数量主来源为多年订单数量控制台，固定覆盖 `1年~8年 × 当前订单模板市场 × 当前订单模板订单类型`。
- 多年订单数量控制台按 Excel 的三段结构组织和展示：`1~3年`、`4~5年`、`6~8年`；该展示不受管理员配置的最终年份影响。
- 市场预测由多年订单数量控制台和订单生成公式链产生，用于玩家端趋势展示；市场预测不是独立手工配置的一套订单数量。
- 订单生成主链路为：管理员维护多年订单数量控制台 -> 系统生成市场预测快照 -> 管理员当年手动开启市场 -> 系统读取当年已开启市场的控制台数量生成预览订单池 -> 管理员确认订单池 -> 系统固化生成批次、随机种子、参数快照和订单明细。
- 每年开始前生成当年订单，不赛前一次性生成全部年份订单。
- 当年订单数量从多年订单数量控制台带入；年度订单页不再维护另一套独立订单数量来源。
- 生成预览阶段允许反复重新生成；每次重新生成使用新的随机种子并覆盖当前预览批次。
- 管理员确认订单池后，该年订单池转为正式批次；一旦确认后不允许修改订单数量或重新生成订单池。
- 管理员端订单页应先配置当年市场开启状态和单市场投入上限；默认开启状态由当前订单模板定义，管理员可在订单池确认前且本年尚无任何小组提交市场投入时开启或关闭市场、调整上限。
- 市场是否进入订单生成和抢单完全以管理员当年手动开启为准；即使多年订单数量控制台中某市场当年存在订单数量，只要管理员未开启该市场，该市场仍视为关闭。
- 市场一旦关闭，该市场下全部订单类型标段不生成订单池，不进入释放顺序，不参与选单，玩家对应投入由系统自动按 `0` 提交。
- 市场开启状态和单市场投入上限在订单池确认后或已有任意小组提交本年市场投入后锁定；若后续需要调整，应在玩家提交投入前完成。
- 生成批次必须保存公式版本、随机种子、订单数量控制台快照、市场预测快照、公式参数快照和生成出的订单明细，用于复盘和审计；首版页面可不展示随机种子。
- 首版管理员可配置的订单生成参数限定为：多年订单数量控制台中的 `年份 + 市场 + 订单类型` 订单卡片数量；贵宾模板取值范围为 `0 ~ 15`，机场模板取值范围为 `0 ~ 28`。
- 对已开启市场，`0` 表示该标段未配置订单、不生成订单，也不进入开标；超过当前订单模板上限不允许保存。
- 管理员可配置每年各标段的释放顺序；释放单元为当前订单模板下的 `市场 + 订单类型`。
- 标段释放顺序只对已开启且订单数量大于 `0` 的标段生效；未开启市场和订单数量为 `0` 的标段不应占用有效释放顺序。
- 标段释放顺序可在开标前配置和调整；释放第一个标段后锁定，开标过程中不允许调整。
- 订单均价、波动系数、最小/最大订单数量、账期范围、每产品最多订单卡数等公式参数首版按 Excel 内置，不做页面配置，但必须保存到生成批次参数快照中。
- 当年带入的订单数量只做风险提示，不强制保底或强制分配。提示至少覆盖全年订单总数少于小组数、某市场订单数少于有资格小组数、某标段订单数少于有资格小组数、某小组本年可能没有可参与标段等情况。
- 管理员可查看所有未破产小组的当年市场投入提交状态；未全部提交时不允许开始开标，系统不做管理员代填。
- 订单池生成不依赖市场投入；选单排序依赖市场投入。
- 开标前置条件为：所有未破产小组已提交当前订单模板下全部市场投入、当年订单池已确认、当年标段释放顺序已配置。
- 系统按当前标段生成选单顺序，不按市场共用一个顺序。
- 管理员按已配置释放顺序手动逐个释放标段；当前标段结束后不自动释放下一标段。
- 管理员只能释放下一个应释放标段，不能跳过预设顺序释放后续标段。
- 管理员可查看各标段的市场投入、选单顺序、市场龙头、订单选择进度和未交付订单状态；未开启市场与未配置订单应和真正流程跳过分开展示。
- 管理员订单池查看默认展示当前年份全部订单，并可按市场、订单类型筛选；订单列表展示的订单编号应为业务订单编号或订单卡片编号，例如 `CARD-01`，不得用数据库自增 ID 作为主要展示编号。
- 管理员订单页应按真实操作顺序组织：多年订单数量控制台/市场预测、年份选择与刷新、市场开启设置、当年控制台数量只读带入与释放顺序、生成预览订单池、确认订单池、生成选单顺序、释放标段与当前选单状态、订单池查看。
- `保存配置` 操作应放在对应配置模块内；多年订单数量控制台单独保存，当年订单管理区只保存市场开启和标段释放顺序，不再重复保存另一套订单数量。
- “上传 Excel”不再作为首版订单池主链路；如后续保留导入能力，应定位为“导入订单生成控制台参数/模板”，而不是上传固定订单池结果。
- 不做上传机场 Excel 自动抽取公式；机场订单公式由开发从 `机场沙盘订单.xlsx` 提取后内置为 `AIRPORT_ORDER_FORMULA_V1`。
- 首版不做复杂订单撤销、订单交易、导出与实时大屏。

### 7.6 异常解锁

> 定位说明：异常解锁继续保留，但在管理员端产品入口中并入 `回退与修正` 页面，作为 `退回重提` 模式。它适合小范围阶段填错，不依赖历史快照；新增的 `恢复快照` 模式见 `7.7`。

#### 7.6.1 触发条件

- 仅管理员可执行。
- 仅针对 `某组 + 某年`。
- 仅允许在 `下一年尚未开放前` 执行。
- 管理员必须显式选择本次解锁目标：
  - `OPERATING`：经营页异常解锁
  - `REPORT`：财报页异常解锁
- 当目标为 `OPERATING` 时，管理员还必须选择回退阶段：
  - `Q1`
  - `Q2`
  - `Q3`
  - `Q4`
  - `YEAR_END`
- 仅允许回退到“已正式提交”的目标阶段或财报结果。
- 管理员无需填写退回原因；系统自动记录默认原因 `管理员退回重提`，并保留异常解锁审计记录。

#### 7.6.2 输入项

| 输入项 | 是否必填 | 说明 |
|---|---|---|
| `groupId` | 是 | 目标组 |
| `yearNo` | 是 | 目标年份 |
| `unlockTargetType` | 是 | `OPERATING` / `REPORT` |
| `targetStageCode` | 条件必填 | 当 `unlockTargetType = OPERATING` 时必填 |
| `reason` | 否 | 退回说明；为空时服务端自动记录为 `管理员退回重提` |

#### 7.6.3 经营页异常解锁

- 管理员选择 `OPERATING + 目标阶段` 后，系统按该阶段执行定向回退。
- 早于目标阶段的已生效经营结果继续有效，并保持只读。
- 目标阶段恢复为可编辑状态。
- 晚于目标阶段的经营阶段结果全部失效，但页面中的原值不清空，保留为 `失效草稿`。
- 本年财报结果同步失效；财报手工项原值不清空，保留为 `失效草稿`。
- `失效草稿` 具有以下约束：
  - 不计入当前有效经营结果
  - 不计入当前有效财报结果
  - 不计入管理员汇总
  - 不计入下一年的正式结转
  - 只有在玩家重新走到对应阶段并重新提交后，才重新生效
- 若该年破产结论由被失效的后续结果触发，异常解锁后应临时恢复为 `NORMAL`，待重新提交后再重新判定。

#### 7.6.4 财报页异常解锁

- 管理员选择 `REPORT` 时，不回退经营页的已生效阶段。
- 财报结果失效，财报页恢复可编辑。
- 财报手工项原值不清空，保留为 `失效草稿`，玩家可在此基础上修改后重新提交。
- 该年汇总结果同步失效。
- 若该年破产结论由财报结果触发，异常解锁后应临时恢复为 `NORMAL`，待财报重新提交后再重新判定。

#### 7.6.5 解锁后的重新提交流程

1. 管理员在组数据页发起异常解锁。
2. 玩家看到目标页或目标阶段重新开放。
3. 若为经营页异常解锁，玩家必须从目标阶段开始，依次重新提交：
   - 目标阶段
   - 后续经营阶段
   - 年末
   - 财报
4. 若为财报页异常解锁，玩家只需重新提交财报。
5. 只有在重新提交完成后，该年才重新计入正式汇总。

#### 7.6.6 后端实现规则清单

- 接口请求体必须正式承载 `unlockTargetType` 与 `targetStageCode`，不得继续使用只有 `groupId + yearNo + reason` 的年份级通用解锁口径。
- 服务端状态机必须区分 `有效结果` 与 `失效草稿`，不能用“清空后续值”代替本需求。
- 当目标为 `OPERATING` 时，必须按 `Q1 / Q2 / Q3 / Q4 / YEAR_END` 做阶段级回退，而不是只恢复“当前最新阶段可编辑”。
- 经营页回退后，后续经营阶段与财报必须同时失效；但原值保留，可作为重新开放时的草稿回填来源。
- 汇总、破产状态、下一年结转口径都必须只读取 `有效结果`，不能读取 `失效草稿`。
- 异常解锁日志必须至少记录：目标组、目标年份、解锁目标类型、目标阶段、系统默认原因或退回说明、操作人、操作时间、解锁前后状态摘要。
- 服务端错误提示必须目标化，例如：
  - `经营页当前无需解锁`
  - `财报页当前无需解锁`
  - `目标阶段尚未正式提交，不能解锁`
  - `下一年已开放，不能再解锁本年`
- 必须补齐单元测试 / 集成测试，覆盖经营页回退、财报页解锁、失效草稿保留、汇总失效、破产恢复等关键场景。

#### 7.6.7 前端页面与交互改造清单

- 管理员 `组数据页` 的异常解锁弹窗必须新增：
  - 解锁目标类型选择
  - 当目标为 `OPERATING` 时显示经营阶段选择
  - 影响说明区
- 管理端错误提示必须与目标类型一致，不再使用笼统的“当前年份已处于可编辑状态”覆盖所有场景。
- 玩家经营页在经营页异常解锁后必须同时表达 3 类状态：
  - 已生效且只读的历史阶段
  - 当前重新开放可编辑的目标阶段
  - 保留原值但已失效、需重新提交的后续阶段
- 玩家财报页在经营页异常解锁后应恢复为未生效状态；此前手工值保留为草稿，待重新到达财报阶段时自动回填。
- 玩家财报页在财报页异常解锁后应直接打开为可编辑状态，并回填此前保留的手工草稿。
- 前端展示应尽量保持 Excel 高保真布局，不在主表中央增加大段说明；状态提示应优先放在阶段标题、页签状态、右侧工作栏或提交区。

### 7.7 回退与修正

#### 7.7.1 功能定位

- 管理员端新增或改造为统一的 `回退与修正` 入口。
- `回退与修正` 包含两个模式：
  - `退回重提`：复用现有异常解锁能力，按目标阶段重新开放，适合小范围修正。
  - `恢复快照`：新增单组快照回退能力，按历史快照恢复某组流程状态，适合某组已经推进到后续年份后发现早期阶段错误。
- 两种模式都不清空玩家已填写数据；目标节点之后的数据保留为 `失效草稿`，玩家在原数据基础上修改并重新提交。
- 首版只做单组、阶段级快照回退，不做字段级回退，不做系统自动全局回退。

#### 7.7.2 快照范围与保留

- 单组快照用于恢复某个 `小组 + 年份 + 阶段` 的业务状态。
- 全局快照用于记录订单池确认、标段完成、开放下一年等全局流程节点，首版主要用于审计和后续全局恢复扩展，不混入单组恢复逻辑。
- 快照在本场比赛内不自动清理。
- 每次管理员执行 `退回重提` 或 `恢复快照` 前，系统必须先自动生成一份 `回退前安全快照`。
- 允许连续回退；退回重提由系统自动记录默认原因，恢复快照仍需填写原因；每次回退都必须记录日志并生成新的回退前安全快照。

自动快照节点建议：

- 单组经营阶段提交成功后生成单组快照。
- 单组财报提交成功后生成单组快照。
- 管理员执行退回重提或恢复快照前生成单组安全快照。
- 管理员确认订单池后生成全局快照。
- 每个标段完成后生成全局快照。
- 管理员开放下一年后生成全局快照。

管理员可手动创建单组快照或全局快照，并填写说明。

#### 7.7.3 单组快照回退规则

- 回退目标粒度按阶段，不支持字段级回退。
- 可回退到某年 `Q1 / Q2 / Q3 / Q4 / YEAR_END`，以及财报相关节点。
- 单组跨年度回退允许，例如某组从 `5年` 回退到 `3年 Q2`。
- 回退不改变全局当前开放年份。
- 回退后：
  - 目标阶段恢复为当前可编辑或待重提状态。
  - 目标节点之后的经营、财报、汇总结果失效。
  - 目标节点之后的数据保留为 `失效草稿`。
  - 被回退小组必须从目标阶段开始依次重新提交。
  - 当前未提交草稿也保留，但标记为失效草稿，不允许继续按旧页面提交。
- 回退执行期间短暂锁定该组写操作；若玩家同时提交，服务端应返回“状态已变化，请刷新页面”。
- 被回退小组玩家端必须显示提示：已被管理员回退到某年某阶段，后续数据为失效草稿，请从当前阶段开始核对并重新提交。

#### 7.7.4 订单边界

- 单组快照回退不回滚订单竞标结果：
  - 已选订单保留归属，不释放给其他小组。
  - 不重算市场龙头。
  - 不重排历史选单顺序。
  - 不重新生成已确认订单池。
- 目标节点之后的订单交付状态失效，需要该组重新经营到对应阶段后再次确认交付。
- 后续年份已选订单标记为失效但不释放；当该组重新走到对应年份时，继续作为该组订单来源。
- 若回退时该组还未参与某个已生成顺序的标段，系统不强制所有小组等待；管理员负责现场节奏控制。页面应提示：该组处于回退补提中，继续释放标段可能导致该组无法按原节奏参与。
- 若确实需要回滚订单竞标结果，应作为后续 `全局快照恢复` 或 `标段局部重开` 单独设计，不纳入首版单组快照回退。

#### 7.7.5 奖惩、通知、汇总与破产

- 普通通知不回退。
- 目标节点之后的奖惩影响经营结果，因此应失效；奖惩记录保留，但标记为已失效，不再计入经营页。
- 若仍需对该组生效，管理员需要重新下发奖惩。
- 目标节点之后的正式汇总撤回，汇总页显示该组相关年份为 `待重提`，不计入当前排名。
- 历史数值可在组数据页查看，但正式汇总口径不采用失效结果。
- 若破产发生在目标节点之后，回退后应临时恢复为 `NORMAL`，待重新提交后重新判定。

#### 7.7.6 年度控制影响

- 若存在任意小组处于回退补提 / 待重提状态，管理员不能开放下一年。
- 年度控制页应展示阻断原因，例如：`仍有小组处于回退补提中，不能开放下一年`。
- 必须等所有未破产小组完成当前开放年份要求，并且不存在回退补提状态后，才能继续开放下一年。

#### 7.7.7 管理员页面要求

- 管理员端 `回退与修正` 页面建议包含两个 Tab：
  - `退回重提`
  - `恢复快照`
- `退回重提` 表单项：
  - 小组
  - 年份
  - 目标类型：经营页 / 财报页
  - 经营阶段：`Q1 / Q2 / Q3 / Q4 / YEAR_END`
  - 原因
  - 影响说明与二次确认
- `恢复快照` 页面项：
  - 快照列表
  - 按小组、年份、阶段、快照类型筛选
  - 查看快照详情
  - 输入回退原因
  - 二次确认后执行
- 回退确认弹窗必须展示：
  - 回退小组
  - 当前阶段
  - 目标快照或目标阶段
  - 将失效的年份和阶段
  - 订单影响说明：不释放订单、不重排选单顺序
  - 回退原因

## 8. 核心业务规则

### 8.1 提交校验规则

| 提交动作 | 校验范围 |
|---|---|
| Q1 提交 | `年初 + Q1`；正式年份还需本年订单竞标流程已结束 |
| Q2 提交 | `Q2` |
| Q3 提交 | `Q3` |
| Q4 提交 | `Q4` |
| 年末提交 | `年末区手工项` |

补充规则：

- 已提交且已锁定的历史阶段，不重复做必填完整性校验。
- 每次经营阶段提交后，系统返回当期计算的期末现金，供玩家线下自行核对。

### 8.1.1 线上订单与市场竞标规则

#### 8.1.1.1 适用范围

- 线上订单只适用于 `1年 ~ 最终年`。
- `0年` 不需要订单，不参与市场投入排序和订单选择。
- 订单竞标按标段独立执行，不做全年统一订单池。
- 每个 `市场 + 订单类型` 组合为一个标段；市场、订单类型和标段数量由当前比赛绑定的订单模板定义。
- 贵宾订单模板 `VIP_ORDER_TEMPLATE_V1` 为 `本地 / 区域 / 全国 / 全球` 四个市场乘以 `代办过检 / 两舱贵宾 / 商务贵宾 / 会员定制` 四类订单，每年最多 `16` 个标段。
- 机场订单模板 `AIRPORT_ORDER_TEMPLATE_V1` 为 `国内 / 国际` 两个市场乘以 `窄体 / 宽体` 两类订单，每年最多 `4` 个标段。
- 默认市场开启状态由订单模板定义：贵宾模板本地市场默认开启，区域 / 全国 / 全球默认关闭；机场模板国内市场默认开启，国际市场默认关闭。
- 管理员可按当年订单流程手动开启或关闭市场；未开启市场不生成订单池、不进入标段释放顺序、不进入抢单流程。
- 管理员配置标段释放顺序，系统按顺序逐个开放标段选单。

#### 8.1.1.2 订单池生成

- 管理员通过订单管理维护订单池。
- 系统按当前订单模板绑定的 Excel 公式链生成订单池，Excel 本身作为规则依据，不作为运行时订单池上传结果。
- 贵宾订单模板依据 `道具-订单推算（服务企业）.xlsx`；机场订单模板依据 `机场沙盘订单.xlsx`。
- 多年订单数量控制台是订单数量主来源，固定覆盖 `1年~8年 × 当前订单模板市场 × 当前订单模板订单类型`；控制台按 `1~3年 / 4~5年 / 6~8年` 三段展示和维护。
- 市场预测由多年订单数量控制台和当前订单模板生成公式链生成，玩家端只读展示；管理员最终年份配置不裁剪市场预测三段展示。
- 每年开始前生成当年订单池，不赛前一次性生成全部年份。
- 当年订单池生成时，系统从多年订单数量控制台读取该年份、已开启市场的 `市场 + 订单类型` 数量；年度订单管理页不再维护独立的订单数量配置。
- 市场是否参与当年订单生成完全以管理员当年手动开启为准；控制台有订单数量但市场未开启时，该市场仍不生成订单、不进入抢单。
- 订单数量上限由订单模板定义：贵宾模板每标段 `0 ~ 15`，机场模板每标段 `0 ~ 28`。
- 已开启市场下 `0` 表示该标段未配置订单、不生成订单且不进入开标。
- 首版需要支持配置标段释放顺序，释放单元为当前订单模板下的 `市场 + 订单类型`；有效释放顺序只覆盖已开启且订单数量大于 `0` 的标段。
- 管理员可生成预览订单池；预览阶段若需要调整数量，应回到多年订单数量控制台修改后再重新生成，重新生成会覆盖旧预览批次。
- 管理员确认订单池后，系统固化正式生成批次、随机种子、公式版本、参数快照和订单明细。
- 订单池确认后不允许修改订单数量、不允许重新生成；任一标段开始释放后，标段释放顺序也锁定。
- 订单池数量由管理员负责配置冗余，系统只提供风险提示，不做强制保底、不做多轮分配、不强制每组全年至少获得一个订单。
- 订单主表保存所有模板通用并参与流程的字段：年份、市场、订单类型、标段序号、业务订单编号、订单金额、主数量、单价、账期和状态。
- 模板专属订单字段保存到 `order_payload_json`，由当前订单模板字段定义决定页面展示。
- 贵宾订单金额生成口径为 `订单金额 = 数量 × 单价`；数量为整数，单价允许保留小数，但系统后端在生成订单时必须自动校准有效单价，保证相乘后的订单金额为整数。
- 机场订单金额生成口径为：按 Excel 公式得到底层总收入，再按 Excel 显示口径四舍五入为整数 `M`，作为系统订单金额；单价保留 4 位小数，底层收入只存扩展字段，不在玩家页展示。
- 订单池页面默认展示全部订单，并允许按市场和订单类型筛选；页面主编号显示业务编号或卡片序号，例如 `CARD-01`，不使用数据库自增 ID 作为管理员识别订单的主要编号。
- 订单数量和账期按对应 Excel 随机公式生成；系统额外保存随机种子用于复盘，不改变玩家看到的规则。
- 当前订单推算 Excel 未提供直接成本和交付季度，因此首版不从订单生成器生成直接成本或交付季度。
- 直接成本继续由玩家在经营页填写。
- 交付季度由玩家在经营页自行安排。

#### 8.1.1.3 机场订单模板专属字段

- 机场订单卡展示字段包括：订单编号、航线区域、飞机类型、航线类型、跑道要求、架次、吞吐量、客座率、总收入、单价、账期。
- 机场订单编号沿用 `CARD-01 ~ CARD-28`，每个标段内独立编号。
- 机场订单架次范围为 `9000 ~ 11000`，保存到主数量字段。
- 机场订单客座率为 `60% ~ 80%` 的整数，页面显示百分比。
- 机场订单吞吐量按 `160 × 架次 × 客座率 / 1000000` 计算，页面按 Excel 显示口径取整展示，底层值存扩展字段。
- 机场订单单价公式为 `客座率 / 200 × 0.012 × 航线系数 × 跑道系数`，展示 4 位小数。
- 航线系数：国内 `1`，国际 `1.7`。
- 跑道系数：`4C = 1`，`4D = 2`，`4E = 2.4`，`4F = 3`。
- 窄体订单跑道要求固定 `4C`；宽体订单跑道要求按 Excel 随机 `4D / 4E / 4F`。
- 国内订单航线区域固定 `国内`；国际订单航线区域按 Excel 随机 `亚太 / 欧非 / 美洲`。

#### 8.1.1.4 市场投入与参与资格

- `0年` 不走独立市场投入提交。
- `1年 ~ 最终年` 开标前，玩家必须一次性提交当前订单模板下全部 `市场 + 订单类型` 投入值；贵宾模板为 `16` 项，机场模板为 `4` 项。
- 全部投入项均必填，允许填 `0`；空值不允许提交。
- 未开启市场对应的投入由系统自动按 `0` 提交，玩家端输入框禁用；若绕过前端提交非 `0`，服务端应拒绝提交并提示该市场未开启。
- 市场投入必须为非负整数，不允许小数。
- 管理员可按 `年份 + 市场` 配置单市场投入上限；未配置表示无上限。若配置了上限，则该市场下所有订单类型投入合计不得超过上限。
- 单市场投入上限必须为非负整数，单位为 `M`。
- 已有任意未破产小组提交本年市场投入后，管理员不能再修改本年市场开启状态和单市场投入上限。
- 市场投入提交后不允许修改。
- 市场投入从经营页前移到独立年度订单页/市场投入页提交；经营页对应市场投入格只读带入，不允许在 `Q1` 再修改。
- 非市场龙头小组在某标段没有正数投入，则不参与该标段选单。
- 市场龙头是对应市场的例外：即使本年该市场下某产品投入为 `0`，也仍在该市场下对应标段优先选单。
- 未开启市场不进入选单排序和跳过判断；已开启市场中，订单数量为 `0` 的标段为“未配置订单”，不进入开标；订单数量大于 `0` 但所有未破产小组该标段投入均为 `0` 时，才作为流程跳过。
- 各标段市场投入汇总进入经营页年初区的 `市场投入`；机场经营页未接入前，仅在订单模块联调范围内记录投入，不进入未知经营模板。

#### 8.1.1.5 选单排序

- `1年`：按当前标段的 `市场 + 订单类型` 投入从高到低排序。
- `1年` 当前标段投入相同：通过随机方式确定先后，并记录随机结果。
- `2年` 起：该市场上一年市场龙头在该市场下各标段优先选择，其余参与小组再按当前标段投入从高到低排序。
- `2年` 起若市场龙头没有当前标段投入，仍保留该市场下对应标段优先权；该投入金额仍按实际 `0` 计入经营页市场投入。
- 若上一年该市场没有任何已选订单，则本年不产生市场龙头优先权，直接按当年市场投入排序。
- 市场龙头定义为：上一年该市场全部订单类型已选订单金额合计最高的小组。
- 机场模板下，国内市场龙头按上一年国内窄体 + 国内宽体已选订单金额合计计算，国际市场龙头按上一年国际窄体 + 国际宽体已选订单金额合计计算。
- 每个市场每年只产生 `1` 个市场龙头；若上一年该市场已选订单金额并列最高，则随机确定其中一个为市场龙头，并记录随机结果。
- 市场龙头只在未破产小组中生效；若上一年市场龙头已破产，本年按没有有效市场龙头处理。
- 非龙头小组当前标段投入相同时，按上一年度该市场订单总额从高到低排序；仍相同则随机，并记录随机结果。
- 市场龙头按已选订单金额统计，不要求订单已交付。

#### 8.1.1.6 标段释放与选单轮次

- 管理员先配置同一年内各标段的释放顺序。
- 标段释放顺序只覆盖已开启市场中订单数量大于 `0` 的标段；未开启市场和未配置订单的标段不占用有效释放顺序。
- 标段释放顺序在释放第一个有效标段前可调整；释放第一个有效标段后锁定，不允许修改。
- 开标前置条件为：所有未破产小组已提交当前订单模板下全部市场投入、当年订单池已确认、当年有效标段释放顺序已配置。
- 管理员手动释放下一标段，必须按预设顺序释放，不能跳序；当前标段结束后不自动释放下一标段。
- 每个标段只进行 `1` 轮选择。
- 每个参与小组在同一标段最多选择 `1` 个订单。
- 按排序依次选择；某个订单被选后立即锁定，不再对后续小组可选。
- 所有有资格小组都完成选择、放弃或被管理员代跳过后，该标段抢单结束；若订单池提前被选空，也视为该标段结束。
- 当前标段结束后，管理员再按释放顺序手动释放下一标段。
- 标段订单池未被选完时，不继续追加轮次；剩余订单保持未选状态。
- 玩家选择订单后不可撤销；首版管理员也不提供撤销选单能力。
- 当前轮到的小组可放弃本标段，放弃后不可反悔；管理员可代为跳过长时间未操作的小组，但不能代选订单。
- 玩家端和管理员端通过 `3` 秒自动轮询同步状态；不做 WebSocket 实时推送。
- 玩家端年度订单页自动轮询必须静默刷新，不应打断玩家查看订单池或导致页面跳回顶部。

#### 8.1.1.7 与经营页联动

- 正式年份当年订单竞标流程未结束时，不允许进入或提交 `Q1` 经营。
- 当年所有应开标段均已完成或跳过后，订单竞标流程结束；未开启市场和未配置订单标段不属于应开标段。
- 本组在全部已释放标段中已选订单金额合计进入经营页 `订单总额`。
- 本组提交的当前订单模板全部市场投入合计进入经营页 `市场投入`，并在经营页只读展示；未开启市场由系统自动按 `0` 提交，不会增加经营页市场投入。
- 经营页只消费订单模块提供的订单来源，不替代订单模块的选单流程。
- 账期字段首版只在订单卡片和本组已选订单明细中展示，不参与经营页应收账款自动计算。
- 直接成本不由订单模块生成，仍由玩家在经营页填写。
- 订单不允许分季度拆分交付。
- 玩家在订单展示页面对本组已选订单执行交付操作，并绑定当前经营季度。
- 某季度销售收入必须等于该季度交付订单金额合计，校验通过后可将这些订单标记为已交付。
- 年末未交付订单标记为 `UNFINISHED`，但暂不阻断财报提交。
- 未交付处罚规则暂定；首版只保存订单交付状态，预留后续处罚计算接入口。
- 机场经营页和财报页未接入前，机场订单交付按钮保留但置灰不可点击；机场版只能独立联调订单配置、开标、选单、锁定和市场龙头，不支持完整经营闭环、年度结转和最终排名。

### 8.2 季末现金展示规则

- 经营页主表保留“核对季末现金”展示行。
- 系统按当前经营数据计算 `Q1/Q2/Q3/Q4` 的季度期末现金。
- 玩家自行对照线下沙盘现金进行核对。
- 系统不采集现场现金，也不因现金差异阻断提交。

### 8.3 贷款提醒

- 每个季度提交后，系统提醒玩家关注贷款更新。
- 该提醒仅为提醒，不做强制拦截。
- 不区分当前是否存在贷款，都统一提醒。

### 8.4 通知与奖惩

#### 8.4.1 普通通知

- 管理员可发送普通通知。
- 普通通知支持：
  - 发送给全体小组
  - 发送给单个小组
- 普通通知允许自由文本，不限制为固定模板。
- 普通通知可用于：
  - 提醒准备开启下一年
  - 催促提交经营或财报
  - 广播赛事事件，例如 `第一小组已破产`
- 普通通知只负责展示，不参与经营计算、财报计算和汇总计算。

#### 8.4.2 奖惩通知

- 奖励与罚款改为管理员下发，不再由玩家手工填写。
- 奖惩必须绑定到：
  - 目标小组
  - 年份
  - 季度
- 奖惩最小字段包括：
  - 类型：`奖励 / 罚款`
  - 金额
  - 原因说明
  - 下发人
  - 下发时间
- 奖惩属于计算型业务事件，必须参与：
  - 经营页当期计算
  - 财报结果承接
  - 管理员汇总口径
- 若同一组同一季度存在多条奖励或罚款，系统应按类型分别合计后展示到经营页对应单元格。

#### 8.4.3 玩家页展示与编辑边界

- 经营页中 `额外支出 / 罚款`、`额外收入 / 奖励` 保留现有 Excel 布局位置。
- 上述两类单元格改为玩家只读。
- 玩家在右侧通知区查看具体奖惩原因，不要求把长说明塞入 Excel 主表。
- `折现费用` 仍由玩家填写，不转移给管理员。

#### 8.4.4 奖惩与阶段锁定关系

- 若目标季度当前仍未正式提交，管理员可直接下发奖惩并立即生效。
- 若目标季度已经正式提交并锁定，管理员不得直接修改该季度已生效奖惩结果。
- 对已锁定季度补发或更正奖惩时，应先走异常解锁，再由玩家重新提交该季度及后续阶段。
### 8.5 破产规则

#### 8.5.1 触发条件

以下任一条件满足，则判定破产：

- 在经营阶段提交节点，现金流断裂
- 在最终年份，所有者权益为负

#### 8.5.2 破产后的行为

- 该组后续所有年份和财报不可再填写。
- 已破产组不参与后续年份或后续未开始标段的订单竞标与选单。
- 已提交历史数据保留。
- 玩家仍可查看历史数据，但不可编辑。
- 管理员汇总页标记该组 `已破产`。

## 10. 计算规则与实现约束

### 10.1 总体原则

- 当前以确认版 Excel 作为规则基线。
- 系统不直接把 Excel 当运行引擎。
- 系统按 `业务字段 + 计算规则` 实现。
- 每个关键计算字段应保留对应的 Excel 来源说明。
- 公式不提供管理员在线编辑能力；若后续出现新版 Excel 公式，由开发提取后以内置公式版本发布。
- 当前已确认生产版与贵宾版经营页、财报页公式一致，首版共用 `COMMON_FORMULA_V1`。
- 首版不做管理员上传 Excel 自动抽取公式；后续如需扩展，应作为 `Excel 公式版本导入工具` 单独设计，生成公式版本草稿并经过字段映射、试算和发布校验后，才允许新比赛选择。
- 订单均价、波动范围、数量范围、账期范围等公式参数首版只读展示，不开放编辑；随机种子不在管理员页面展示。

### 10.2 存储与映射原则

- 数据存储以业务字段为主。
- 不按 Excel 每个单元格直接建库存储。
- 前端通过字段到页面位置的映射还原 Excel 风格页面。
- 年份页面采用“动态年份视图”模式，而不是“每一年一套独立页面文件”模式。
- 后端负责维护可运行的年份状态空间；前端负责按 `finalYear + yearNo` 组织标签与切换。
- 字段展示与页面标签通过字段模板版本控制；首版先从 `guibing` 分支既有服务/贵宾字段配置提取 `VIP_OPERATING_TEMPLATE_V1`、`VIP_REPORT_TEMPLATE_V1` 与 `VIP_ORDER_TEMPLATE_V1`。
- 字段模板版本只控制显示字段、标签和页面文案，不改变稳定的系统字段名、payload 结构和数据库字段语义。
- 业务显示字典在字段模板默认名称之上生效，只覆盖当前比赛或字典方案中的显示名；公式、提交 payload 和数据库仍只使用稳定字段编码。
- 汇总页、回退与修正页、通知/奖惩页中出现业务字段、市场或订单类型名称时，应使用当前比赛字典显示名；系统列、流程状态、按钮、菜单、错误提示和自由文本不做字典替换。

### 10.3 规则变更边界

若后续只是少量公式调整，应优先通过集中修改规则映射或计算逻辑完成。

若变更已经影响以下内容，则应按需求变更重新确认：

- 字段结构
- 流程状态
- 汇总口径
- 跨表联动语义

### 10.4 沙盘版本包规则

- 沙盘版本包由 `editionCode`、字段模板版本、公式规则版本和流程规则版本组成。
- 首版默认版本包为 `VIP_SERVICE_V1`，中文名建议为“贵宾服务版 V1”。
- `VIP_SERVICE_V1` 绑定：
  - 经营页字段模板：`VIP_OPERATING_TEMPLATE_V1`
  - 财报页字段模板：`VIP_REPORT_TEMPLATE_V1`
  - 订单字段模板：`VIP_ORDER_TEMPLATE_V1`
  - 公式规则版本：`COMMON_FORMULA_V1`
  - 流程规则版本：`COMMON_PROCESS_V1`
- `PRODUCTION_V1` 绑定：
  - 经营页字段模板：`PRODUCTION_OPERATING_TEMPLATE_V1`
  - 财报页字段模板：`PRODUCTION_REPORT_TEMPLATE_V1`
  - 订单字段模板：暂用 `VIP_ORDER_TEMPLATE_V1`
  - 公式规则版本：`COMMON_FORMULA_V1`
  - 流程规则版本：`COMMON_PROCESS_V1`
- `AIRPORT_V1` 绑定：
  - 经营页字段模板：`PENDING_OPERATING_TEMPLATE`
  - 财报页字段模板：`PENDING_REPORT_TEMPLATE`
  - 订单模板：`AIRPORT_ORDER_TEMPLATE_V1`
  - 订单生成公式版本：`AIRPORT_ORDER_FORMULA_V1`
  - 流程规则版本：暂用 `COMMON_PROCESS_V1`
- `PRODUCTION_V1` 的经营页和财报页显示名以 `shengchan` 分支现有生产制造字段为来源；订单页和订单相关四类产品字段暂用贵宾订单口径，待生产版订单字段来源确认后另行调整。
- `AIRPORT_V1` 的经营页和财报页 Excel 尚未提供，因此不临时套用贵宾版或生产版经营 / 财报字段；该版本首轮仅支持订单模块独立联调，经营页 / 财报页显示待接入占位页。
- 管理员只能选择系统内置版本包，不能在线新增字段、修改字段结构、修改字段含义、编辑公式或改变流程规则；业务显示名可通过业务显示字典维护。
- 已发布版本包原则上只新增不修改；生产制造版作为 `PRODUCTION_V1` 独立版本包新增，不覆盖 `VIP_SERVICE_V1`。
- 当前系统不做多场比赛历史归档；当前比赛内部的提交、订单、回退、快照、日志仍必须保留到本场比赛结束。
- 历史提交、订单生成批次与汇总快照应能追溯本场比赛当时使用的沙盘版本包和规则/模板版本；业务显示名展示时以当前比赛字典快照为准。

## 11. 外部依赖与变更管理

### 11.1 当前外部依赖

| 事项 | 当前状态 | 处理方式 |
|---|---|---|
| Excel 中部分单元格名称 / 显示名称待调整 | 待外部输入 | 收到最终版后补字段命名映射；若仅改标签则不推翻现有需求 |
| 贵宾服务版经营页 / 财报页字段 | 已在 `guibing` 分支形成前端字段配置雏形 | 本轮提取为 `VIP_SERVICE_V1` 字段模板，公式和流程仍走通用版本 |
| 生产版经营页 / 财报页字段模板 | 来源为 `shengchan` 分支现有生产制造字段 | 新增 `PRODUCTION_V1`，经营页和财报页使用生产制造口径，公式和流程仍走通用版本 |
| 生产版订单字段模板 | 暂未拿到最终字段来源 | `PRODUCTION_V1` 首轮暂用 `VIP_ORDER_TEMPLATE_V1`；拿到生产版订单字段后再新增 `PRODUCTION_ORDER_TEMPLATE_V1` 或等价模板版本 |

### 11.2 变更处理原则

- 若只是名称展示调整，应优先通过标签映射更新。
- 若名称调整同时改变业务语义、字段边界或汇总口径，则必须回到需求确认流程。
- 任何规则调整、范围变化、UI 方向变化，都应同步更新：
  - 本文档
  - `docs/requirements_consensus_checklist.md`
  - `docs/minimal_state_machine.md`
  - `docs/implementation_plan.md`

### 11.3 测试 / 演练支持边界

- 正式比赛规则保持不变，管理员开放下一年仍以“全部未破产组完成当前开放年份财报”为前提。
- 单组演练库 / 单组演练模式仅用于开发、测试、联调、验收与公式回归，不作为正式比赛规则放宽方案。
- 不建议为了方便单组演练而改动正式库中的年度推进规则，也不建议引入“按组独立推进年份”的正式业务规则。
- 推荐采用环境隔离方式支持演练：
  - 正式比赛库
  - 多组演练库
  - 单组演练库 / 单组演练模式
- 单组演练环境推荐只初始化：
  - `1` 个管理员账号
  - `1` 个玩家组账号
- 单组演练环境应支持重复执行 `0年 -> 最终年` 的单链路推演。
- 若后续 Excel 公式或字段名称调整，优先通过独立配置、初始化流程与映射文档收口，避免反向污染正式比赛环境。
- 正式比赛环境的小组数量通过管理员端赛前初始化流程配置；运行期不支持动态增减小组数量。
- 赛前初始化完成后，系统以后端已生成的小组主数据作为唯一运行依据。

## 12. 首版明确不做

| 项目 | 原因 |
|---|---|
| 导出功能 | 用户已明确首版不做 |
| 订单均价/波动系数/最小最大订单数量配置 | 订单模块首版先做数量控制，复杂生成参数后续再扩展 |
| 订单选择撤销 | 用户已确认首版不做玩家撤销，管理员撤销也暂不做 |
| 强制选完订单池 | 当前规则为每标段一轮选单，剩余订单不强制选完 |
| 未交付订单处罚自动计算 | 处罚规则暂未确定，首版只记录交付状态 |
| 可用资金总额校验 | 暂时不做；市场投入先只按非负整数、单市场投入上限和未开启市场自动置零校验 |
| 管理员在线编辑字段结构或字段含义 | 首版只允许通过业务显示字典修改显示名称，不允许新增字段、隐藏字段、调整字段位置或改变字段含义 |
| 管理员在线编辑公式 | 公式由 Excel 来源经开发提取后内置，管理员不直接维护公式表达式 |
| 管理员上传 Excel 自动抽取公式 | 公式导入属于重型公式引擎能力，本轮只预留后续 `Excel 公式版本导入工具` 方向 |
| 管理员编辑流程规则 | 流程规则由版本包内置，不在页面展示或编辑 |
| 管理员新增/删除市场或订单类型 | 市场和订单类型数量固定，只允许通过业务显示字典修改显示名 |
| 公式参数编辑 | 订单均价、波动范围、数量范围、账期范围等首版只读展示，不开放编辑 |
| 比赛中切换沙盘版本包 | 版本包影响字段解释和历史追溯，仅允许赛前初始化时选择 |
| 通用历史纠错引擎 | 首版过重 |
| 字段级快照回滚 / 历史版本编辑器 | 首版不做；已确认的单组阶段级快照恢复除外 |
| 系统自动全局快照恢复 | 首版不做；全局快照仅用于审计和后续扩展 |
| 字段级回滚 | 管理复杂度过高 |
| 复杂排名图表或大屏 | 首版仅做基础汇总 |
| 去年规则文档中的认证/小巨人/贷款上限等完整电子化 | 不属于首版项目范围 |
| 桌游流程完全电子化 | 当前只做经营与财报系统，不做桌面流程全替代 |
| 整年重开（直接回退至 Q1_OPEN） | 与定向异常解锁不是同一能力，当前仍需单独确认风险与主持人操作边界，本轮先不做 |

## 13. 首版验收基线

### 13.1 业务验收

- 玩家可完成 `0年` 到正式年份的经营填写、阶段提交、财报填写。
- 玩家在 `0年` 不需要订单；从 `1年` 起可在年度订单页完成当前订单模板下全部市场投入和订单选择，未开启市场由系统自动按 `0` 提交。
- 管理员可维护多年订单数量控制台，系统按订单推算 Excel 公式链生成预览订单池并确认固化正式批次。
- 管理员可配置当年市场开启状态；默认开启状态由当前订单模板定义，未开启市场不生成订单、不进入抢单。
- 系统可按 `市场 + 订单类型` 标段分别生成选单顺序；无投入或无订单数量的标段可跳过。
- 管理员可配置当前订单模板下全部市场-订单类型标段的释放顺序；贵宾模板每年最多 `16` 个标段，机场模板每年最多 `4` 个标段；有效释放顺序只覆盖已开启且订单数量大于 `0` 的标段。
- `1年` 按当前标段投入排序；`2年` 起市场龙头优先，再按当前标段投入排序；并列通过随机结果收口。
- 每个标段只选一轮，每个参与小组最多选 `1` 单，剩余订单不强制选完。
- 玩家与管理员可通过统一登录页完成登录，并按角色自动进入对应首页。
- 管理员可完成初始基线录入、最终年份设置、下一年开放。
- 管理员上调 `最终年份` 后，系统可自动扩展未来年份空间，玩家端和管理员端年份标签随之增加。
- 管理员可在赛前配置页选择沙盘版本包并完成比赛初始化；当前已支持贵宾服务版和生产制造版，机场沙盘版按 `AIRPORT_V1` 作为新增内置版本包推进。
- 初始化完成后，系统按初始化结果生成对应的小组、账号与各年份初始状态数据，并锁定本场比赛沙盘版本包。
- 比赛开始后不支持动态增减小组数量；如需调整，应重新初始化新的比赛环境或新的比赛库。
- 比赛开始后不支持切换沙盘版本包；如需改为其他版本，应重新初始化新的比赛环境或新的比赛库。
- 新增年份在被正式开放前应保持可见但锁定。
- 汇总页可在正式年份展示收入/利润/权益与经营状态。
- 经营页能展示系统计算的季末现金，供玩家线下自检。
- 财报平衡校验能阻断错误提交。
- 异常解锁能按 `经营页 / 财报页` 定向生效；经营页可回退至指定阶段，后续结果失效但保留草稿。
- 破产规则能阻断后续经营。
- 正式年份未完成订单竞标流程时，系统能阻断进入或提交 `Q1`。
- 已选订单能汇总为经营页订单总额，订单未交付时能保留 `UNFINISHED` 状态且不阻断财报提交。

- 未开放阶段可见但锁定。
- 右侧工作栏存在但不破坏主表主体性。
