# 订单模块页面与联调验收清单

> 更新日期：2026-05-20  
> 适用范围：`I4-05` 订单模块收口验收，覆盖管理员订单页、玩家年度订单页、经营页订单前置联动和 `.http` 接口联调。

## 1. 验收前提

- 后端已启动：`go run ./cmd/server -config configs/local.yaml`
- 前端已启动：在 `frontend/` 执行 `npm run dev`
- 当前联调库不是正式比赛库
- 管理员账号可登录：`admin / 123456`
- 至少存在 `2` 个未破产玩家组，且目标年份为正式年份（`1年` 起）

## 2. 管理员订单生成验收

1. 进入管理员端订单页。  
   期望：页面按操作顺序展示年份与刷新、市场开启、标段数量与释放顺序、订单池生成/确认、选单控制和订单池查看。

2. 配置当年市场开启状态。  
   期望：本地市场默认开启；区域市场、全国市场、全球市场默认关闭；订单池确认前可手动开启/关闭，确认后锁定。

3. 配置标段订单数量与释放顺序。  
   期望：未开启市场行置灰或明确显示“市场未开启”，订单数量固定为 `0`；已开启市场订单数量只接受 `0~15`；有效释放顺序只覆盖已开启且订单数量大于 `0` 的标段；保存按钮位于该配置区内。

4. 点击生成预览订单池。  
   期望：页面展示预览批次、随机种子、公式版本、生成数量；未确认前允许覆盖重生成。

5. 点击确认订单池。  
   期望：确认后配置锁定，不允许继续修改数量、释放顺序或覆盖订单池。

6. 查看订单池。  
   期望：默认展示当前年份全部订单，可按市场和订单类型筛选；订单编号显示 `CARD-01` 等业务编号或卡片序号，不显示数据库自增 ID 作为主编号；订单卡展示市场、订单类型、金额、数量、单价、账期和状态。

## 3. 玩家市场投入验收

1. 玩家打开 `0年` 订单页。  
   期望：显示 `0年` 不需要订单，不出现提交市场投入和选单动作。

2. 玩家打开正式年份订单页。  
   期望：订单池确认后可提交市场投入；必须一次提交完整 `16` 项，`0` 合法但缺项不合法；未开启市场仍显示对应 4 项，玩家必须手动填写 `0`。

3. 玩家在未开启市场填写非 `0` 投入后提交。  
   期望：服务端拒绝提交，并提示该市场未开启、投入必须填写 `0`。

4. 玩家提交市场投入后再次进入。  
   期望：投入变为只读，不能二次修改。

## 4. 选单顺序与标段释放验收

1. 管理员在所有未破产组提交完整投入后生成选单顺序。  
   期望：未开启市场显示为“市场未开启”且不进入开标；订单数量为 `0` 的已开启标段显示为“未配置订单”；订单数量大于 `0` 但全员 `0` 投入的标段才显示为“已跳过”。

2. 验证排序规则。  
   期望：`1年` 按本标段市场投入倒序；`2年` 起同市场龙头优先，非龙头同投入时按上一年度该市场订单总额，再按随机结果。

3. 管理员释放下一个标段。  
   期望：只能按开标前配置的释放顺序释放；当前标段未完成时，释放下一标段会被拦截。

4. 玩家按顺序选单。  
   期望：未轮到的小组不能选择；已被上一小组选走的订单，在下一小组页面为锁定/灰色不可选。

5. 玩家放弃或管理员代跳过。  
   期望：玩家可自行放弃当前标段；管理员只能跳过当前小组，必须填写原因，不能代选订单。

6. 当前标段顺序走完。  
   期望：标段结束；未被选择的订单保留未选状态，不要求把订单池全部选完。

## 5. 经营页联动验收

1. 正式年份订单标段未全部完成或跳过时，玩家提交 `Q1`。  
   期望：系统拦截并提示本年订单选择尚未完成。

2. 全部应开标段完成或跳过后，玩家进入经营页。  
   期望：市场投入和订单总额由订单模块带入，相关单元格只读，不允许玩家在经营页改写。

3. 玩家交付订单。  
   期望：只能交付本组本年已选且未交付订单；交付季度必须等于当前经营季度；本季度销售收入必须等于本季度已交付订单金额合计。

4. 年末提交仍有未交付订单。  
   期望：未交付订单状态保留为 `UNFINISHED`；首版不自动处罚。

## 6. 接口联调脚本

订单模块脚本位于：

- `tests/http/sandbox-game/AdminOrder.http`

推荐顺序：

1. 管理员读取订单控制台
2. 管理员保存 `16` 个标段配置
3. 管理员生成预览订单池
4. 管理员确认订单池
5. 玩家提交 `16` 项市场投入
6. 管理员生成选单顺序
7. 管理员释放下一个标段
8. 玩家刷新订单页并选单
9. 管理员代跳过当前小组
10. 玩家交付订单

## 7. 完成判定

- 自动化测试覆盖订单生成、投入、排序、跳过、释放、选择、交付、未交付保留和 `Q1` 前置拦截。
- `.http` 脚本能按手工替换 `batchId / orderId / currentGroupId` 的方式跑通核心接口。
- 管理员订单页和玩家年度订单页能支撑现场按组轮流选单，不依赖 WebSocket，采用页面刷新或自动轮询同步状态。
