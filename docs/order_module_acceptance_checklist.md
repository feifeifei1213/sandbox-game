# 订单模块页面与联调验收清单

> 更新日期：2026-07-23
> 适用范围：贵宾服务版、生产制造版订单多轮升级验收，覆盖无固定订单数量上限、固定 `3 / 6 / 9` 资格、四轮推进、管理员/玩家页面、经营页订单前置联动和回退边界。机场版不参与多轮验收，但必须保留单轮回归验证。

## 1. 验收前提

- 后端已启动：`go run ./cmd/server -config configs/local.yaml`
- 前端已启动：在 `frontend/` 执行 `npm run dev`
- 当前联调库不是正式比赛库
- 管理员账号可登录：`admin / 123456`
- 至少存在 `2` 个未破产玩家组，且目标年份为正式年份（`1年` 起）

## 2. 管理员订单生成验收

1. 进入管理员端订单页。  
   期望：页面按操作顺序展示多年订单数量控制台/市场预测、年份与刷新、市场开启、当年控制台数量只读带入与释放顺序、订单池生成/确认、选单控制和订单池查看。

2. 配置多年订单数量控制台。  
   期望：控制台固定展示 `1~8年 × 四个市场 × 四类产品`，按 `1~3年 / 4~5年 / 6~8年` 三段组织；订单数量只接受非负整数，不设置固定最大值；该展示不受管理员最终年份配置裁剪。

3. 查看玩家端市场预测。  
   期望：玩家年度订单页可只读查看三段市场预测；预测图表和说明文字来自多年订单数量控制台及预测快照，不展示其他小组经营数据；预测图表应为贴近 Excel 的竖状柱状图，阶段下按市场分图、年份为横轴、四类订单为柱状系列。

4. 配置当年市场开启状态。  
   期望：本地市场默认开启；区域市场、全国市场、全球市场默认关闭；订单池确认前可手动开启/关闭，确认后锁定。

5. 验证市场开启优先级。  
   期望：即使多年控制台中某市场当年有订单数量，只要管理员未开启该市场，该市场仍显示“市场未开启”，不生成订单、不进入释放顺序，玩家对应 4 项投入必须填 `0`。

6. 配置当年释放顺序。  
   期望：当年订单数量从多年控制台只读带入；有效释放顺序只覆盖已开启且订单数量大于 `0` 的标段；保存按钮位于释放顺序配置区内。

7. 点击生成预览订单池。  
   期望：页面展示预览批次、随机种子、公式版本、生成数量；未确认前允许覆盖重生成。

8. 点击确认订单池。  
   期望：确认后配置锁定，不允许继续修改数量、释放顺序或覆盖订单池。

9. 查看订单池。  
   期望：默认展示当前年份全部订单，可按市场和订单类型筛选；订单编号显示 `CARD-01` 等业务编号或卡片序号，不显示数据库自增 ID 作为主编号；订单卡展示市场、订单类型、金额、数量、单价、账期和状态；金额显示为整数，且后端生成结果满足金额等于数量乘以单价，单价允许小数。

## 3. 玩家市场投入验收

1. 玩家打开 `0年` 订单页。  
   期望：显示 `0年` 不需要订单，不出现提交市场投入和选单动作。

2. 玩家打开正式年份订单页。  
   期望：订单池确认后可提交市场投入；必须一次提交完整 `16` 项，`0` 合法但缺项不合法；未开启市场仍显示对应 4 项，但输入框禁用并自动按 `0` 提交。

3. 玩家端查看市场投入上限。  
   期望：每个市场展示“无上限 / 上限 XM / 未开启”；未开启市场不允许输入，已开启市场有上限时展示上限。

4. 玩家在市场投入阶段查看订单相关区域。
   期望：市场预测和市场投入表正常可见；订单卡片、本组已选订单和交付面板均不展示。接口响应中各标段 `ordersVisible=false`，`availableOrders / lockedOrders / selectedOrders` 不返回具体订单明细。

5. 玩家提交市场投入后、管理员生成顺序或尚未释放标段前再次查看订单页。
   期望：市场投入变为只读；市场预测仍可见；订单卡片、本组已选订单和交付面板仍不展示，直到管理员释放标段并进入选单阶段。

6. 玩家提交小数市场投入或负数市场投入。
   期望：前端提示并高亮对应输入格；绕过前端提交时，服务端拒绝并提示投入必须为非负整数。

7. 玩家提交某市场 4 项投入合计超过管理员配置的单市场上限。
   期望：服务端拒绝提交，页面顶部错误条提示具体市场、合计值和上限值，并高亮对应市场。

8. 玩家提交市场投入后再次进入。
   期望：投入变为只读，不能二次修改。

## 4. 选单顺序与标段释放验收

1. 管理员在所有未破产组提交完整投入后生成选单顺序。  
   期望：缺少任何正常小组提交时禁止生成，不把缺失项按 `0` 处理；未开启市场显示为“市场未开启”且不进入开标；订单数量为 `0` 的已开启标段显示为“未配置订单”；订单数量大于 `0` 但全员 `0` 投入的标段才显示为“已跳过”。

2. 管理员只生成选单顺序但尚未释放标段。
   期望：管理员端可查看顺序；玩家端仍只看到市场预测和只读市场投入，不提前展示订单卡片、本组已选订单或交付面板。

3. 验证投入资格。
   期望：当前标段投入 `0 / 1 / 3 / 6 / 9 / 10` 分别生成 `0 / 1 / 2 / 3 / 4 / 4` 轮资格；资格按具体 `市场 + 订单类型` 计算，不按市场合计。市场龙头投入 `0` 时同样没有资格。

4. 验证基础排序和市场龙头。
   期望：`1年` 按本标段市场投入倒序；`2年` 起有资格的同市场龙头优先，非龙头同投入时按上一年度该市场全部轮次已选订单总额，再按随机结果。一个市场只产生一个龙头，该市场下全部订单类型复用。

5. 验证全部轮次顺序一次生成。
   期望：管理员端按第一至第四轮纵向展示完整顺序；后续轮次是基础顺序的资格过滤结果，不重新排序或随机；不展示“投入 >= 3”等门槛说明。未来轮次显示“待本轮开始”，空轮显示“无参与小组”。

6. 管理员释放下一个标段。
   期望：只能按开标前配置的释放顺序释放；释放后直接开始第一轮，不显示“开启第一轮”；当前标段处于选单中或下一轮待开启时，释放下一标段会被拦截。

7. 玩家按顺序选单。
   期望：未轮到的小组不能选择；已被上一小组选走的订单，在下一小组页面为锁定/灰色不可选。

8. 玩家停留在订单列表中等待自动轮询。
   期望：每 `3` 秒自动刷新状态但不出现整页 loading，不把页面滚动位置重置到顶部。

9. 玩家放弃或管理员代跳过。
   期望：玩家放弃前出现确认弹窗，不要求原因，只影响当前轮；后续仍有资格时可以继续参与。管理员只能跳过当前轮当前小组，必须填写原因，不能代选订单。

10. 第一轮结束并开启下一轮。
   期望：有第二轮参与者时标段进入下一轮待开启；管理员状态区显示当前轮次和即将开启的轮次，点击统一按钮“开启下一轮”后直接开始，不出现确认弹窗。空轮自动跳过。

11. 验证订单池不足警告。
    期望：系统按全部有效小组资格数相加得到理论最大选单机会；订单池不足时状态区显示“订单池可能提前选空”，不弹窗、不阻止生成顺序。

12. 验证订单池提前选空。
    期望：最后一张可用订单被选走后立即完成整个标段，当前轮剩余小组和未来轮次显示“订单池已选空”，不能继续开启下一轮，也不自动补单。

13. 验证有效轮次正常结束。
    期望：最后一个有效轮次结束后标段完成；剩余可用订单转为 `UNSELECTED_EXPIRED`，只保留审计记录，不进入交付、订单总额或下一年龙头统计。

14. 验证顺序生成后破产。
    期望：破产小组已选订单和已完成轮次保留；当前及未来未完成轮次显示“已破产，本轮无资格”。若其为当前小组，系统自动推进，其他小组不重排。

15. 验证重复请求和并发保护。
    期望：重复生成选单顺序不会重排或新增记录；重复开启下一轮、重复放弃和重复选单均返回明确冲突，不产生重复选择或跨轮推进；服务端根据加锁后的标段状态决定当前轮，不接受客户端伪造轮次。

16. 机场版单轮回归。
    期望：机场模板仍只生成第一轮，正数投入最多一次选单，投入 `0` 无资格；不出现第二至第四轮，也不受贵宾/生产 `3 / 6 / 9` 资格规则影响。

## 5. 经营页联动验收

1. 正式年份订单标段未全部完成或跳过时，玩家提交 `Q1`。  
   期望：系统拦截并提示本年订单选择尚未完成。

2. 全部应开标段完成或跳过后，玩家进入经营页。  
   期望：市场投入和订单总额由订单模块带入，相关单元格只读，不允许玩家在经营页改写。

3. 玩家交付订单。  
   期望：只能交付本组本年已选且未交付订单；交付季度必须等于当前经营季度；本季度销售收入必须等于本季度已交付订单金额合计。

4. 年末提交仍有未交付订单。  
   期望：未交付订单状态保留为 `UNFINISHED`；首版不自动处罚。

## 6. 接口联调脚本

订单模块脚本位于：

- `tests/http/sandbox-game/AdminOrder.http`

推荐顺序：

1. 管理员读取多年订单数量控制台。
2. 管理员保存多年订单数量控制台和市场预测说明。
3. 管理员读取年度标段配置，确认当年数量从控制台只读带入。
4. 管理员保存当年市场开启状态。
5. 管理员保存当年标段释放顺序。
6. 管理员生成预览订单池。
7. 管理员确认订单池。
8. 玩家读取市场预测。
9. 玩家提交 `16` 项市场投入。
10. 管理员生成第一至第四轮选单顺序。
11. 管理员释放下一个标段并自动开始第一轮。
12. 玩家刷新订单页并选单或放弃本轮。
13. 管理员代跳过当前轮当前小组。
14. 第一轮结束后管理员开启下一轮。
15. 玩家交付订单。

## 7. 订单专项造数边界

现有 `seed-order-scenario` 已升级为手动联调停点：保留 `1年` 订单历史，用来测试 `2年` 市场龙头；预置 `3` 个正常组和 `1` 个破产组，停在 `2年已开放、1年龙头历史已写入、2年订单数量/市场投入待手动配置`。造数能力仍只允许在独立测试库使用，不关闭正式规则校验。

执行命令示例：

```powershell
$env:GOCACHE=(Resolve-Path .go-build-cache).Path
go run ./cmd/dbtool -config configs/local.yaml -action seed-order-scenario -confirm-reset
```

推荐造数停点：

- 初始化 `4` 个玩家组，其中 `1` 个为破产组。
- 写入合法但非真实的 `0年 / 1年` 经营与平衡财报结果。
- 造出 `1年` 各市场已选订单结果，用于形成 `2年` 市场龙头。
- 停在 `2年已开放、1年龙头历史已写入、2年订单数量/市场投入待手动配置`。
- `2年` 的多年订单数量控制台、市场开启状态、标段释放顺序、订单池生成与确认均由管理员在页面上手工完成。

验收重点：

1. 管理员端能从空配置状态开始维护多年订单数量控制台，并生成三阶段市场预测。
2. 管理员端能配置 `2年` 市场开启状态；未开启市场不生成订单、不进入选单，玩家对应投入自动按 `0` 提交。
3. 管理员端能配置 `2年` 标段释放顺序，年度标段数量只读带入控制台，不能在年度配置区单独改数量。
4. 管理员端能生成并确认 `2年` 订单池，订单池确认前后锁定规则符合页面提示。
5. 玩家端能在 `2年` 市场投入前看到管理员配置后生成的市场预测。
6. `2年` 市场龙头来自 `1年` 对应市场已选订单金额，不是全市场共用龙头。
7. 新造数命令升级后，应支持手工配置投入、多轮顺序、市场龙头和订单池提前选空场景；升级前不执行本项。
8. 订单流程未完成前，经营页 `Q1` 提交仍被前置拦截。

## 8. 完成判定

- 自动化测试覆盖无固定数量上限、投入资格、基础排序、市场龙头、多轮过滤、放弃、管理员跳过、开启下一轮、订单池选空、剩余订单过期、破产资格失效、交付和 `Q1` 前置拦截。
- `.http` 脚本能按手工替换 `batchId / orderId / currentGroupId` 的方式跑通核心接口。
- 管理员订单页能纵向展示全部轮次并控制“开启下一轮”；玩家年度订单页只展示本组状态和当前轮次，不依赖 WebSocket，采用静默自动轮询同步状态。
- 玩家端市场预测为 Excel 口径竖状柱状图；市场投入阶段不提前返回或展示订单明细；订单卡片、本组已选订单和交付面板页面上仍分开展示，并统一受 `ordersVisible` 控制；自动轮询不导致页面跳顶；订单金额为整数且满足金额、数量、单价之间的乘积关系。
