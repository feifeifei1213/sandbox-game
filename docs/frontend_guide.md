# 沙盘经营系统前端开发指南（正式版）

> 更新日期：2026-03-26  
> 适用方式：基于《正式需求文档（首版）》《技术选型细化文档（Go 方向） v0.1》《接口设计文档（正式版）》与现有 Excel 风格原型，定义首版前端页面结构、交互边界和联调规范。  
> 文档定位：本文件回答“前端页面和交互应该怎么实现”，不替代视觉原型与接口文档。
> 页面范围与页面层级以 `docs/frontend_page_structure.md` 为准。

## 1. 适用范围

本指南适用于沙盘经营系统首版前端，包括：

- 玩家端经营页
- 玩家端财报页
- 管理员汇总页
- 管理员年度控制页
- 管理员初始基线页
- 管理员组数据查看页
- 异常解锁相关弹窗和日志视图

本文件不覆盖：

- 后端接口实现细节
- 桌游流程线下主持环节
- 完整电子表格引擎接入方案

---

## 2. 技术与运行基线

### 2.1 当前推荐基线

首版前端推荐采用：

- `Vue 3`
- `TypeScript`
- `Vite`
- `Vue Router`
- `Pinia`
- UI 组件库：`Ant Design Vue` 或团队统一组件库
- 单元测试：`Vitest`

### 2.2 页面实现基本判断

- 首版前端不是普通 CRUD 后台页面。
- 首版前端也不是“把 Excel 嵌进网页”的纯电子表格方案。
- 首版前端应采用：`自定义 Excel 风格页面 + 业务字段绑定 + 状态控制锁定`。

### 2.3 运行边界

- 前端所有计算结果以服务端返回为准。
- 前端仅做：
  - 必填高亮
  - 输入合法性限制
  - 提交前基础检查
  - 状态驱动的只读控制
- 前端不应自行保存“正式业务真相”。

## 3. API 客户端规范

### 3.1 目录建议

推荐按领域拆分 API 客户端：

```text
src/api/sandbox-game/
  game-config.ts
  player-operating.ts
  player-report.ts
  admin-summary.ts
  admin-control.ts
  admin-group-data.ts
  audit-log.ts
```

### 3.2 约定

- 统一使用单一请求客户端封装。
- 函数命名使用动词开头：`get/save/submit/update/open/query`。
- 请求类型、响应类型必须显式声明。
- 路径、方法、错误语义必须与 `docs/api_design.md` 保持一致。
- 前端禁止绕过 API 层直接在页面中硬编码路径。

### 3.3 关键约束

- 提交接口与草稿接口必须拆开。
- 管理员接口与玩家接口必须拆开。
- 任何页面若依赖结构性状态字段，必须优先使用接口返回状态，而不是前端本地推断。

## 5. Excel 风格页面规范

### 5.1 总体原则

- 主表必须始终是视觉主体。
- 页面应尽量还原真实 Excel 的结构分区与阅读方式。
- 不到当前阶段的区域必须“可见但锁定”。
- 锁定态、已提交态、异常解锁态必须能被用户一眼识别。

### 5.2 经营页规范

- 整页展示 `年初/Q1/Q2/Q3/Q4/年末` 区域。
- 当前开放区可编辑，其余区只读。
- 不拆成多页，不拆成多步骤向导。
- 默认空值展示为空，不自动填 `0`。
- `0` 需要由玩家显式填写。
- 阶段提交按钮要与当前阶段一致，不允许同时出现多个正式提交入口。
- 最终版经营页主表中应保留 `核对季末现金` 行，不应改造成弹窗或右侧卡片。
- `Q1/Q2/Q3/Q4` 的季度现金核对值应展示在主表对应列中。
- `期末现金` 标题位置应按最终版 Excel 的主表排布还原。

### 5.3 财报页规范

- 财报页采用与 Excel 接近的整页布局。
- 自动计算项与手工项视觉要明显区分。
- 绿色手工项边界必须与现有共识一致。
- 所得税税率采用下拉框，不允许自由输入其他值。
- 财报页仅在本年经营结束后开放。

### 5.4 右侧工作栏规范

- 右侧工作栏是辅助区，不得压过主表。
- 经营页工作栏应展示：
  - 当前阶段
  - 草稿状态
  - 提交后贷款提醒
- 季末现金核对位于经营页主表，不放在右侧工作栏。
- 财报页工作栏应展示：
  - 平衡校验结果
  - 税率说明
  - 财报提交入口

### 5.5 不推荐做法

- 不把通用电子表格引擎作为业务底座。
- 不把所有格子都做成可编辑。
- 不把复杂业务提示全部塞进右侧栏，导致主表失焦。
- 不把经营页做成普通表单页，失去 Excel 心智一致性。

### 5.6 管理员页面规范

- `admin/summary` 页面采用 Excel 风格整页布局。
- 汇总页上方为“年度汇总区”，下方为“最终排名区”。
- 年度汇总区按“组”为行、按“年份”为列组展示；每年下显示 `收入 / 利润 / 权益`。
- 年份列按 `finalYear` 动态生成，首版不提供年份切换。
- 组名右侧展示 `经营状态`；`已破产` 使用红色标签。
- 年度汇总空值显示 `--`。
- 最终排名区位于页面下方，首版仅显示 `排名 / 小组` 两列。
- 最终排名未开放时，页面展示状态提示，不单独跳转排名页。
- `admin/control` 页面只做年份推进控制，不做详细进度大盘。
- `admin/control` 页面应展示 `最终年份`、`当前开放年份`、`是否允许开放下一年` 与阻断原因提示。
- `admin/baseline` 页面采用接近 Excel 的单页模板布局，只填写一套统一初始基线数据。
- `admin/baseline` 页面提交后一次性应用到全部小组，并展示提交状态、提交人、提交时间。
- `admin/group-data` 默认打开经营页，主内容区复用玩家端页面但保持只读。
- `admin/group-data` 页面按 `小组 -> 年份 -> 页面类型` 查看数据。
- 异常解锁入口位于 `admin/group-data` 页面，前端首版不做是否可解锁的复杂预判；点击后弹出“目标类型 + 阶段 + 原因”的确认弹窗。

## 6. 路由与权限

### 6.1 路由建议

推荐至少区分：

- `/sandbox-game/player/operating`
- `/sandbox-game/player/report`
- `/sandbox-game/admin/summary`
- `/sandbox-game/admin/control`
- `/sandbox-game/admin/baseline`
- `/sandbox-game/admin/group-data`

### 6.2 权限边界

- 玩家只能访问本组页面。
- 管理员可访问全部后台页面。
- 汇总页仅管理员可见。
- 页面级权限与按钮级权限必须与后端返回角色保持一致。

### 6.3 年份标签行为

- 全部年份标签可见。
- 未开放年份可显示但不可进入，或进入后整体只读。
- `0年` 默认进入。
- `1年~最终年` 的可操作性由当前开放年份与组状态决定。

## 7. 交互与错误处理

### 7.1 提示规范

统一使用：

- 成功提示
- 错误提示
- 警告提示
- 二次确认弹窗

### 7.2 首版重点交互

- 草稿自动保存：每 5 分钟一次。
- 正式提交：用户主动触发。
- 经营页在主表内展示系统计算的季末现金核对值，供玩家线下自检，不阻断提交。
- 财报平衡失败：阻断提交并显示校验失败。
- 异常解锁：管理员必须选择解锁目标并填写原因；当目标为经营页时还必须选择回退阶段。

### 7.3 错误展示要求

- 未填项：字段高亮 + 顶部错误提示。
- 状态冲突：明确提示“当前阶段已变化”或“当前年份未开放”。
- 网络异常：提示“保存失败/提交失败”，不得静默吞错。
- 失败提示文案不能只显示技术错误码。

## 8. 状态驱动的页面控制

### 8.1 前端必须识别的结构性状态

- 年份主状态
- 当前经营阶段状态
- 财报状态
- 经营状态（是否破产）

### 8.2 推荐控制方式

- 由接口返回结构性状态字段。
- 页面基于状态控制只读、按钮显示、标签可进性。
- 不通过前端自行推演阶段推进。

### 8.3 典型页面行为

| 状态 | 页面行为 |
|---|---|
| `OPERATING + Q2_OPEN` | 年初、Q1 只读，Q2 可编辑 |
| `REPORT_PENDING` | 财报页可进入，经营页年末区只读 |
| `COMPLETED` | 本年经营与财报全部只读 |
| `BANKRUPT` | 历史可看，后续年份不可编辑 |

## 9. 与后端联动检查清单

每次功能变更至少核对：

1. API 客户端是否同步更新。
2. 页面字段是否与后端结构性字段一致。
3. 提交按钮是否与状态机一致。
4. 玩家端与管理员端权限是否一致。
5. `.http` 冒烟与页面手工回归是否覆盖到本次改动。
6. 若字段显示名变化，是否同步更新 `docs/excel_field_mapping.md`。
