# 订单模块多轮选单升级设计

> 状态：业务口径已确认，I13-02 ~ I13-07 与 I13-09 已完成；I13-08 造数命令为手动联调版，待继续完善
> 更新日期：2026-07-23
> 适用范围：贵宾服务版、生产制造版的多轮选单升级，以及全部订单模板的订单数量固定上限移除
> 不包含：造数命令升级、机场版多轮选单、订单撤销、标段重开、管理员可配置门槛

## 1. 目标与边界

本次升级解决两个问题：

1. 贵宾服务版和生产制造版的每个标段由单轮选单升级为最多四轮，玩家可参与的轮次数量由当前标段投入决定。
2. 移除订单数量控制台中按模板设置的固定业务上限，避免订单池数量不足以覆盖多轮选单机会。

稳定边界如下：

- 贵宾服务版、生产制造版采用固定 `3 / 6 / 9` 门槛，不开放管理员配置。
- 机场版暂时保持单轮选单，不套用 `3 / 6 / 9` 多轮资格。
- 贵宾服务版和生产制造版继续使用当前服务订单生成公式；生产制造版本次不新增另一套生成公式。
- 机场版继续使用机场订单生成公式。
- 全部版本的订单数量都取消固定业务上限；输入仍必须是非负整数。
- 不增加分页、隐藏技术上限、强制保底、自动补单或订单池自动扩容。
- 允许同一标段生成参数重复的订单，只要业务订单卡 ID 不同即可。
- 本次只升级订单模块；现有经营页回退、快照恢复和财报补提逻辑不重新设计。
- 造数命令在订单模块开发完成后单独升级，不属于当前设计实现任务。

## 2. 核心术语

| 术语 | 含义 |
|---|---|
| 标段 | 一个 `年份 + 市场 + 订单类型` 组合 |
| 标段投入 | 玩家在订单页为当前 `市场 + 订单类型` 提交的投入 |
| 基础顺序 | 当前标段只生成一次的完整排序，后续轮次只做资格过滤，不重新排序 |
| 轮次资格 | 根据当前标段投入确定的最多可参与轮数 |
| 市场龙头 | 上一年该市场全部订单类型已选订单金额合计最高的有效小组 |
| 订单池 | 当前标段生成并确认的一组固定订单，第一至第四轮共用 |
| 定序依据固化 | 将投入、上一年市场金额、龙头和随机结果保存为订单业务事实；不是回退快照 |

## 3. 市场投入与轮次资格

### 3.1 固定资格规则

贵宾服务版和生产制造版按当前标段的具体投入判定：

| 当前标段投入 | 是否有资格 | 最多可选订单数 | 可参与轮次 |
|---:|---|---:|---|
| `0` | 否 | `0` | 无 |
| `1 ~ 2` | 是 | `1` | 第一轮 |
| `3 ~ 5` | 是 | `2` | 第一、二轮 |
| `6 ~ 8` | 是 | `3` | 第一、二、三轮 |
| `>= 9` | 是 | `4` | 第一、二、三、四轮 |

补充规则：

- 投入必须继续遵守当前非负整数校验。
- 投入大于 `9` 仍然最多参与四轮，不产生第五轮。
- 资格按当前标段计算，不按同一市场投入合计，也不按全年投入合计。
- 每组每轮最多选择一张订单，因此每组在同一标段最多选择四张订单。
- 机场版继续沿用当前单轮规则：正数投入参与一轮，投入 `0` 无资格。

### 3.2 投入提交完整性

- 所有正常参赛且未破产小组必须先提交本年度当前订单模板下的完整投入表，管理员才能生成选单顺序。
- 不参与的标段必须显式提交 `0`；未提交不能自动按 `0` 处理。
- 不提供管理员忽略未提交小组或强制生成顺序的能力。
- 未开启市场仍由系统按现有规则提交 `0`，不参与竞标。
- 市场投入提交后继续保持不可修改。
- 市场投入存储在订单模块中，经营页只读展示汇总值。

## 4. 市场龙头与基础顺序

### 4.1 龙头定义

- 每个市场每年最多一个市场龙头，不是每个标段一个龙头。
- 同一市场下所有订单类型共享该市场龙头。
- 本年市场龙头按上一年该市场全部订单类型、全部轮次的已选订单金额合计确定。
- 龙头金额按已选订单统计，不要求订单已经交付。
- 第一正式年没有上一年线上订单，因此没有市场龙头。
- 上一年该市场没有任何已选订单时，本年没有市场龙头。
- 上一年金额并列最高时，继续沿用当前随机确定规则，并保存候选组和随机结果。
- 已破产小组不能成为本年有效市场龙头。
- 每年重新计算龙头，不沿用上一年的龙头身份。

### 4.2 龙头权限边界

- 市场龙头只影响基础选单顺序。
- 龙头不增加投入、不增加选单数量、不增加轮次资格。
- 龙头在当前标段投入为 `0` 时没有参与资格，必须从该标段全部轮次中过滤。
- 必须移除当前系统中“龙头投入为 0 仍可优先选单”的例外。

### 4.3 基础顺序生成

每个标段只生成一次基础顺序：

1. 先过滤当前标段投入为 `0`、已破产、已淘汰或未激活的小组。
2. 有资格的市场龙头排在第一位。
3. 其他小组按当前标段投入从高到低排序。
4. 投入相同时继续沿用当前规则：先按上一年该市场已选订单金额从高到低，再按随机结果收口。
5. 同一标段的第二至第四轮不重新排序、不重新随机，只从基础顺序中过滤没有该轮资格的小组。

管理员点击“生成选单顺序”时，在同一事务中完成：

- 校验所有正常小组已提交完整投入。
- 为每个市场统一计算一次市场龙头。
- 为每个标段生成一次基础顺序。
- 一次性生成该标段第一至第四轮中实际有资格的小组顺序记录。
- 固化投入、上一年市场金额、龙头身份、并列候选和随机结果。

上述记录属于订单定序业务事实，不新增第二套可恢复快照，也不跟随经营阶段提交节点生成。

## 5. 固定订单池

### 5.1 生成与使用

- 每个标段只生成并确认一次固定订单池。
- 第一至第四轮共用同一订单池，不按轮次重新生成。
- 订单被选择后立即锁定，后续小组和后续轮次不可重复选择。
- 允许订单参数重复，但业务订单卡 ID 必须唯一。
- 贵宾服务版和生产制造版使用当前服务订单生成规则。
- 机场版继续使用机场订单生成规则。

### 5.2 订单数量

- 贵宾服务版和生产制造版移除原每标段 `15` 张上限。
- 机场版移除原每标段 `28` 张上限。
- 订单数量必须为非负整数，`0` 仍表示该标段未配置订单。
- 页面、接口、后端模板注册表和生成器校验必须统一取消固定最大值。
- 不新增另一个隐藏技术上限，也不增加分页作为本次需求。

理论最大选单机会按所有有效小组在当前标段的资格数相加：

```text
理论最大选单机会 = Σ 每个有效小组的标段资格轮数
```

例如六个小组当前标段投入均为 `9`：

```text
6 个小组 × 4 轮 = 24 次最大选单机会
```

管理员生成顺序后，若订单池数量小于理论最大选单机会，状态区显示：

```text
订单池可能提前选空
```

该提示只警告，不阻止生成顺序，不要求弹窗确认。

### 5.3 订单池选空与剩余订单

- 任意轮次中最后一张可用订单被选走后，立即结束整个标段。
- 当前轮剩余小组和未来轮次不再获得选单机会，页面显示“订单池已选空”。
- 不继续开启下一轮，也不生成新订单补足机会。
- 全部有效轮次完成后仍未被选择的订单不再作为可用订单保留，统一标记为 `UNSELECTED_EXPIRED`。
- `UNSELECTED_EXPIRED` 只作为审计记录存在，不进入交付、订单总额、市场龙头、后续标段或后续年份。

## 6. 轮次推进

### 6.1 标段内流程

```text
管理员释放下一标段
  -> 系统立即开启该标段第一轮
  -> 第一轮依序选择
  -> 第一轮结束
  -> 若第二轮有资格小组且订单池未空，进入下一轮待开启
  -> 管理员点击“开启下一轮”
  -> 第二轮依序选择
  -> 按相同方式推进第三、第四轮
  -> 最后一个有效轮次结束
  -> 标段完成
```

规则：

- “释放下一标段”继续沿用现有语义，释放后直接开始第一轮，不增加“开启第一轮”按钮。
- 第二至第四轮由管理员手动点击统一按钮“开启下一轮”。
- 按钮旁必须显示当前轮次和即将开启的实际轮次。
- “开启下一轮”不增加确认弹窗。
- 如果下一轮没有任何有资格小组，系统自动跳过该空轮。
- 如果后续全部轮次都没有有资格小组，直接完成标段。
- 当前标段处于选单中或下一轮待开启时，禁止释放后续标段。
- 必须完成当前标段的全部有效轮次后，才能按原释放顺序释放下一标段。
- 不采用“所有标段先完成第一轮，再统一进入第二轮”的交错方式。

### 6.2 轮内推进

- 每次只有当前小组可以选择或放弃。
- 当前小组选择、放弃或被管理员跳过后，系统自动推进到本轮下一小组。
- 本轮最后一个小组处理完成后，系统自动结束本轮。
- 玩家选择订单继续沿用即时生效方式，不增加确认弹窗。
- 玩家选择后不可撤销，管理员也不能撤销或代选。

### 6.3 放弃与管理员跳过

- 玩家放弃只影响当前轮，不退出整个标段。
- 玩家在后续仍有资格的轮次中可以继续参与。
- 玩家放弃前显示确认弹窗，不要求填写原因。
- 放弃弹窗明确说明“只影响当前轮，后续有资格轮次仍可参与”。
- 管理员跳过只影响当前轮，继续要求填写原因。
- 不增加“退出整个标段”功能。

## 7. 破产边界

- 生成顺序前已破产小组不参与任何标段和轮次。
- 顺序生成后发生破产时，此前已经选择的订单和已经完成的轮次结果继续保留。
- 当前及未来尚未完成轮次自动标记为“已破产，本轮无资格”。
- 如果破产小组正好是当前选择小组，系统自动推进到本轮下一小组。
- 其他小组不重新排序、不补位、不重新随机。
- 系统自动取消破产小组资格不属于管理员跳过，不要求跳过原因。

## 8. 状态机设计

### 8.1 标段状态

| 状态 | 含义 |
|---|---|
| `MARKET_DISABLED` | 市场未开启 |
| `NO_ORDER_CONFIG` | 订单数量为 `0` |
| `WAITING_INVESTMENT` | 等待所有正常小组提交完整投入 |
| `SEQUENCE_READY` | 多轮顺序已生成，等待按释放顺序释放 |
| `SELECTING` | 某一轮正在选单 |
| `ROUND_READY` | 当前轮已结束，下一有效轮等待管理员开启 |
| `COMPLETED` | 全部有效轮次完成或订单池选空 |
| `SKIPPED` | 有订单但全部有效小组当前标段投入均为 `0` 等原因导致无需开标 |

### 8.2 标段状态流转

| 当前状态 | 触发 | 结果 |
|---|---|---|
| `WAITING_INVESTMENT` | 全部正常小组提交投入并生成顺序 | `SEQUENCE_READY` |
| `WAITING_INVESTMENT` | 全部有效小组投入为 `0` | `SKIPPED` |
| `SEQUENCE_READY` | 管理员释放标段 | 第一轮 `SELECTING` |
| `SELECTING` | 当前轮结束，存在后续有效轮次且订单池未空 | `ROUND_READY` |
| `ROUND_READY` | 管理员开启下一轮 | 下一轮 `SELECTING` |
| `SELECTING` | 订单池选空 | `COMPLETED`，原因 `ORDER_POOL_EXHAUSTED` |
| `SELECTING` | 最后一个有效轮次结束 | `COMPLETED`，原因 `ALL_ROUNDS_COMPLETED` |
| `ROUND_READY` | 后续资格因破产等原因全部消失 | `COMPLETED`，原因 `NO_ELIGIBLE_PARTICIPANTS` |

### 8.3 轮次顺序状态

| 状态 | 含义 |
|---|---|
| `WAITING` | 有资格，等待本轮开始或等待轮到本组 |
| `CURRENT` | 当前轮到该小组 |
| `SELECTED` | 本轮已选择一张订单 |
| `PASSED` | 玩家本轮已放弃 |
| `ADMIN_SKIPPED` | 管理员本轮已跳过 |
| `INELIGIBLE_BANKRUPT` | 顺序生成后破产，本轮资格自动失效 |

玩家没有某轮顺序记录时，页面派生显示“本轮无资格”，不需要为所有无资格小组预生成占位记录。

## 9. 数据模型调整

### 9.1 `sg_market_bidding_state`

建议增加：

| 字段 | 用途 |
|---|---|
| `current_round_no` | 当前或最近处理轮次，`0` 表示尚未释放 |
| `completion_reason` | `ALL_ROUNDS_COMPLETED / ORDER_POOL_EXHAUSTED / NO_ELIGIBLE_PARTICIPANTS` 等完成原因 |

`segment_status` 增加 `ROUND_READY`。

### 9.2 `sg_market_selection_order`

建议增加：

| 字段 | 用途 |
|---|---|
| `round_no` | `1 ~ 4`，机场单轮固定为 `1` |

唯一约束调整为：

- `年份 + 市场 + 订单类型 + 轮次 + 小组` 唯一。
- `年份 + 市场 + 订单类型 + 轮次 + 顺序号` 唯一。

现有 `market_investment / previous_market_order_amount / is_market_leader / rank_basis_json` 继续保存定序依据。多轮记录必须来自同一基础顺序，不能逐轮重新计算。

### 9.3 `sg_group_order_selection`

建议增加：

| 字段 | 用途 |
|---|---|
| `round_no` | 该订单在哪一轮被选择 |
| `selection_order_id` | 对应本轮选单顺序记录 |

约束调整为：

- 移除“一个小组在一个标段只能有一条选择记录”的旧唯一约束。
- 保留 `order_id` 全局唯一，确保一张订单只能被一个小组选择。
- `selection_order_id` 唯一，确保一个轮次机会最多产生一次选择。

### 9.4 `sg_order_pool`

- 订单池状态增加 `UNSELECTED_EXPIRED`。
- 标段正常完成且仍有可用订单时，批量转为 `UNSELECTED_EXPIRED`。
- 该状态订单只可审计查看，不能再次选择、交付或汇总。

### 9.5 迁移原则

- 当前环境数据由测试造数产生，不需要为旧业务数据设计复杂兼容迁移。
- 迁移仍需幂等，并同步 ORM、Repository、测试建表兜底和正式打包脚本。
- 客户端不能提交权威 `roundNo` 决定当前轮；后端必须从加锁后的标段状态读取当前轮次。

## 10. 并发与幂等

- 生成顺序、释放标段、开启下一轮、选择、放弃和管理员跳过都必须在事务中锁定当前标段状态。
- 同一年度只能成功生成一次选单顺序；重复请求不得重排或新增重复轮次记录。
- 已释放标段不能再次释放。
- 已开启轮次不能再次开启，已结束轮次不能恢复为进行中。
- 选择订单时同时锁定当前顺序记录和目标订单，防止重复选择。
- 玩家或管理员请求中的轮次只可用于一致性校验，不能覆盖服务端当前轮次。
- 页面重复点击、网络重试和并发轮询不得造成重复选单、重复推进或跨轮操作。

## 11. 管理员端设计

沿用当前订单管理页结构：上方标段概览，下方显示当前选中标段的选单顺序。

下方顺序区纵向展示：

```text
第一轮选单顺序
第二轮选单顺序
第三轮选单顺序
第四轮选单顺序
```

规则：

- 不使用 Tab、分页或独立轮次页面。
- 管理员可以查看所有轮次和所有小组顺序。
- 不展示“投入 >= 3 / 6 / 9”等资格说明文字。
- 每轮继续展示：顺序、小组、标段投入、上一年市场订单金额、市场龙头、状态、本轮所选订单。
- 未来轮次显示“待本轮开始”；没有参与小组的轮次显示“无参与小组”。
- 状态区显示当前轮次、下一轮和订单池剩余数量。
- 下一轮存在时显示统一按钮“开启下一轮”，不使用“开始第二轮”等逐轮文案。
- 订单池不足时在状态区显示“订单池可能提前选空”，不弹窗、不阻止。

## 12. 玩家端设计

玩家端页面结构继续沿用现有订单页布局，不新增合并后的“本组订单与交付”大模块。订单卡片、本组已选订单、交付面板在页面上仍保持分开展示；本次只统一它们的业务可见性口径。

玩家端只展示：

- 当前标段。
- 当前轮次。
- 本组当前轮次状态。
- 本组已经选择的订单。
- 当前仍可选择的订单池。

玩家端不展示：

- 其他小组投入。
- 其他小组完整选单顺序。
- 未来轮次参与小组名单。
- `3 / 6 / 9` 资格门槛说明。

状态文案包括：

- `等待管理员开始本轮`
- `等待选择`
- `当前选择`
- `本轮已选择`
- `本轮已放弃`
- `本轮已被管理员跳过`
- `本轮无资格`
- `已破产，本轮无资格`
- `订单池已选空`

玩家和管理员页面继续使用当前轮询机制。轮询必须静默局部更新，不进入整页加载态，不改变滚动位置，不把页面刷新到顶部。

### 12.1 玩家端订单明细可见性

玩家填写市场投入时，可以看到市场预测和市场投入表，但不能看到具体订单卡、已选订单明细或交付面板。市场预测是投入决策依据，订单明细属于开标后的业务结果，两者必须分开。

后端玩家年度订单视图必须提供显式字段 `ordersVisible`，由服务端按标段状态计算，前端不得只靠页面隐藏来保护订单信息：

- `ordersVisible=false`：市场投入阶段、等待其他小组提交投入、已生成选单顺序但标段尚未释放、市场未开启、未配置订单、流程跳过等状态。此时后端不得向玩家接口返回具体订单池明细，包括 `availableOrders`、`lockedOrders`、`selectedOrders` 中的订单金额、数量、单价、账期、订单编号等信息；前端按现有页面结构隐藏订单卡片区、本组已选订单区和交付面板区。
- `ordersVisible=true`：管理员释放标段并进入过选单阶段后，包括 `SELECTING`、`ROUND_READY` 以及由实际选单流程结束产生的 `COMPLETED`。此时前端仍按原页面位置分别展示订单卡片、本组已选订单和交付面板，不做视觉合并。

补充边界：

- 市场预测接口和年度订单视图中的市场开启状态、投入上限、投入提交状态可以在市场投入阶段正常返回。
- 已被其他小组选择的订单在可见后仍只作为灰色不可选订单展示，不返回选中组。
- 交付面板与订单明细使用同一可见性口径；订单模板暂不支持交付时，仍按既有置灰或提示口径处理。
- 该规则属于信息可见性与接口安全要求，不改变市场投入、选单顺序、订单归属、交付、经营页联动或财报公式。

## 13. 回退、快照与定序依据边界

- 单组退回重提和恢复快照不修改订单页已提交的市场投入。
- 回退不重新计算轮次资格，不重算市场龙头，不重排顺序，不重开轮次，不重新生成订单池。
- 已选订单和选单轮次结果继续保留。
- 目标阶段及后续阶段的旧订单交付记录继续按回退 / 快照恢复规则保留为历史留痕或草稿参考，但不直接作为当前有效交付；对应订单恢复为待交付 / 可重新交付，等待重新经营后由玩家重新确认。
- 订单交付自动生成销售收入时，经营页销售收入只按当前有效交付记录汇总；退回重提或恢复快照带回的旧销售收入不直接进入新的正式提交。
- 订单顺序中的投入、龙头和随机依据属于定序业务记录，不是另一套可恢复快照。
- 现有全局快照节点继续保留：订单池确认、标段完成、开放下一年等；本次不新增全局恢复能力。
- 存在正在选单或下一轮待开启的标段时，阻止与订单竞标事实冲突的回退或恢复操作。

## 15. 验收基线

- 投入 `0 / 1 / 3 / 6 / 9 / 10` 分别得到 `0 / 1 / 2 / 3 / 4 / 4` 轮资格。
- 龙头投入 `0` 时无资格；龙头投入为正时只改变排序，不改变轮数。
- 一个市场只确定一个龙头，同市场全部标段复用。
- 后续轮次是基础顺序过滤结果，不发生重排或重新随机。
- 玩家放弃第一轮后，只要仍有资格，可以参与第二轮。
- 管理员跳过只影响当前轮，并继续强制填写原因。
- 第一轮随标段释放自动开始，第二至第四轮由管理员点击“开启下一轮”。
- 空轮自动跳过，订单池选空立即结束整个标段。
- 未选订单在标段完成后变为 `UNSELECTED_EXPIRED`，不参与后续业务。
- 全部模板的订单数量可超过原 `15 / 28` 上限并正常生成。
- 顺序生成后小组破产，未完成轮次自动失效，已选订单和历史结果保留。
- 回退和快照恢复不改变市场投入、选单顺序、轮次结果和订单归属。
- 玩家市场投入阶段只展示市场预测和投入表；订单卡片、本组已选订单和交付面板保持页面分开展示，但必须统一受 `ordersVisible` 控制，且后端在不可见时不返回订单明细。
- 自动轮询不触发整页加载，不重置管理员或玩家页面滚动位置。
