## 3. 已确认共识

### 3.1 项目定位与首版范围

- `已确认`
- 本项目首版以公司活动使用为目标，教育和演练意义更强。
- 首版目标是先做出“可调试初版系统”，优先保证规则正确、流程可走通。
- 首版只做：`Excel 已承载的规则 + 少量必要流程控制`。
- 当前桌游纸面流程暂不完整电子化，但系统设计应尽量不阻断后续电子化扩展。

### 3.2 角色与数据权限

- `已确认`
- 系统角色分为：
  - 玩家组账号
  - 管理员账号
- 总共有 `10` 个参赛组账号。
- 每组在系统中按 `1 个操作账号` 建模。
- 玩家之间数据隔离，不能查看彼此经营数据。
- 管理员可查看所有组数据。
- 汇总页仅管理员可见。
- 管理员允许通过普通通知向全体公开赛事事件信息，例如 `第一小组已破产`；这属于赛事信息公开，不等同于开放经营明细。

### 3.2.1 首版登录闭环

- `已确认`
- 系统提供统一登录页。
- 用户通过用户名和密码登录。
- 系统根据账号角色自动跳转，不要求用户手动选择角色。
- 玩家登录成功后默认进入 `0年经营`。
- 管理员登录成功后默认进入管理端首页；首版默认落在 `汇总页`。
- 系统提供退出登录动作，退出后回到统一登录页。
- 首版登录仅做最小认证闭环，不扩展复杂账号管理能力。

### 3.3 年份与年度定位

- `已确认`
- 存在 `初始基线`、`0年经营/财报`、`1年~最终年经营/财报`。
- `初始基线`：
  - 由管理员录入或确认
  - 提交后锁定，不可修改
- `0年`：
  - 是引导年 / 非排名年
  - 玩家可正常填写和提交
  - 参与到 `1年` 的数据传递
  - 不进入正式汇总和最终排名
- `1年 ~ 最终年`：
  - 为正式比赛年
  - 进入汇总
  - 参与最终胜负判定

### 3.4 年度推进与阶段推进

- `已确认`
- 季度推进由各组自行决定，通过阶段提交推进。
- 年度推进不由玩家决定，由管理员统一开放下一年。
- `0年` 与正式年份流程一致，主持人在线下讲解，不在系统内增加特殊“教学模式”。
- 年份标签页全部可见，未开放年份不可进入。

### 3.4.1 单组演练支持边界

- `已确认`
- 单组演练库 / 单组演练模式属于开发、测试、联调、验收支持能力，不改变正式比赛规则。
- 正式比赛中，管理员开放下一年仍要求“全部未破产组完成当前开放年份财报”。
- 推荐通过“正式比赛库 / 多组演练库 / 单组演练库”分离来支持不同用途。
- 单组演练环境推荐仅初始化 `1` 个管理员账号与 `1` 个玩家组账号，便于重复跑 `0年 -> 最终年` 主链。

### 3.4.2 赛前初始化小组数量

- `已确认`
- 需要支持赛前初始化可配置小组数量。
- 不需要支持比赛进行中动态增减小组数量。
- 初始化完成后，系统以后端已初始化的小组主数据作为唯一运行依据。
- 首版建议直接以后端 `sg_group` 实际记录数推断 `initialized` 与 `groupCount`。
- 管理员提交初始基线时，按当前已初始化的小组集合进行扇出应用。
- 汇总页、最终排名区、组数据页、通知与奖惩目标范围，均按实际初始化的小组数据动态适配。
- 若需变更小组数量，应重新初始化新的比赛环境或新的比赛库。

### 3.5 玩家端页面方向

- `已确认`
- 玩家端经营页采用高保真 Excel 风格整页布局。
- 玩家端财报页也采用高保真 Excel 风格整页布局。
- 首页默认进入 `0年经营`。
- 页面中所有阶段区域尽量完整展示，不拆成多个碎页面。
- 未开放阶段的区域保持可见，但输入格为锁定态，不可编辑。
- 右侧允许存在轻量工作栏，但主表必须是页面主体，不能破坏 Excel 感。
- 玩家端右侧工作栏顶部应放置通知区，优先展示管理员最新通知。

### 3.6 经营页提交流程

- `已确认`
- 不做单独“年初提交”。
- `Q1 提交` 时一并提交 `年初区 + Q1 区`。
- `Q2/Q3/Q4` 各自单独提交。
- `年末区` 单独提交。
- 本年经营全部完成后，才开放本年财报页。

### 3.7 提交校验规则

- `已确认`
- 阶段提交时，仅校验当前阶段范围内的手工必填项。
- 已提交且已锁定的历史阶段，不重复进行必填完整性校验。
- 具体为：
  - `Q1 提交`：校验 `年初 + Q1`
  - `Q2 提交`：只校验 `Q2`
  - `Q3 提交`：只校验 `Q3`
  - `Q4 提交`：只校验 `Q4`
  - `年末提交`：只校验 `年末区手工项`
- 所有填写项默认空值，`0` 必须由用户显式填写。
- 首版不做重型“校验列表面板”，只做：
  - 顶部错误提示
  - 未填项高亮

### 3.8 现金核对与阶段提醒

- `已确认`
- 经营页主表保留“核对季末现金”展示行。
- 系统展示各季度对应的季末现金计算值，供玩家线下自检。
- 系统不采集现场现金，也不因现金差异阻断提交。
- 每个季度提交后，系统提醒玩家关注贷款更新。
- 该提醒仅为提醒，不做强制拦截。
- 管理员可向全体或单组发送普通通知，允许自由文本。
- 普通通知可用于流程提醒、赛事播报与现场主持说明。
- 奖励 / 罚款不再由玩家手动填写，改为管理员按 `组 + 年 + 季` 下发。
- 经营页中的 `额外支出 / 罚款`、`额外收入 / 奖励` 保留 Excel 位置，但改为玩家只读、系统自动带入。
- `折现费用` 继续由玩家填写。

### 3.9 财报页规则

- `已确认`
- 财报页只有在本年经营结束后才开放。
- 财报页中自动带出 Excel 可计算结果。
- 首版财报页以当前 Excel 中绿色单元格定义手工输入边界。
- 当前已确认的财报手工项包括：
  - 在制品
  - 成品
  - 材料
  - 所得税税率
- 所得税税率使用下拉框，选项限制为：
  - `0.25`
  - `0.15`
  - `0`
- 财报提交后，本年度完成。
- 财报提交时必须校验：
  - `总资产 = 总负债 + 总权益`

### 3.10 汇总页与胜负规则

- `已确认`
- 汇总页属于管理员端的一部分。
- 汇总页正式口径来自各组各年“已提交财报”的结果。
- 汇总页当前核心指标为：
  - 收入
  - 利润
  - 权益
- 汇总页从 `1年` 开始显示，不显示 `0年`。
- 汇总页采用同页双区结构：
  - 上方为年度汇总区
  - 下方为最终排名区
- 未满足最终排名开放条件时，最终排名区显示状态提示，不单独跳转页面。
- 当前胜负规则可按：
  - 最终年份 `所有者权益最高` 的公司获胜
- 该规则与补充规则文档一致，可作为当前正式共识使用。

### 3.11 管理员端范围

- `已确认`
- 首版管理员端菜单范围为：
  - 汇总
  - 年度控制
  - 通知与奖惩
  - 初始基线
  - 组数据
- 管理员端不做导出功能。
- 管理员端不做复杂图表大屏。
- 管理员端不做进度总控大盘，现场进度可线下询问。
- 初始基线页采用共享模板单页录入，不按组分别录入。

### 3.12 年度控制

- `已确认`
- `最终年份` 是配置项，由管理员设定。
- `当前开放年份` 是运行时状态，由管理员控制。
- 这两个概念不是一回事，必须分开建模。
- 管理员可以手动开放下一年。

### 3.13 异常处理方式

- `已确认`
- 首版不做通用历史纠错引擎。
- 首版不做字段级回滚与任意快照恢复。
- 首版采用 `定向异常解锁` 机制。
- 异常解锁规则当前共识为：
  - 只有管理员可执行
  - 只针对 `某组 + 某年`
  - 只允许在 `下一年尚未开放前` 执行
  - 管理员必须选择解锁目标：`OPERATING / REPORT`
  - 当目标为 `OPERATING` 时，必须再选择 `Q1 / Q2 / Q3 / Q4 / YEAR_END`
  - 仅允许对已正式提交的目标阶段或财报结果执行异常解锁
  - 若回退经营页，后续经营阶段与财报结果失效，但原值保留为 `失效草稿`
  - 若回退财报页，只回收财报结果，不回退经营页已生效阶段
  - 汇总结果同步失效
  - 管理员必须填写解锁原因
  - 系统需保留解锁记录

### 3.14 破产规则与后续行为

- `已确认`
- 当前破产条件为：
  - 在经营阶段提交节点，若现金流断裂，则破产
  - 在最终年份，若所有者权益为负，则破产
- 破产后：
  - 该组后续所有年份和财报不可再填写
  - 已提交历史数据保留
  - 玩家可查看历史数据，但不可编辑
  - 管理员汇总页标记该组“已破产”

### 3.15 已明确不纳入首版

- `已确认`
- 不做导出
- 不做通用历史纠错引擎
- 不做字段级回滚与任意快照恢复
- 不做复杂排名图表或大屏
- 不把去年规则文档中的认证、小巨人、贷款上限等完整电子化
- 不把桌游纸面流程整体电子化
- 不做整年直接回退到 `Q1_OPEN`

## 4. 原待确认项收口结果

以下内容原本属于“待确认项”，经本轮讨论后，已形成当前首版正式共识。

### 4.1 最小状态机定义

- `已确认`
- 年份主状态按以下主链定义：
  - `未开放 -> 经营中 -> 待财报 -> 财报中 -> 已完成`
- `已破产` 作为覆盖态处理，不再参与正常年份推进。
- `异常解锁` 不是新的主状态，而是管理员动作：把某组某年恢复到“可修改且待重新提交”的状态。
- 下一步只需要把这套结论整理成正式状态表，无需再就方向本身反复讨论。

### 4.2 异常解锁后的提交覆盖规则

- `已确认`
- 解锁后重新提交，以当前最新提交结果覆盖生效。
- 首版不做完整历史提交快照版本库。
- 系统保留操作日志与提交日志，用于审计和追溯。

### 4.3 汇总页是否直接显示排名序号

- `已确认`
- 首版不展示过程中的实时排名。
- 在最终年份完成后，管理员汇总页可展示最终排名。
- 排名依据为最终年份 `所有者权益` 由高到低。

### 4.4 已破产状态的展示方式

- `已确认`
- 汇总页增加单独 `经营状态` 列。
- 已破产组以红色 `已破产` 标签展示。
- 首版不采用整行染色作为唯一表达方式。

### 4.5 通知与奖惩改造

- `已确认`
- 玩家端右侧工作栏顶部新增通知区，优先展示管理员最新通知。
- 普通通知由管理员发送，可发全体或单组，可为自由文本。
- 管理员允许向全体广播赛事事件信息，例如 `第一小组已破产`。
- 奖励 / 罚款不再由玩家手动填写，改为管理员按 `组 + 年 + 季` 结构化下发。
- 经营页中 `额外支出 / 罚款`、`额外收入 / 奖励` 保留 Excel 位置，但改为玩家只读、系统自动带入。
- `折现费用` 继续由玩家填写。
### 4.6 自动保存失败时的交互

- `已确认`
- 首版自动保存采用轻量方案：每 `5` 分钟自动保存一次草稿。
- 季度提交 / 年末提交 / 财报提交仍是唯一正式提交动作。
- 首版不做复杂的自动保存失败交互设计：
  - 不做持续红色失败状态条
  - 不做离开页面的未保存提醒
- 这意味着首版更偏“草稿兜底”，而不是“强可靠协同编辑”。

### 4.7 经营页与财报页右侧工作栏是否区分内容

- `已确认`
- 两类页面的右侧工作栏采用 `同布局、分内容` 方案。
- 经营页工作栏偏向：
  - 阶段状态
  - 季末现金展示说明
  - 贷款提醒
- 财报页工作栏偏向：
  - 平衡校验
  - 税率说明
  - 财报提交

### 4.8 正式技术方案与数据存储粒度

- `已确认`
- 首版采用 `轻中型 Web 方案`。
- 数据存储以 `业务字段` 为主，不按 Excel 每个单元格直接建库存储。
- 前端通过字段到页面位置的映射来还原 Excel 风格。

### 4.9 Excel 公式的正式实现策略

- `已确认`
- 当前以确认版 Excel 作为 `规则基线`。
- 系统不直接把 Excel 当运行引擎，而是按 `业务字段 + 计算规则` 实现。
- 每个关键计算字段都应保留对应的 Excel 来源说明，保证可追溯。
- 若后续只是少量公式调整，应尽量通过集中修改规则映射或计算逻辑完成。
- 若变更已经影响到：
  - 字段结构
  - 流程状态
  - 汇总口径
  - 跨表联动语义
  则应按 `需求变更` 重新确认，不能视作普通公式微调。

### 4.10 财报页是否需要更贴近 Excel 的原始布局

- `已确认`
- 财报页要求高保真贴近 Excel。
- 但首版不要求像素级 `1:1` 复刻。
- 验收重点是：
  - 主表结构接近
  - 色块和手工格位置接近
  - 自动计算区与说明区关系清晰

### 4.11 异常解锁后财报与汇总的失效规则

- `已确认`
- 若某组某年已完成财报提交，之后又被管理员执行异常解锁，则：
  - 该年财报结果自动失效
  - 该年汇总数据临时撤回
  - 若为经营页异常解锁，玩家需重新完成该年的后续经营提交，再重新提交财报
  - 若为财报页异常解锁，玩家只需重新提交财报
  - 财报重提成功后，该年数据再重新计入汇总

### 4.12 异常解锁目标粒度补充

- `已确认`
- 当前“按年份通用解锁”的口径不足以满足管理员现场纠错。
- 正式需求新增：异常解锁需支持目标类型 `OPERATING` / `REPORT`。
- 若管理员选择 `OPERATING`，系统必须继续要求选择回退阶段：`Q1 / Q2 / Q3 / Q4 / YEAR_END`。
- 若管理员选择 `OPERATING`，系统不得仅因为财报页仍可编辑就拒绝解锁经营页。
- `OPERATING` 解锁后，目标阶段之前的结果保持有效，目标阶段重新开放，后续经营阶段与财报结果失效。
- `REPORT` 解锁后，只回收财报结果，不额外放开经营页已锁定区。
- “整年直接回到 Q1_OPEN” 与“定向异常解锁”不是同一能力，暂不并入本轮，后续单独讨论。

### 4.13 失效草稿规则

- `已确认`
- 经营页回退到 `Q2` 时：
  - `Q1` 保持有效且只读
  - `Q2` 重新开放可编辑
  - `Q3 / Q4 / 年末 / 财报` 不清空原值，但全部转为 `失效草稿`
- `失效草稿` 不计入：
  - 当前有效经营结果
  - 当前有效财报结果
  - 管理员汇总
  - 下一年的正式结转
- 玩家重新提交到对应阶段后，该阶段结果才重新恢复有效。
