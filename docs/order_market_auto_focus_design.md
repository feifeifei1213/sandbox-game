# 订单竞标市场自动聚焦开发设计

> 日期：2026-07-28
> 状态：已实现，并补充选单结束态展示口径
> 适用范围：订单模块竞标控制阶段的管理员端和玩家端市场展示焦点
> 不改变：订单释放顺序、选单顺序、轮次资格、订单池、订单归属、交付、市场龙头和历史订单事实

## 1. 背景问题

当前订单竞标流程已经按标段释放顺序推进，但页面焦点仍以“用户手动选择市场”为主，导致真实流程与页面展示脱节。

典型问题：

1. 当前真实开标标段已经进入 `区域市场 / 代办过检`，页面刷新后管理员端“控制市场”又回到 `本地市场`。
2. 玩家端当前市场订单处理完后，需要手动点击下一个市场，才能看到后续竞标进度。
3. 管理员端当前市场结束后，也需要手动在“控制市场”下拉框切换到下一个市场，操作链路不连贯。
4. 当 `ROUND_READY` 等待下一轮时，页面不能误跳到后续市场；该状态仍属于当前标段未完成。

本优化的目标是让页面市场焦点跟随真实订单竞标流程，而不是让管理员和玩家靠记忆手动切市场。

## 2. 核心定义

### 2.1 关注标段

关注标段指当前页面最应该展示给用户的订单标段。

页面从全部市场、全部标段中按优先级寻找一个关注标段，再把市场焦点切换到该标段所在市场。

### 2.2 关注市场

关注市场指关注标段所在市场，即 `focusMarketCode`。

例如：

```text
#5 区域市场 / 代办过检 / SELECTING
```

则：

```text
focusMarketCode = REGIONAL
```

## 3. 关注标段优先级

首版按以下优先级选择关注标段：

| 优先级 | 标段状态 | 含义 | 是否自动聚焦 |
|---|---|---|---|
| 1 | `SELECTING` | 正在选单，存在当前小组 | 是 |
| 2 | `ROUND_READY` | 当前轮已结束，等待管理员开启下一轮 | 是，且不得跳走 |
| 3 | `SEQUENCE_READY` / `WAITING_RELEASE` | 顺序已生成或等待释放，是下一步应处理标段 | 是 |
| 4 | 其他非终态 | 暂不作为首版自动聚焦目标 | 否 |
| - | `COMPLETED` / `SKIPPED` / `MARKET_DISABLED` / `NO_ORDER_CONFIG` | 已完成、已跳过或无需处理 | 否 |

同一优先级内，按 `releaseSequenceNo` 从小到大选择最靠前标段。

## 4. 管理员端规则

管理员端是流程推进者，采用“强跟随”规则。

### 4.1 自动聚焦触发时机

管理员端在以下时机执行自动聚焦：

1. 进入订单管理页或刷新页面后。
2. 切换到竞标控制页签并加载竞标状态后。
3. 点击“释放下一个标段”成功后。
4. 点击“开启下一轮”成功后。
5. 点击“跳过当前小组”成功后。
6. 竞标控制页签静默轮询刷新后。

### 4.2 自动聚焦行为

管理员端自动聚焦时：

1. 从全年标段列表中按优先级找关注标段。
2. 若关注市场与当前 `controlForm.marketCode` 不一致，则自动切换控制市场。
3. 切换控制市场后，必须重新加载该市场的选单状态，避免下拉框和状态卡错位。
4. 若关注标段存在，则下方选单顺序表默认选中该标段。

### 4.3 不自动跳走的边界

如果当前市场内仍存在：

```text
SELECTING
ROUND_READY
```

说明当前市场当前标段仍未完成，页面应保持在当前市场，不跳到后续市场。

尤其是 `ROUND_READY`：

```text
本地市场 / 两舱贵宾 / ROUND_READY
```

表示等待管理员开启下一轮，不是标段完成，不能自动切到区域市场。

## 5. 玩家端规则

玩家端是流程参与者和观察者，采用“初始化强跟随、轮询弱跟随”规则。

### 5.1 自动聚焦触发时机

玩家端在以下时机执行自动聚焦：

1. 进入订单页或刷新页面后。
2. 年度订单视图加载成功后。
3. 玩家选择订单成功并刷新视图后。
4. 玩家放弃本轮成功并刷新视图后。
5. 自动轮询刷新后。

### 5.2 自动聚焦行为

玩家端自动聚焦时：

1. 从全部市场、全部标段中按优先级找关注标段。
2. 页面初始化或切换年份后，若存在关注标段，直接切到关注市场。
3. 自动轮询刷新时，若当前市场已经没有 `SELECTING / ROUND_READY / SEQUENCE_READY / WAITING_RELEASE` 等流程关注点，才切到关注市场。
4. 若当前市场仍有 `SELECTING / ROUND_READY`，不跳走，避免玩家查看当前轮次时被页面抢焦点。

### 5.3 玩家手动查看历史的保护

首版不增加开关，也不引入复杂时间窗口。

采用简单保护规则：

```text
如果当前市场仍有可关注标段，则不自动切走；
只有当前市场已经没有可关注标段，而其他市场存在更高优先级关注标段时，才自动切换。
```

这样既能在刷新后自动定位到真实开标市场，也不会在玩家查看仍有关联流程的市场时频繁跳动。

## 6. 实现方案

### 6.1 通用判断

前端新增/复用本地辅助函数，按标段状态和释放顺序计算关注市场。

伪代码：

```text
resolveFocusMarketCode(marketsOrSegments):
  flatten all segments
  find first SELECTING by releaseSequenceNo
  else find first ROUND_READY by releaseSequenceNo
  else find first SEQUENCE_READY / WAITING_RELEASE by releaseSequenceNo
  else return null
```

### 6.2 管理员端落点

建议落点：

- `frontend/src/stores/admin-order.ts`
- `frontend/src/views/sandbox-game/admin/order/AdminOrderPage.vue`

管理员端实现要点：

1. 在 store 中基于已加载的全年订单配置/标段列表计算 `focusMarketCode`。
2. 增加 `syncControlMarketToOrderFocus()`，用于将 `controlForm.marketCode` 同步到关注市场。
3. 在页面初始化、竞标控制轮询、释放、开启下一轮、跳过后调用同步函数。
4. 如果同步函数改变了 `controlForm.marketCode`，必须重新调用 `loadSelectionStatus()`。
5. 页面选单顺序表跟随 `currentSegment` 或关注标段更新选中行。

### 6.3 玩家端落点

建议落点：

- `frontend/src/stores/player-order.ts`
- `frontend/src/views/sandbox-game/player/order/PlayerOrderPage.vue`

玩家端实现要点：

1. 在 store 中基于 `currentView.markets[].segments[]` 计算关注市场。
2. `loadYearView()` 成功后按触发模式同步 `selectedMarketCode`。
3. 初始化/年份切换使用强同步，刷新后直接定位真实开标市场。
4. 静默轮询使用弱同步，当前市场仍有流程关注点时不切走。
5. 玩家手动点击市场时仍允许自由查看；后续只有当前市场无关注点时才自动跟随。

## 7. 验收场景

### 7.1 管理员端刷新保持当前开标市场

前置：

```text
区域市场 / 代办过检 = SELECTING
当前组 = 第二组
```

操作：

```text
刷新管理员订单页
```

期望：

```text
控制市场 = 区域市场
当前选单标段 = 区域市场 代办过检
当前小组 = 第二组
标段列表高亮 #5
不回到本地市场 #1
```

### 7.2 玩家端刷新保持当前开标市场

前置：

```text
区域市场 / 代办过检 = SELECTING
```

操作：

```text
玩家刷新订单页
```

期望：

```text
市场自动切到区域市场
展示区域市场 / 代办过检
轮到本组时可直接选择或放弃
未轮到本组时显示只能查看
```

### 7.3 当前市场完成后自动跳到下一个市场

前置：

```text
本地市场最后一个有效标段完成
下一个释放顺序为区域市场 / 代办过检
```

期望：

```text
管理员端自动切到区域市场
玩家端在当前市场无关注点时自动切到区域市场
```

### 7.4 `ROUND_READY` 不跳走

前置：

```text
本地市场 / 两舱贵宾 = ROUND_READY
下一轮 = 第 2 轮
```

期望：

```text
管理员端仍停在本地市场
玩家端仍展示本地市场 / 两舱贵宾
不自动跳到区域市场
```

## 8. 风险与边界

1. 本功能只改变页面展示焦点，不改变订单业务事实。
2. 自动聚焦必须以 `releaseSequenceNo` 为准，不按固定市场顺序猜测。
3. 管理员端切换市场后必须重新加载该市场状态，避免 UI 状态错位。
4. 玩家端轮询不能频繁抢焦点，必须保留“当前市场仍有关注点不跳走”的保护。
5. 若现有管理员端配置数据无法完整提供全年标段状态，再考虑后端补 `focusMarketCode`，首版优先不新增接口。

## 9. 选单结束态展示补充

### 9.1 背景问题

多轮选单顺序是一次性生成的，因此后续轮次和后续小组会提前存在 `WAITING` 记录。

当订单池在前面轮次被选空时，标段会进入：

```text
segmentStatus = COMPLETED
completionReason = ORDER_POOL_EXHAUSTED
availableCount = 0
```

此时后续尚未执行的 `WAITING / CURRENT` 记录不再表示“还会轮到该小组选择”，而是表示“理论机会存在，但因订单池已空不会执行”。

如果页面继续把这些记录显示为“待选择”或“当前选择”，会让管理员或玩家误以为流程尚未结束、仍需开启下一轮或跳过小组。

### 9.2 展示口径

首版只修正展示语义，不新增数据库枚举，不重写历史选单顺序，不把未执行机会伪装成“已放弃”或“管理员跳过”。

展示规则：

| 标段状态 | 完成原因 | 原选单状态 | 页面展示 |
|---|---|---|---|
| `COMPLETED` | `ORDER_POOL_EXHAUSTED` | `WAITING / CURRENT` | `未执行（订单池已空）` |
| `COMPLETED` | `NO_ELIGIBLE_PARTICIPANTS` | `WAITING / CURRENT` | `未执行（无可参与小组）` |
| `COMPLETED` | `ALL_ROUNDS_COMPLETED` | `WAITING / CURRENT` | `未执行（全部轮次完成）` |
| `COMPLETED` | 空值或未知原因 | `WAITING / CURRENT` | `未执行（选单已结束）` |
| 任意 | 任意 | `SELECTED / PASSED / ADMIN_SKIPPED / INELIGIBLE_BANKRUPT / INELIGIBLE` | 保留原事实状态 |

说明：

- `SELECTED` 必须继续显示“已选择”，因为已选订单是订单事实。
- `PASSED` 必须继续显示“已放弃”，因为这是玩家主动放弃事实。
- `ADMIN_SKIPPED` 必须继续显示“管理员跳过”，因为这是管理员操作事实。
- `INELIGIBLE_BANKRUPT` 必须继续显示破产无资格，不能被订单池选空覆盖。
- `WAITING / CURRENT` 在完成态下只是未执行机会，才需要按完成原因转译。

### 9.3 管理员端体验

管理员端在选中已完成标段时，应在状态卡下方展示明确结束提示：

```text
本标段选单已结束：全国市场 · 代办过检
结束原因：订单池已提前选空。已选订单 2 个，剩余订单 0 个；后续未执行机会不再进入选单。
```

同时，完成态不应继续展示“代跳过原因 / 跳过当前小组”。该区域只在以下条件同时满足时展示：

```text
currentSegment.segmentStatus = SELECTING
currentSegment.currentGroupId 不为空
```

### 9.4 玩家端体验

玩家端在标段已完成时，应展示明确结果：

```text
本标段选单已结束
结束原因：订单池已提前选空。本组已获得 1 个订单，可继续查看交付状态。
```

若本组未获得订单，则展示：

```text
本标段选单已结束
结束原因：订单池已提前选空。本组未获得该标段订单。
```

玩家端需要返回并使用 `completionReason`，避免只靠 `COMPLETED` 猜测结束原因。
