# 管理员端分页面输入导航与输入态优化开发说明

> 更新日期：2026-07-24
> 状态：已完成前端开发，待页面人工复测
> 适用范围：管理员端赛前配置页字典修改、初始基线录入页、订单管理页数量控制、订单管理页标段释放顺序。
> 文档定位：本文件是 `docs/input_navigation_design.md` 的后续管理员端专项增强口径，只定义前端输入交互，不改变保存、提交、生成订单、释放标段、后端校验、订单公式或 Excel 规则链。

## 1. 背景

`I14` 已完成一版“最稳妥”的输入体验优化：

- 玩家端支持 `Enter` 跳到下一个可编辑输入格，并用蓝色描边 / 浅蓝光晕标亮当前格。
- 管理员端数字输入框只支持 `Enter` 结束当前输入态，不跳格、不高亮。

经过页面实操后，管理员端有几类录入页更接近“连续填表”场景。如果仍然只做 `Enter` 失焦，管理员需要频繁移动鼠标，录入效率偏低。因此本次新增一个管理员端专项增强，但仍然坚持“按页面局部接入”，不把整个管理员端改成全局 Excel 编辑器。

本次优化解决的问题是：

1. 管理员在指定录入区域输入后，按 `Enter` 可以结束当前输入态。
2. 在适合连续录入的区域，`Enter` 可以跳到下一个可编辑输入框。
3. 当前正在填写的输入格在指定区域内显示蓝色高亮，方便管理员定位。
4. 锁定、只读、禁用、隐藏、未展开但不属于当前跳转目标的控件都不应误参与。

本次优化不解决的问题：

- 不把 `Enter` 做成保存。
- 不把 `Enter` 做成提交。
- 不把 `Enter` 做成“保存数量并刷新预览”。
- 不把 `Enter` 做成“保存顺序”。
- 不把 `Enter` 做成“确认初始化比赛”。
- 不接管管理员端全部表单。
- 不接管按钮、下拉框、复选框、搜索框、确认文本框或多行文本框。
- 不修改任何业务数据结构、后端接口、订单生成规则、财报公式或 Excel 公式链。

## 2. 总体口径

### 2.1 行为语义

本次管理员端指定区域的 `Enter` 语义是：

```text
结束当前输入态，如果存在下一个可编辑输入框，则聚焦到下一个输入框。
```

需要特别区分三件事：

| 行为 | 是否本次要做 | 说明 |
|---|---|---|
| 结束输入态 | 做 | 当前输入框失焦或跳走后自然结束输入态 |
| 跳到下一个输入框 | 只在指定区域做 | 字典、初始基线、订单数量控制、释放顺序 |
| 保存 / 提交 / 生成 / 释放 | 不做 | 仍然必须由管理员点击对应按钮 |

### 2.2 通用跳过规则

`Enter` 跳转时，候选输入框必须满足以下条件：

- 是 `HTMLInputElement`。
- 没有 `disabled`。
- 没有 `readonly`。
- 不是 `type="hidden"`。
- 当前在 DOM 中存在。
- 当前可见。
- 当前可聚焦。
- 属于本页面明确标记的跳转区域。

以下输入框或控件不参与跳转：

- 搜索框。
- 字典方案下拉框。
- 沙盘版本下拉框。
- 年份下拉框。
- 市场筛选下拉框。
- 订单类型筛选下拉框。
- 复选框。
- 按钮。
- `textarea`。
- 普通原因输入、跳过原因输入、确认文本输入。
- 已锁定年份的订单数量格。
- 市场未开启导致不可编辑的释放顺序格。
- 已提交锁定的初始基线格。
- 正在保存、生成、释放等处理中被禁用的输入框。

### 2.3 最后一格行为

如果当前输入框已经是当前区域内最后一个可编辑输入框：

- 再按 `Enter` 时只结束输入态。
- 不循环回第一个输入框。
- 不跳到按钮。
- 不触发保存动作。

### 2.4 中文输入法处理

赛前配置页字典修改输入的是中文文本，因此必须避免中文输入法组合态误触发。

规则：

- 当 `event.isComposing === true` 时，不处理 `Enter` 跳转。
- 当 `event.key === 'Process'` 时，不处理 `Enter` 跳转。
- 只有中文输入法确认完成后的普通 `Enter` 才执行结束输入态 / 跳转。

### 2.5 当前格高亮

管理员端本次只在指定连续录入区域做当前格高亮。

高亮口径沿用玩家端的稳定方案：

```text
蓝色描边 / 浅蓝光晕 = 当前正在输入
```

注意：

- 高亮是叠加样式，不替换原业务底色。
- 红色错误态仍然表示校验错误。
- 灰色仍然表示锁定或只读。
- 黄色 / 橙色等已有提示语义不能被覆盖。
- 不在管理员端全局增加高亮，只在本文件列出的区域加。

推荐 CSS 方向：

```css
.admin-nav-cell:focus-within {
  box-shadow: inset 0 0 0 2px #2563eb, 0 0 0 2px rgba(37, 99, 235, 0.12);
}
```

具体类名可以按页面既有结构命名，但必须保持局部作用域。

## 4. 页面一：赛前配置页 / 业务显示字典

### 4.1 当前页面事实

赛前配置页通过 `DictionaryEditor.vue` 渲染业务显示字典。

字典组件当前特征：

- 输入框是中文文本输入。
- 按分类折叠展示。
- 分类顺序当前为：

```text
市场 → 订单类型 → 经营页 → 财报页 → 初始基线
```

- 同一分类内按 `displayOrder` 排序。
- 输入框只在分类展开后渲染，因为当前分类内容使用 `v-if="expandedCategories[group.category]"`。
- 组件被赛前配置页两处使用：
  - 比赛初始化前的“业务显示字典”。
  - 初始化后的“当前比赛显示名称”。

### 4.2 跳转顺序

字典修改的跳转顺序为：

```text
按当前筛选结果中的分类顺序 → 分类内 displayOrder 顺序
```

解释：

- 没有搜索、没有开启“只看已修改”时，按全量字典顺序跳。
- 如果管理员正在搜索，则只在搜索结果内跳转。
- 如果管理员开启“只看已修改”，则只在当前筛选结果内跳转。
- 不强行跳到被搜索条件隐藏的字段，否则会违背管理员当前筛选意图。

### 4.3 自动展开规则

如果下一个目标输入框所在分类当前处于折叠状态：

1. 先展开目标分类。
2. 等待 Vue 完成 DOM 更新。
3. 再聚焦到目标输入框。
4. 聚焦后选中输入框内文本，方便管理员直接覆盖输入。

伪流程：

```ts
async function focusDictionaryItem(itemCode: string, category: string) {
  expandedCategories.value = {
    ...expandedCategories.value,
    [category]: true,
  }

  await nextTick()

  const input = dictionaryInputRefs.get(itemCode)
  focusInputElement(input)
}
```

### 4.4 不参与跳转的字典控件

以下控件不参与字典跳转：

- 搜索框。
- “只看已修改”按钮。
- 分类标题展开 / 收起按钮。
- “撤销”按钮。
- “默认”按钮。
- “恢复本类默认”按钮。
- 保存方案、应用方案、恢复默认、确认初始化等外层按钮。

### 4.5 只读与禁用规则

以下字典输入不参与跳转：

- `readonly === true` 的整组件状态。
- `row.item.editable === false` 的字段。
- 初始化中或保存中导致外层只读的字段。

如果当前分类中后续项目都不可编辑，则继续查找后续分类；如果没有任何后续可编辑项，则当前输入框失焦。

### 4.6 高亮规则

建议在字典行或输入容器上增加局部焦点样式：

```css
.dictionary-row:focus-within .row-input input,
.row-input:focus-within input {
  box-shadow: inset 0 0 0 2px #2563eb, 0 0 0 2px rgba(37, 99, 235, 0.12);
}
```

高亮不得覆盖：

- 已修改的黄色提示。
- 空值的红色错误提示。
- 只读的灰色输入框。

## 5. 页面二：初始基线录入页

### 5.1 当前页面事实

初始基线录入页是共享初始基线模板，主要字段来自 `fieldDefs`：

```text
损益 → 资产 → 存货 → 负债 → 权益
```

页面本质是一个从上到下的数字录入表。

当前输入框已经具备：

- `type="number"`
- `step="1"`
- `inputmode="numeric"`
- 整数错误样式
- 提交后 `view.editable === false` 锁定

### 5.2 跳转顺序

初始基线页跳转顺序为：

```text
从上到下，按页面表格行顺序。
```

即按 `fieldDefs` 当前顺序：

```text
baselineSalesRevenue
→ baselineDirectCost
→ baselineComprehensiveCost
→ ...
→ baselineRetainedEarnings
```

### 5.3 跳过规则

以下输入框跳过：

- 页面加载中不存在的输入框。
- `view.editable === false` 时被禁用的输入框。
- 已提交并锁定后的输入框。
- 任何禁用、只读、隐藏输入框。

### 5.4 最后一格规则

如果当前已经是最后一个可编辑基线输入框：

- 按 `Enter` 只失焦。
- 不跳到“提交并应用到全部小组”按钮。
- 不触发提交。

### 5.5 高亮规则

建议在 `input-cell` 上使用 `:focus-within`：

```css
.input-cell:focus-within {
  box-shadow: inset 0 0 0 2px #2563eb, 0 0 0 2px rgba(37, 99, 235, 0.12);
}
```

如果当前格有小数错误：

- 红色错误样式继续保留。
- 蓝色焦点描边可以叠加。

## 6. 页面三：订单管理页 / 数量控制

### 6.1 当前页面事实

订单管理页“数量控制”区域是多年订单数量控制台。

当前模板结构大致是：

- 外层：`forecastStages`
- 表格行：市场 → 订单类型
- 表格列：年份数量

当前 DOM 渲染顺序接近：

```text
阶段 → 市场 → 订单类型 → 年份
```

但用户确认的录入顺序不是这个 DOM 顺序。

### 6.2 已确认跳转顺序

订单数量控制的 `Enter` 跳格顺序必须按“年份列优先”：

```text
阶段 → 年份 → 市场 → 订单类型
```

也就是先填完某一年数量这一整列，再进入下一年。

示例：

```text
本地市场 - 订单类型 A - 1年数量
本地市场 - 订单类型 B - 1年数量
本地市场 - 订单类型 C - 1年数量
本地市场 - 订单类型 D - 1年数量

区域市场 - 订单类型 A - 1年数量
区域市场 - 订单类型 B - 1年数量
区域市场 - 订单类型 C - 1年数量
区域市场 - 订单类型 D - 1年数量

国内市场 - 订单类型 A - 1年数量
国内市场 - 订单类型 B - 1年数量
国内市场 - 订单类型 C - 1年数量
国内市场 - 订单类型 D - 1年数量

全球市场 - 订单类型 A - 1年数量
全球市场 - 订单类型 B - 1年数量
全球市场 - 订单类型 C - 1年数量
全球市场 - 订单类型 D - 1年数量

然后进入：

本地市场 - 订单类型 A - 2年数量
本地市场 - 订单类型 B - 2年数量
...
```

更短的口径：

```text
先纵向填完 1 年数量这一列；
再纵向填完 2 年数量这一列；
再纵向填完 3 年数量这一列。
```

### 6.3 技术实现要求

由于 DOM 顺序与用户确认的录入顺序不同，不能直接复用通用 DOM 顺序跳转。

推荐生成显式跳转序列：

```ts
for (const stage of forecastStages) {
  for (const yearNo of stage.years) {
    for (const market of marketOptions) {
      for (const orderType of orderTypeOptions) {
        keys.push(forecastInputKey(stage.forecastStageCode, yearNo, market.code, orderType.code))
      }
    }
  }
}
```

每个数量输入框建议带一个稳定 key：

```text
data-admin-forecast-key="{stageCode}|{yearNo}|{marketCode}|{orderType}"
```

或使用 Vue `ref` map 保存：

```text
forecastInputRefs: Map<string, HTMLInputElement>
```

按 `Enter` 时：

1. 根据当前 key 找到显式序列中的位置。
2. 从当前位置之后继续查找。
3. 跳过禁用、只读、隐藏、已锁定年份的输入框。
4. 找到后聚焦并选中文本。
5. 找不到则当前输入框失焦。

### 6.4 跳过规则

以下数量格跳过：

- 已确认年份整列锁定，即 `isForecastYearLocked(yearNo) === true`。
- 正在保存数量，即 `savingForecastControl === true`。
- 正在生成订单池，即 `generatingPool === true`。
- 禁用、只读、隐藏的输入框。
- 不存在于当前模板选项内的市场或订单类型。

注意：

- 锁定年份是按列锁定，因此如果 `1年数量` 已锁定，跳转应直接跳过全部 `1年数量` 格，进入后续未锁定年份。
- 如果所有年份都锁定，则按 `Enter` 只结束当前输入态。

### 6.5 不参与数量控制跳转的控件

以下控件不参与：

- “保存数量并刷新预览”按钮。
- 市场预测图表。
- 市场说明 `textarea`。
- 市场设置页的单市场投入上限。
- 订单池筛选。
- 竞标控制相关输入。

### 6.6 高亮规则

建议在数量输入所在单元格上加局部焦点样式：

```css
.forecast-control-table td:focus-within {
  box-shadow: inset 0 0 0 2px #2563eb, 0 0 0 2px rgba(37, 99, 235, 0.12);
}
```

需要避免给以下单元格制造误导：

- 预测金额只读单元格。
- 已锁定年份单元格。
- 合计行。

可通过更明确的类名限制：

```css
.forecast-input-cell:focus-within {
  box-shadow: inset 0 0 0 2px #2563eb, 0 0 0 2px rgba(37, 99, 235, 0.12);
}
```

## 7. 页面四：订单管理页 / 标段顺序 / 释放顺序

### 7.1 当前页面事实

标段顺序页的释放顺序是一个纵向数字表。

当前输入框位于 `sortedItems` 行内：

```text
释放顺序 → 市场 → 订单类型 → 已生成 → 状态
```

市场未开启时整行有禁用状态，释放顺序输入框不可编辑。

### 7.2 跳转顺序

释放顺序跳转按页面从上到下：

```text
sortedItems[0].releaseSequenceNo
→ sortedItems[1].releaseSequenceNo
→ sortedItems[2].releaseSequenceNo
→ ...
```

如果中间行不可编辑，则跳过。

### 7.3 跳过规则

以下释放顺序输入框跳过：

- 市场未开启，即 `!item.marketEnabled`。
- 当前配置不可更新，即 `!config?.canUpdateConfig`。
- 正在保存顺序，即 `savingConfig === true`。
- 正在生成订单池，即 `generatingPool === true`。
- 禁用、只读、隐藏的输入框。

### 7.4 最后一格规则

如果当前已经是最后一个可编辑释放顺序输入框：

- 按 `Enter` 只失焦。
- 不跳到“保存顺序”按钮。
- 不触发保存。

### 7.5 高亮规则

建议在释放顺序输入单元格上加局部焦点样式：

```css
.release-sequence-cell:focus-within {
  box-shadow: inset 0 0 0 2px #2563eb, 0 0 0 2px rgba(37, 99, 235, 0.12);
}
```

市场未开启行仍保持灰色禁用语义。

## 8. 技术落点建议

### 8.1 通用工具扩展

当前已有：

```text
frontend/src/utils/input-navigation.ts
```

已有函数：

```ts
confirmInputOnEnter(event: KeyboardEvent): void
focusNextInputOnEnter(event: KeyboardEvent): void
```

本次建议在不破坏现有玩家端行为的前提下，补充面向页面自定义顺序的能力。

推荐导出以下底层能力之一：

```ts
export function focusInputElement(input: HTMLInputElement | null | undefined): boolean
export function canFocusEnterInput(input: HTMLInputElement | null | undefined): input is HTMLInputElement
export function shouldHandleEnterNavigation(event: KeyboardEvent): boolean
export function focusNextInputFromList(event: KeyboardEvent, inputs: Array<HTMLInputElement | null | undefined>): void
```

也可以保留底层函数私有，在页面内实现自定义序列查找。但从复用角度看，建议把“组合态判断、可见性判断、focus + select”沉到工具函数里，页面只负责决定“下一个是谁”。

### 8.2 页面落点

| 文件 | 建议修改 |
|---|---|
| `frontend/src/utils/input-navigation.ts` | 补充自定义顺序跳转辅助函数，保留原 `confirmInputOnEnter` / `focusNextInputOnEnter` 行为 |
| `frontend/src/components/sandbox-game/admin/DictionaryEditor.vue` | 增加字典输入 refs、`Enter` 跳转、自动展开、字典输入高亮 |
| `frontend/src/views/sandbox-game/admin/baseline/AdminBaselinePage.vue` | 初始基线表增加局部跳转 scope / data 标记或 refs，并增加输入格高亮 |
| `frontend/src/views/sandbox-game/admin/order/AdminOrderPage.vue` | 数量控制使用显式 key 序列跳转；释放顺序使用纵向跳转；增加局部高亮 |

### 8.3 不建议的实现方式

不建议做全局键盘监听：

- 管理员端页面按钮和确认动作较多，全局监听容易误伤。
- 字典中文输入需要处理输入法组合态，局部监听更安全。
- 订单数量控制存在自定义顺序，靠全局 DOM 顺序无法表达。

不建议依赖纯 DOM 顺序处理订单数量控制：

- 当前 DOM 顺序是 `市场 → 订单类型 → 年份`。
- 用户确认的录入顺序是 `年份 → 市场 → 订单类型`。
- 两者不同，必须显式生成序列。

不建议把按钮纳入跳转链：

- 最后一格按 `Enter` 时如果跳到保存按钮，管理员可能下意识再次按回车误触发保存。
- 本次设计的底线是：`Enter` 不触发任何业务动作。

## 9. 验收清单

### 9.1 赛前配置页 / 字典修改

- 在第一个字典输入框输入中文后，输入法组合态下按 `Enter` 不跳走。
- 中文确认完成后再按 `Enter`，跳到下一个可编辑字典输入框。
- 如果下一个输入框在折叠分类中，系统先展开分类，再聚焦目标输入框。
- 搜索框不参与跳转。
- “只看已修改”开启时，只在筛选结果内跳转。
- 只读字段、不可编辑字段不参与跳转。
- 最后一个可编辑字典输入框按 `Enter` 只失焦，不跳到按钮。
- 当前字典输入框出现蓝色高亮。
- 空值红色错误样式不被蓝色高亮覆盖。

### 9.2 初始基线录入页

- 第一行输入后按 `Enter`，跳到第二行输入框。
- 按页面从上到下顺序连续跳转。
- 已提交锁定后，输入框不可编辑且不参与跳转。
- 最后一行输入框按 `Enter` 只失焦，不触发提交。
- 当前输入格显示蓝色高亮。
- 小数错误红色样式仍然保留。

### 9.3 订单管理页 / 数量控制

- 在 `本地市场 - 订单类型 A - 1年数量` 按 `Enter`，跳到 `本地市场 - 订单类型 B - 1年数量`。
- 按 `Enter` 继续跳到 `本地市场 - 订单类型 C - 1年数量`、`本地市场 - 订单类型 D - 1年数量`。
- 本地市场 1 年数量填完后，跳到 `区域市场 - 订单类型 A - 1年数量`。
- 当前年份这一列全部市场、全部订单类型填完后，才进入下一年份数量列。
- 已锁定年份整列被跳过。
- 正在保存数量或生成订单池时不发生跳转。
- 最后一个可编辑数量格按 `Enter` 只失焦，不触发“保存数量并刷新预览”。
- 当前数量格显示蓝色高亮。

### 9.4 订单管理页 / 标段顺序 / 释放顺序

- 第一行释放顺序输入后按 `Enter`，跳到下一行可编辑释放顺序。
- 市场未开启的行被跳过。
- 不可更新或保存中状态下的输入框被跳过。
- 最后一个可编辑释放顺序按 `Enter` 只失焦，不触发“保存顺序”。
- 当前释放顺序格显示蓝色高亮。

## 10. 后续可选增强

以下能力不进入本次开发：

- `Shift + Enter` 跳到上一个输入框。
- `Tab / Shift + Tab` 自定义跳转。
- 方向键导航。
- 最后一格循环回第一个。
- 管理员端所有页面统一跳格。
- 订单管理页市场设置的单市场投入上限连续跳格。
- 竞标控制区键盘快捷操作。
- 校验错误时强制停留在当前格。

如果后续要做这些能力，应单独确认页面范围和键盘语义，避免和保存、提交、释放等高风险动作混在一起。
